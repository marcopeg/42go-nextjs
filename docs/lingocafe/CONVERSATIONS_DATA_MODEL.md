# LingoCafe Conversations Data Model

## Purpose and authority

This document is the standalone publication contract for scenario-based
LingoCafe conversations. The `books` repository owns the editorial YAML.
`42go-nextjs` owns the PostgreSQL runtime model, learner state, and migrations.

The complete ordered migration history under `knex/migrations/` is the schema
source of truth. Importers must evaluate that history rather than copying this
document or one create migration as executable DDL. This document explains the
accumulated model and the safe publication protocol. The additive foundation
described here is migration
`20260806223000_lingocafe_conversations.js`, with export-time category
availability added by
`20260807120000_lingocafe_conversation_category_availability.js`, and browse
cache versioning added by
`20260807170000_lingocafe_conversation_cache_versions.js`.

All conversation tables are in the PostgreSQL `lingocafe` schema. PostgreSQL is
the only supported target.

## Ownership boundary

Content publication owns these tables:

- `conversation_categories`
- `conversation_category_parents`
- `conversation_scenarios`
- `conversation_scenario_localizations`
- `conversation_category_scenarios`
- `conversation_category_availability`
- `conversation_scenario_actors`
- `conversation_variants`
- `conversation_variant_localizations`
- `conversations`
- `conversation_rounds`
- `conversation_publication_state`

The application and its learners own these tables:

- `conversation_reads`
- `conversation_stars`
- `conversation_user_state_versions`

An importer must never insert, update, delete, truncate, replace, or derive rows
in the learner-owned tables. The publisher updates only the singleton
`conversation_publication_state` row after all content writes succeed. Normal
publication must not touch books, book
pages, progress, completion, profiles, consent, events, or translation data.

## Common conventions

- Structural and exact-conversation IDs are stable lowercase source IDs. They
  are not localized or regenerated by the database.
- CEFR values are lowercase `a1`, `a2`, `b1`, or `b2`.
- Language codes are normalized lowercase source codes such as `en`, `sv`, and
  `it`.
- Ordered positions are 1-based positive integers.
- Where present, `created_at` records first insertion. A content upsert updates
  `updated_at` but preserves `created_at`.
- Source lifecycle `status` is editorial evidence. `is_visible` is the separate
  runtime publication decision. Runtime code must require visible records and
  must never treat a draft/review status as an implicit visibility decision.
- Source audit fields preserve the producing schema version, repository-relative
  path, and content hash. `metadata` retains non-runtime editorial information
  as JSONB; normalized keys and display fields remain authoritative at runtime.
- `tags` and specific-language lists use PostgreSQL `text[]`. Flexible audit or
  editorial payloads use non-null JSONB values; importers supply objects for
  the documented metadata/provenance fields.

## Tables

### `lingocafe.conversation_categories`

One canonical navigation category.

| Column | Meaning |
| --- | --- |
| `id` | Stable text primary key. |
| `status` | Source lifecycle: `draft`, `accepted`, or `deprecated`. |
| `title` | Canonical-English title. |
| `description` | Canonical-English description. |
| `goal` | Canonical-English learner-facing navigation goal. |
| `language_scope` | `all` or `specific`. |
| `languages` | Specific applicable languages; empty for `all`. |
| `tags` | Preserved controlled source tags. |
| `is_visible` | Explicit runtime visibility. |
| `source_schema_version` | Producing YAML schema version. |
| `source_path` | Repository-relative canonical source path. |
| `source_hash` | Deterministic hash of the canonical source record. |
| `metadata` | Remaining source/audit data. |
| `created_at`, `updated_at` | Runtime audit timestamps. |

Checks keep `language_scope` coherent: `all` requires an empty language list;
`specific` requires at least one language. The importer must force deprecated
categories invisible, and a database check rejects a deprecated row with
`is_visible = true`.

### `lingocafe.conversation_category_parents`

Directed child-to-parent edges in the plural-parent category graph.

| Column | Meaning |
| --- | --- |
| `category_id` | Child category. |
| `parent_category_id` | Parent category. |

The pair is the primary key. Both columns cascade when their category is
deleted, self-edges are rejected, and a parent lookup index supports child
navigation. PostgreSQL does not enforce graph acyclicity or visible-root
reachability; the importer validates both before writing.

### `lingocafe.conversation_scenarios`

One reusable generic situation.

| Column | Meaning |
| --- | --- |
| `id` | Stable text primary key. |
| `status` | `development`, `release-candidate`, `review`, `accepted`, or `retired`. |
| `canonical_language` | Canonical authoring language. |
| `title`, `description` | Canonical display metadata. |
| `learner_promise` | Canonical learner value statement. |
| `language_scope`, `languages` | Explicit applicability using the common scope rule. |
| `tags` | Controlled source tags. |
| `is_visible` | Explicit runtime visibility. |
| `source_schema_version`, `source_path`, `source_hash` | Source audit identity. |
| `metadata` | Remaining scenario data. |
| `created_at`, `updated_at` | Runtime audit timestamps. |

The importer must force retired scenarios invisible, and a database check
rejects a retired row with `is_visible = true`.

### `lingocafe.conversation_scenario_localizations`

Explicit scenario navigation text for one language and CEFR level.

| Column | Meaning |
| --- | --- |
| `scenario_id` | Owning scenario. |
| `language` | Localization language. |
| `cefr_level` | `a1`, `a2`, `b1`, or `b2`. |
| `title`, `description` | Fully explicit localized values. |

`(scenario_id, language, cefr_level)` is the primary key. Deleting the scenario
cascades to its localizations. There is no fallback or inheritance between
languages or levels. Language must match
`^[a-z]{2,3}(-[a-z0-9]+)*$`.

### `lingocafe.conversation_category_scenarios`

Materialized many-to-many category membership. Runtime APIs read this table;
they never evaluate YAML tag queries.

| Column | Meaning |
| --- | --- |
| `category_id` | Matching category. |
| `scenario_id` | Matching scenario. |
| `match_provenance` | JSONB audit evidence for query, explicit inclusion, and blacklist processing. |

`(category_id, scenario_id)` is the primary key. Both foreign keys cascade on
content deletion. A scenario lookup index supports reverse inspection.

### `lingocafe.conversation_category_availability`

Export-time materialized availability for category navigation. Runtime APIs
read this table directly; they do not recursively traverse the category graph
or aggregate eligible conversations to render category badges.

| Column | Meaning |
| --- | --- |
| `category_id` | Category whose self-and-descendant availability was measured. |
| `language` | Exact normalized conversation language. |
| `level_key` | Exact CEFR (`a1`, `a2`, `b1`, `b2`) or UI band (`beginner`, `intermediate`, `advanced`). |
| `conversation_count` | Count of distinct exported, runtime-visible exact conversations. |
| `updated_at` | Time this materialized value was last published. |

`(category_id, language, level_key)` is the primary key. Category deletion
cascades. Counts are non-negative, and the selection index on
`(language, level_key, category_id)` supports category discovery.

The publisher emits the complete category × supported-language matrix for all
seven level keys, including rows whose count is zero. Exact CEFR values are the
canonical counts. Band rows are derived before publication: `beginner` is A1,
`intermediate` is A2 plus B1, and `advanced` is B2. The application therefore
never aggregates counts while serving a request.

For every category, a count includes distinct eligible conversations attached
to that category or to any descendant reached through visible,
language-applicable category paths. A conversation reached through multiple
paths in the category DAG is counted once. Here, eligible/final means the exact
conversation is exported and visible in the app: the scenario, variant, and
conversation are visible and language-applicable, and the conversation has at
least one valid exported round.

### `lingocafe.conversation_scenario_actors`

Scenario-scoped actors referenced by dialogue rounds.

| Column | Meaning |
| --- | --- |
| `scenario_id` | Owning scenario. |
| `id` | Stable actor ID within that scenario. |
| `position` | 1-based actor display order. |
| `name`, `role`, `description` | Canonical actor metadata. |
| `metadata` | Remaining actor data. |

`(scenario_id, id)` is the primary key and actor position is unique within a
scenario. Scenario deletion cascades to actors. Round references use restrictive
deletion semantics so removing an actor cannot silently remove dialogue text.

### `lingocafe.conversation_variants`

One semantic sub-scenario. Variant IDs are scoped to their scenario.

| Column | Meaning |
| --- | --- |
| `scenario_id`, `id` | Composite primary key. |
| `status` | `developed`, `release-candidate`, `review`, `accepted`, or `retired`. |
| `canonical_language` | Canonical authoring language. |
| `title`, `description` | Canonical display metadata. |
| `language_scope`, `languages` | Explicit applicability using the common scope rule. |
| `tags` | Controlled source tags. |
| `is_visible` | Explicit runtime visibility. |
| `source_schema_version`, `source_path`, `source_hash` | Source audit identity. |
| `metadata` | Selected variables, guidelines, design, and remaining source data. |
| `created_at`, `updated_at` | Runtime audit timestamps. |

The scenario foreign key cascades. The importer must force retired variants
invisible, and a database check rejects a retired row with `is_visible = true`.

### `lingocafe.conversation_variant_localizations`

Explicit variant navigation text for one language and CEFR level.

| Column | Meaning |
| --- | --- |
| `scenario_id`, `variant_id` | Owning scenario-scoped variant. |
| `language`, `cefr_level` | Exact localization identity. |
| `title`, `description` | Fully explicit localized values. |

The four columns form the primary key. A composite foreign key proves the
variant belongs to the named scenario and cascades on variant deletion.
Language must match `^[a-z]{2,3}(-[a-z0-9]+)*$`.

### `lingocafe.conversations`

One exact language-and-CEFR realization.

| Column | Meaning |
| --- | --- |
| `id` | Globally durable text primary key. |
| `scenario_id`, `variant_id` | Owning scenario-scoped variant. |
| `status` | `development`, `release-candidate`, `review`, `accepted`, or `retired`. |
| `language`, `cefr_level` | Exact realization identity. |
| `title`, `description` | Fully localized display metadata. |
| `tags` | Controlled source tags. |
| `is_visible` | Explicit runtime visibility. |
| `source_schema_version`, `source_path`, `source_hash` | Source audit identity. |
| `metadata` | Provenance, learning goals, level realization, review, and remaining source data. |
| `created_at`, `updated_at` | Runtime audit timestamps. |

`(scenario_id, variant_id, language, cefr_level)` is unique, so only one exact
realization exists for a variant/language/level. A composite foreign key proves
variant scope. The discovery index is
`(language, cefr_level, is_visible)`. The importer must force retired
conversations invisible, and a database check rejects a retired row with
`is_visible = true`. Language must match
`^[a-z]{2,3}(-[a-z0-9]+)*$`.

### `lingocafe.conversation_rounds`

Ordered dialogue turns for an exact conversation.

| Column | Meaning |
| --- | --- |
| `conversation_id` | Exact conversation. |
| `position` | 1-based turn order. |
| `scenario_id` | Redundant scope used to prove actor and conversation ownership. |
| `actor_id` | Actor ID within the scenario. |
| `text` | Non-empty basic-Markdown dialogue text. |

`(conversation_id, position)` is the primary key. Position must be positive and
trimmed text must be non-empty. Composite foreign keys prove that the exact
conversation and actor both belong to `scenario_id`. Conversation deletion
cascades to rounds; actor deletion is restricted.

### `lingocafe.conversation_reads`

| Column | Meaning |
| --- | --- |
| `user_id` | Authenticated `auth.users.id`. |
| `conversation_id` | Exact conversation ID. |
| `read_at` | Latest explicit read timestamp. |

`(user_id, conversation_id)` is the primary key. Both foreign keys cascade on
deletion. The `idx_lc_conversation_reads_user_time` index on
`(user_id, read_at DESC)` supports recent-read queries.

Opening a conversation does not create this row. The reader first persists
scroll progress and creates the read row only after progress reaches 9500 basis
points (95%). Existing read rows are backfilled to 10000 basis points when the
progress table is introduced.

### `lingocafe.conversation_progress`

| Column | Meaning |
| --- | --- |
| `user_id` | Authenticated `auth.users.id`. |
| `conversation_id` | Exact conversation ID. |
| `progress_bps` | Scroll progress from 0 through 10000 basis points. |
| `updated_at` | Last persisted scroll update. |

`(user_id, conversation_id)` is the primary key. Both foreign keys cascade on
deletion, and a check constraint enforces the basis-point range. Progress is
independent of read state so opening or partially reading a conversation does
not make it read. The reader restores this value on reopen, updates it after a
four-second scroll idle period, and sends any pending final value with a
keepalive request when leaving.

### `lingocafe.conversation_publication_state`

Singleton publication metadata used to validate cached browse responses before
the application queries the content graph. The `current` row stores the exact
full-corpus digest produced by `conv-push` and the successful publication time.
The publisher changes this row in the same transaction and only after all
content writes and checks have succeeded.

### `lingocafe.conversation_user_state_versions`

One monotonically increasing version per learner. The application increments
it in the same transaction whenever a read or star mutation changes state.
Browse ETags combine this version with the publication digest and resolved
profile selection, so a conditional `304` never preserves stale read/star
status. This table is application-owned and the publisher must not change it.

### `lingocafe.conversation_stars`

| Column | Meaning |
| --- | --- |
| `user_id` | Authenticated `auth.users.id`. |
| `conversation_id` | Exact conversation ID. |
| `starred_at` | Latest explicit star timestamp. |

`(user_id, conversation_id)` is the primary key. Both foreign keys cascade on
deletion. The `idx_lc_conversation_stars_user_time` index on
`(user_id, starred_at DESC)` supports recent-star queries.

## Source-to-row mapping

The canonical source paths are relative to `books/content/conversations/`.

| Source | Runtime rows |
| --- | --- |
| `categories/records/<category>.yaml` | One category, its outbound parent edges, and its materialized scenario memberships. |
| Complete validated publication graph | The zero-inclusive category availability matrix for supported languages, exact CEFR levels, and UI bands. |
| `scenarios/<scenario>/scenario.yaml` | One scenario, all explicit scenario localizations, and its authoritative actor set. |
| `scenarios/<scenario>/variants/<variant>/variant.yaml` | One scenario-scoped variant and all explicit variant localizations. |
| `scenarios/<scenario>/variants/<variant>/<lang>-<level>.yaml` | One exact conversation and its complete ordered round set. |

Category queries, explicit category-ID tags, inherited blacklists, and language
applicability are resolved by the source-side validator/importer. Only final
membership plus useful provenance is stored. Runtime code must not reproduce
the YAML query evaluator.

After resolving category membership and runtime visibility, the publisher also
replaces `conversation_category_availability` for every explicitly
authoritative category. The replacement is computed from the complete
validated publication snapshot, not from the pre-publication database state.

Source status is copied verbatim. The publisher supplies `is_visible`
deliberately. At minimum, deprecated categories and retired scenarios,
variants, or conversations must be invisible. Visibility of an exact
conversation at runtime also depends on the required parent content being
visible and language-applicable.

## Safe publication transaction

Every write-capable import uses one PostgreSQL transaction and follows this
protocol:

1. Load and validate the complete requested source scope before opening writes.
   Validate IDs, references, the category DAG, visible-root reachability,
   language applicability, statuses, localizations, unique realizations, actor
   references, positive ordering, and non-empty round text.
2. Acquire a transaction-scoped PostgreSQL advisory lock dedicated to
   conversation publication. Concurrent importers must not interleave.
3. Check source schema-version compatibility. Abort before mutation when an
   input version is unsupported.
4. Upsert explicitly supplied top-level category, scenario, variant, and exact
   conversation records by their documented keys. Update source/display fields,
   metadata, visibility, source hash, and `updated_at`; preserve `created_at`.
5. Replace child or relationship sets only under an explicit authoritative
   parent scope:
   - outbound parent edges and category memberships for named categories;
   - category availability rows for named categories;
   - scenario localizations and actors for named authoritative scenarios;
   - variant localizations for named authoritative variants;
   - rounds for named authoritative exact conversations.
6. Treat an empty replacement set as authoritative only when the invocation
   declares that parent scope explicitly. A missing section or omitted parent
   is never a deletion request.
7. Before deleting an actor from an authoritative actor set, prove no retained
   or out-of-scope round references it. Refuse the import instead of cascading
   dialogue loss.
8. Never hard-delete a top-level content row merely because it is absent from a
   full or partial input. Withdraw normal content by changing status and
   `is_visible`. Hard deletion is a separate future operator workflow because
   exact-conversation deletion cascades learner state.
9. Never touch `conversation_reads` or `conversation_stars`. Commit only after
   the complete scoped import succeeds.

Reapplying identical input must be idempotent. Source hashes may be used to skip
unchanged record updates, but they do not relax validation or ownership rules.

## Full and partial imports

A full import means the source set was validated as a whole; it does not grant
permission to truncate tables or delete omitted top-level IDs. A partial import
names every authoritative parent whose child relationships may be replaced.
Records outside those scopes remain unchanged.

Generated SQL seed files and direct database mode implement the same protocol.
Generated SQL must be reviewable, parameter-safe for all source values, wrapped
in one transaction, advisory-locked, and free of learner-state statements.

## Development fixture

The repository-owned development fixture uses reserved fixed IDs and upserts
only those content rows and their explicitly scoped relationships/rounds. It
must not depend on a sibling `books` checkout. Reapplying it must not clear
full-corpus content or mutate learner state.

## Consumer rules

- APIs derive `user_id` from the authenticated session. Clients never select a
  user for read/star mutations.
- Runtime category browsing follows materialized parent and membership rows.
- Queries apply language scope and `is_visible` across the full parent chain.
- A2 and B1 are distinct exact realizations even when a product groups them in
  one learner band.
- Round ordering uses `position`; SQL row order is otherwise undefined.
- Basic Markdown is rendered through the application's sanitized reader path.
- Account erasure explicitly removes and reports read/star rows before the user
  record is deleted; foreign-key cascades remain the final integrity backstop.

## Importer verification checklist

- Apply the complete migration history successfully.
- Confirm the target database is PostgreSQL and the conversation tables match
  this accumulated contract.
- Reject an unsupported source schema version before writing.
- Validate the complete requested graph and acquire the advisory lock.
- Dry-run or generate SQL without opening a database when requested.
- Show the exact authoritative replacement scopes before executing writes.
- Confirm the SQL contains no learner-owned or unrelated LingoCafe table writes.
- Reapply identical input and confirm stable row counts/content.
- Confirm pre-existing book/progress/completion and conversation read/star rows
  are unchanged by publication.
