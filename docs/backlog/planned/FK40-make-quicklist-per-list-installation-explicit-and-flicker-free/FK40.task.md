# Make QuickList Per-List Installation Explicit and Flicker-Free

## Elevator's Pitch

Keep QuickList navigation instant while retaining separately installable list virtual apps. Normal navigation must preserve the initially rendered PWA manifest; installing a list becomes an explicit, explained, full-document installer flow from that list's settings.

## Business Gain

Users can move between the QuickList index, lists, and settings without a disruptive page flash, while still placing important individual lists on a device home screen or desktop as named launchers.

## Current State

QuickList declares every `/quicklists/:projectId/**` route as a dynamic PWA target. `ManifestLink` detects a manifest-identity change during client navigation and calls `window.location.reload()`. Entering or leaving a list therefore flashes and reloads the whole document, even when the user has not requested installation. The existing resolver already authorizes access and produces a stable target ID, list-derived name, and list launch URL.

## Desired State

Normal QuickList navigation remains entirely client-side and never reloads merely because the pathname changes. The only per-list PWA target document is the authenticated `/quicklists/:projectId/install` route, reached from that list's settings page and offering a normal return link to settings. It renders the authorized list's sole effective manifest and clear platform-appropriate installation guidance; the user then invokes the native browser installation flow. The regular list routes—including direct browser visits and refreshes—use the base QuickList manifest. An installed list still launches directly to its own list route and retains its list-specific PWA identity during subsequent client-side navigation.

## Definition of Success

The QuickList index, list detail, and list settings pages navigate without a visible full-page flash. A user who deliberately enters one list's installer route can install that list as a named virtual app using the native browser flow. The installed launcher opens the authorized list route, while regular QuickList routes retain the base PWA identity. The operator completes manual installation and launch checks on iPhone and Android.

## Additional Context

The W3C manifest lifecycle rejects replacement of a document's already processed manifest when the new manifest has a different ID. Ordinary metadata such as title and theme color can change in a SPA, but a separately installable list must be established from its own document. The desired solution moves that document boundary to the user-initiated installation flow. Relevant implementation: `src/42go/pwa/ManifestLink.tsx`, `src/42go/pwa/HeadTags.tsx`, `src/config/quicklist/config.ts`, `src/config/quicklist/pwa.server.ts`, and `src/app/(app)/quicklists/[id]/info/page.tsx`.

## Assumptions

- `/quicklists/:projectId/install` is protected by the same list-access rules as the existing list and settings routes.
- The existing list install-target resolver remains the authority for immutable target ID, list-derived name, access validation, and start URL.
- The regular list routes use the base QuickList manifest even when they are hard-refreshed in an ordinary browser tab.
- The operator will manually validate installation and launch behavior on iPhone and Android; automated coverage should still protect framework behavior that can run in CI.

## Constraints

Do not remove per-list PWA identities or weaken server-side authorization. Do not present JavaScript as capable of opening Safari's native Add to Home Screen flow. Keep the shared PWA framework reusable for other apps, and avoid duplicate manifest or Apple metadata in the installer document.

## Acceptance Criteria

- Navigating `/quicklists` ↔ `/quicklists/:projectId` and between list pages does not call `window.location.reload()` or cause a full-document navigation.
- The client PWA head layer preserves the manifest initially rendered for the document rather than replacing it with a target of a different PWA ID during SPA navigation.
- The list settings UI offers an Install this list action that deliberately enters a dedicated, authenticated installer route/document for that project.
- The installer route is `/quicklists/:projectId/install`, includes a clear explanation and a normal return link to that list's settings, and is the only QuickList route that resolves the list-specific manifest target.
- The installer document renders exactly one effective authorized list manifest, with the list's stable ID, title-derived name, inherited icon/colors, and existing list-specific launch URL.
- The installer document explains the native install step; Chromium uses the supported install prompt when available, while Safari/iOS receives honest manual instructions.
- Installation remains authorization-safe: unauthorized, deleted, or revoked lists do not expose a usable target manifest or installer.
- Launching an installed list still reaches its list route and normal in-app navigation is smooth.
- Automated coverage protects the manifest-identity/no-reload behavior; the operator manually verifies the explicit installer flow and installed-list launch on iPhone and Android.
- `npm run qa` passes.

## Dos

- Preserve ordinary QuickList navigation as Next.js client-side routing.
- Keep a document's initially rendered manifest stable during SPA navigation.
- Resolve the list-specific target server-side only for the installer route, after access validation.
- Reuse the existing generic installation component and platform-specific guidance where it fits the dedicated installer page.
- Add focused tests for base versus installer manifest selection and for the absence of client-triggered document reloads.

## Don'ts

- Do not call `window.location.reload()` for ordinary list navigation.
- Do not replace a document's manifest with a different PWA ID through client-side navigation.
- Do not render competing base and target manifest or Apple metadata in the installer document.
- Do not let a client supply arbitrary list IDs, manifest data, or launch URLs without server-side authorization.
- Do not claim that Safari/iOS can open its native installation flow through JavaScript.

## Open Questions

None. The installer route is `/quicklists/:projectId/install`; ordinary list routes use the base manifest; the operator validates the finished flow on iPhone and Android.
