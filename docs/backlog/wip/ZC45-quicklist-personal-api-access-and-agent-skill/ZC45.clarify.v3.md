# Clarify Round v3 — QuickList Personal API Access and Agent Skill

## Questions

### 1. When API access is switched off, should the token be deleted immediately, requiring a new token when re-enabled?

## Answers

### 1.

Yes. Disabling account API access deletes the token after an explicit confirmation explaining that the credential will be destroyed.

The operator also introduced a second authorization gate at list level:

- Every list has an **Enable API access for this list** setting.
- Lists created through the UI start API-disabled.
- Lists created through the agent API start API-enabled.
- API-disabled lists remain private from the automation API.
- Disabling account API access does not change any per-list API settings.
- If a user enables a list while account API access is disabled, keep the list setting but show a small inline yellow warning beneath the switch explaining that account API access must also be enabled from the profile.

## Resolution Summary

- Account API access and per-list API exposure are independent gates; both must be active for API access to an existing list.
- Turning account API access off requires confirmation and deletes the current token.
- Re-enabling the account later requires creating a new token.
- Per-list API flags survive account-level disable/re-enable.
- UI-created lists default to API-disabled; API-created lists default to API-enabled.
- Enabling a list while the account gate is off is allowed but visibly ineffective until the account gate is enabled.
