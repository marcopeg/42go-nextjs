# Execution Notes — QuickList Personal API Access and Agent Skill
**Task**: ./ZC45.task.md
**Plan**: ./ZC45.plan.md

## Decisions

- Use a dedicated `quicklist.api_tokens` table and an explicit boolean list exposure column.
- Keep session management routes separate from `/api/quicklists/v1` bearer routes.
- Use the shared Modal for one-time token disclosure and destructive disable confirmation.
- Keep the project-owned skill at `.agents/skills/quicklist` with a Python standard-library client.
- Resolve list names by exact case-insensitive equality only; UUIDs bypass name lookup.
- Store skill credentials in `~/.config/quicklist/credentials.json`, keyed by the canonical project path or `_global`, with atomic `0600` writes.

## Problems Encountered

- The skill scaffold created only placeholders; the final client, reference, and workflow were filled in and validated with the official skill validator.
- The public `ql42go.ngrok.app` address and standing development server both resolved to LingoCafe because the running environment was pinned with `APP_ID=lingocafe`. Visual and runtime verification used the production build on a temporary local port with `APP_ID=quicklist`.
- Full-page capture at the desktop viewport rendered incorrectly despite correct DOM geometry; a viewport capture confirmed the actual profile layout was healthy.

## Deviations From Plan

- Added a live two-user smoke test on the temporary QuickList production server in addition to the planned pure tests. It verified collaborator parity, owner-only deletion, hidden disabled lists, hidden exposure metadata, and immediate token revocation.

## Additional Requests

- Removed the redundant account-level API switch. Token existence is now the state: absent shows explanatory copy plus **Create API token**; present shows the masked token plus **Rotate token** and **Disable API access**.
- Moved the one-time disclosure action to the header and made it a two-tap progression: **Copy token** then **Done**. Selecting the token also copies it and advances the header action to **Done**; there is no separate close/cancel action before copying.
- Changed newly generated tokens to an unbiased alphanumeric-only format while retaining at least 256 bits of randomness. Legacy `ql_` tokens remain accepted so existing credentials are not revoked by the format refinement.
- Packaged the current QuickList origin and one-time raw token into a prefixed, versioned Base64URL connection code for both disclosure copy paths. The skill setup now accepts that single code through hidden input, validates and decodes it, and stores the normal scoped credential entry. The code is explicitly documented as transport encoding, not encryption.
- Added an operator-approved mobile fallback for envelopes voluntarily pasted into chat. The skill warns about retained secret history, passes the envelope only through configure-process stdin, proceeds with the operation, and recommends rotation plus secure terminal reconfiguration.
- Hardened the chat fallback after live initialization exposed PTY echo behavior: the stdin reader now temporarily disables terminal echo while receiving an envelope and restores the terminal state immediately afterward.

## Known Limitations

- Automated tests cover token primitives and the offline skill client. Database-backed route behavior was exercised live against the migrated local development database, but the two-user smoke harness is not part of the default `npm run qa` command.
