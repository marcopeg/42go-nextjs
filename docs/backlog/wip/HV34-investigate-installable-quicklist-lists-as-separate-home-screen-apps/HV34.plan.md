# Plan — Enable Per-URL Install Targets and Installable Quicklist Virtual Apps

## Goal

Add a reusable 42Go install-target framework that lets AppConfig map same-origin URL patterns to authorized server resolvers, emits one dynamic manifest/head identity per matched resource, and proves the design by making every accessible Quicklist list installable as its own virtual app using its UUID launch URL and current title.

## Milestones

### Milestone 1 — Define and test the install-target contract

- [x] Step 1 — Extend PWA configuration with explicit identities and URL-pattern overrides
  - Achieve: AppConfig can declare one or more serializable install-target patterns mapped to named server resolvers; static apps can declare a stable explicit manifest ID.
  - Create: Focused 42Go PWA pattern/validation modules and a Node test file.
  - Modify: `src/42go/pwa/types.ts`, current PWA app configs, `package.json` for a focused test command.
  - Delete: Nothing.
  - Touch points: `TPWAConfig`, resolved icon types, pattern grammar, stable ID/start URL/scope validation, app-level backward-compatible defaults.
  - Validation: Focused tests cover exact/nested pattern matching, extracted parameters, invalid patterns, same-origin path validation, and base identity fallback.
  - Notes: Use a small framework-owned `/literal/:param/**` grammar. Do not add a routing dependency for one feature.

- [x] Step 2 — Add the server-only resolver registry and target merge pipeline
  - Achieve: A matched AppConfig declaration resolves through a named server-only function, merges dynamic fields over app PWA defaults, validates the result, and fails closed when unavailable or invalid.
  - Create: `src/PWAInstallTargets.ts`, `src/42go/pwa/server/registry.ts`, `src/42go/pwa/server/resolve-install-target.ts`, and target/base adapters as needed.
  - Modify: PWA exports.
  - Delete: Nothing.
  - Touch points: AppID/config resolution, dynamic resolver context, icon fallback, private/static resolution state, canonical manifest target path.
  - Validation: Focused tests prove fallback merging and stable dynamic identity without importing database code into client AppConfig.
  - Notes: AppConfig stores resolver keys only. The resolver registry is the server/client firewall.
