# Refinement Questions v2 — Add a Play Action to the Reader Translation Popover

Answer inline under each question, then return to chat and say `next round`.

## Questions

### 1. What exact label should the single-word action use?

The proposed label is `Listen to word`, shown below the Play icon. The sentence action remains `Listen from here`.

Answer:

Use `Play word`.

### 2. Confirm whether word pronunciation is a one-shot action.

The proposed behavior when no continuous playback session exists is:

- close the translation popover;
- pronounce only the selected word once, using the current playback voice, language, and speed;
- do not open the global playback bar;
- do not start continuous sentence playback;
- finish in the idle state after the word ends.

Answer:

Confirmed. Single-word pronunciation is a one-shot, isolated action.

### 3. What should word pronunciation do when a continuous playback session already exists?

Please define both cases:

- Translation auto-paused active playback: should the word play once and then restart the previously active sentence, leave continuous playback paused, or end the old session?
- Playback was manually paused before translation opened: should the word play once and then leave the old session paused, restart it, or end it?

The safest proposal is to pronounce the word, then restore the previous session state: restart the active sentence only when translation had auto-paused it, and remain paused when the session was already manually paused.

Answer:

If continuous playback is running and `Auto-pause on translation` is disabled, hide `Play word`. If auto-pause is enabled, the word action may be used while the continuous session is paused by the translation interaction. The exact post-word resume behavior needs one final decision.

### 4. Should word pronunciation affect the visible player state?

The proposed rule is that word pronunciation does not open, close, seek, or advance the global playback bar; does not change playback percentage; and does not use sentence/word playback highlighting or guided scrolling. If a continuous session already exists, its bar remains visible in its paused state until the one-word utterance finishes.

Answer:

Confirmed. Word pronunciation is completely isolated from the playback bar and continuous playback UI. It does not open or require the playback bar and uses the same configured playback speed.

### 5. Which capability should control visibility for each action?

The current `playback.canPlay` requires all of the following: device speech support, a book playback language, a matching installed voice, and a readable sentence catalog.

Proposed split:

- Sentence action: visible only when full `playback.canPlay` is true.
- Word action: visible when the device supports speech and has a matching voice for the book language, even if the sentence catalog is unavailable.
- Both actions remain hidden while playback is actively speaking with translation auto-pause disabled.

Answer:

Use the same full capability requirement for sentences and words: if a sentence can be played, a word can be played. Hide the word action during active playback when translation auto-pause is disabled.

### 6. Should a one-word pronunciation emit analytics?

The proposed rule is to emit one existing `audio.play` event with `language`, `book_id`, and `page_id`, without word text, word ID, sentence ID, or translation content. This keeps privacy semantics intact while counting use of the listening feature.

Answer:

Yes. Emit `audio.play`. For both sentence and word playback, the event payload must include a non-sensitive type discriminator with value `sentence` or `word` so feature utilization can be measured.
