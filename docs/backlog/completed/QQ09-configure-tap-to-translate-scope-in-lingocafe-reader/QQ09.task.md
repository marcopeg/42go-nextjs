# Configure Tap-to-Translate Scope in LingoCafe Reader

## Elevator's Pitch

Add a reader preference that lets a LingoCafe reader choose whether tapping reading content translates the complete sentence or only the tapped word. Sentence translation remains the default.

## Business Gain

Readers learn differently. Context makes sentences useful; focused vocabulary work makes single-word lookup useful. The reader should support both without sending anyone outside the book. Chuck Norris chooses the scope. The translation obeys.

## Current State

The LingoCafe reader converts page content into sentence-level interactive elements in `BookPageReader.tsx`. Tapping a sentence highlights that sentence and requests its translation through `/api/lingocafe/translate`. Reader appearance preferences—font size, font family, background, and text color—are rendered in `BookReaderPreferencesPanel.tsx` and stored in browser local storage under `lingocafe.reader.preferences.v1` through `reader-preferences.ts` and the reader page. The current preference model has no translation-scope setting, and the customization panel has no translation control.

## Desired State

The Reading Preferences panel includes a Translation section with a tab-style choice using the established shared Tabs UI pattern used for theme/settings choices: `Translate full sentence` and `Translate single word`. Full sentence is selected by default for new, missing, malformed, and legacy stored preferences. Changing the selection updates the active reader immediately and persists locally with the other reader preferences. This translation-granularity choice is shared across light, dark, and system reader themes; it is not an appearance preference.

In full-sentence mode, current tap-to-translate behavior remains unchanged. In single-word mode, tapping a translatable word translates and highlights only that word, then presents the result through the existing reader translation experience. The interaction must choose the actual tapped word, rather than the complete enclosing sentence, while preserving the reader's authorization, source-content validation, caching, error handling, and popover behavior as applicable.

## Definition of Success

A reader can select sentence or single-word translation from the reader customization popup, immediately use the selected behavior, and find the choice intact after closing and reopening the reader in the same browser. Fresh and legacy users continue to get sentence translation until they deliberately choose word translation.

## Additional Context

The requested control belongs in the existing reader customization popup—the same surface used for font size, font family, background, and text color—not in global profile settings. The operator specifically prefers tabs, matching the app's existing theme/settings tab treatment, rather than a select, radio list, or switch.

The existing translation endpoint already enforces feature availability and validates requested source text against book-page content; single-word mode must remain within those protections. The implementation may need to evolve the sentence-only reader interaction and any endpoint assumptions that prevent valid individual words from translating, but it must not open the endpoint to arbitrary freeform content.

The existing reader preference store is profile-aware for light, dark, and system themes, with a shared font-size exception. Store translation scope in the same local reader-preference model as a reader-level value shared across theme profiles. Do not introduce server-side persistence.

## Assumptions

- `Translate full sentence` and `Translate single word` are the exact or near-final user-facing tab labels; minor copy polish is allowed.
- The default mode is full-sentence translation in every theme and for all existing saved preferences that lack the new field.
- Translation scope is a reader-level setting shared across light, dark, and system themes because it controls translation granularity, not appearance.
- Single-word translation means the word directly tapped by the reader, not an arbitrary text selection or manually entered text.
- The setting is local to the browser, like existing reader options, and does not sync across devices or user accounts.
- Existing translation permission and global enablement rules continue to determine whether either mode is available.

## Constraints

- Scope the UI to the LingoCafe reader's existing Reading Preferences popup.
- Use the same semantic tablist segmented-control pattern already used by the application for theme/settings controls; do not build a bespoke alternative.
- Persist locally through the existing reader-preferences storage flow, with defensive sanitization and a safe sentence-mode fallback.
- Preserve current full-sentence translation behavior by default.
- Preserve server-side authorization, request validation, page-membership validation, rate/cache behavior, and client-safe errors for translation requests.
- Do not add server-side, database, profile, or cross-device persistence for this preference.
- Do not change unrelated reader appearance, navigation, playback, progress, or translation-cache behavior.
- Run `npm run qa` after implementation.

## Acceptance Criteria

- The LingoCafe Reading Preferences popup contains a Translation section.
- The Translation section matches the existing settings tablist/segmented-control pattern.
- The tabs offer a full-sentence option and a single-word option.
- For a new reader or a stored preference value that is absent, invalid, or unrecognized, full-sentence translation is selected.
- Existing local reader preference payloads without the new setting load safely and use full-sentence translation.
- Changing the translation tab takes effect immediately in the currently open reader.
- The chosen translation scope persists in browser local storage with the existing reader preferences and is restored after a page reload or later reader visit in the same browser.
- Switching the active reader theme does not change the selected translation scope.
- In full-sentence mode, tapping content translates and highlights the containing sentence as it does today.
- In single-word mode, tapping a translatable word sends only that word for translation and shows its translation through the reader UI.
- In single-word mode, only the tapped word is highlighted; the containing sentence is not highlighted.
- Single-word mode does not translate the whole enclosing sentence merely because the word is inside it.
- Translation authorization, global enablement, page-content validation, cache use, errors, and popover dismissal remain enforced for both modes.
- The implementation does not permit arbitrary user-supplied text to bypass translation validation.
- The preference controls are keyboard accessible and expose the selected mode semantically through `role="tablist"`, `role="tab"`, and `aria-selected`.
- The reader customization popup remains usable on mobile and desktop.
- `npm run qa` passes after implementation.

## Dos

- Do make full-sentence translation the unambiguous default.
- Do reuse the current local reader-preference storage key and sanitization flow where appropriate.
- Do preserve reader theme/profile handling when adding the preference field.
- Do store translation scope independently from theme-specific appearance profiles.
- Do make the chosen mode visible and understandable before a reader taps text.
- Do test both modes after persistence and after opening a different book page.

## Don'ts

- Don't replace the requested tabs with a switch, dropdown, or custom control.
- Don't make single-word translation the default.
- Don't persist this preference to the API, database, user profile, or another device.
- Don't regress the existing sentence translation flow, content validation, or translation caches.
- Don't accept arbitrary text selection or freeform text as a workaround for word translation.
