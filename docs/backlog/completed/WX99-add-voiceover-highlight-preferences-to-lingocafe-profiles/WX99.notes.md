# Execution Notes — Add a Local Playback Settings Popover to the LingoCafe Reader
**Task**: ./WX99.task.md
**Plan**: ./WX99.plan.md

## Decisions

- Use a dedicated `lingocafe.reader.playback-preferences.v1` local-storage record with positive booleans defaulting to `true`.
- Render the settings panel directly in the fixed playback layer. This supersedes the attempted Radix Popover because its portal/dismiss layers failed inside the reader Modal, while the shared Modal cannot provide the required compact anchored presentation.
- Keep active sentence and boundary state inside playback even when their visual treatments are hidden.
- Coordinate automatic pauses through a shared reason set so settings and translation cannot resume each other's pauses.
- Store popover-open state in the playback controller so closing/resetting the player clears the settings surface reliably.

## Problems Encountered

- Focused ESLint initially rejected synchronously clearing component state inside an effect. The state moved into the playback controller, eliminating the effect and making page/player resets deterministic.
- The in-app browser runtime failed during setup before opening a tab with `Cannot redefine property: process`; retrying from a clean browser session produced the same failure.
- Operator verification found that the gear rendered but the popover did not appear. The popover portal was outside the reader's full-screen Radix dialog layer; the reader modal could suppress that detached overlay.
- After moving the portal, operator verification still found no response from the gear/speed control while neighboring player controls worked. The remaining failure was isolated to Radix Trigger event/ref forwarding through the repository's custom Button component.
- A third operator test still showed no tap response. The control still differed from the proven speed button because the clickable node itself was used as a Radix anchor and sat under a `display: contents` wrapper, both risky for mobile Safari hit testing.
- The alert and direct pause proved the button click path works. The invisible Radix dismiss layer then consumed the first Play tap as an outside click, confirming an overlay-layer conflict rather than a speech-controller failure.
- Mobile screenshot verification exposed two mounted reader surfaces sharing one settings-open state. The hidden desktop settings instance registered its own document listener, interpreted every tap in the visible mobile panel as an outside tap, and closed the panel before its controls could remain open.
- Follow-up mobile verification showed that Safari ignored the Tailwind arbitrary calculated bottom offset and placed the otherwise correctly aligned panel at its static position below the player.

## Deviations From Plan

- The shared Popover wrapper now accepts an explicit portal container. Playback settings resolve the nearest active modal content and portal inside it, retaining anchored behavior without crossing the reader dialog boundary.
- The gear/speed trigger is now a native button with an explicit controlled `onClick` toggle and visible open-state styling. Radix Popover is used only as the anchor/positioning/dismissal layer, removing trigger event indirection.
- Restored the proven direct shared-Button click pattern from the old speed control. Radix now anchors to a separate non-clickable wrapper, and the `display: contents` wrapper was replaced with a normal flex item.
- Removed Radix Popover and its temporary shared wrapper from the feature. The fixed panel mirrors the control bar's left/right insets, maximum width, safe-area bottom calculation, and sits 4.75rem above the bar at maximum z-index without an event-blocking backdrop.
- Hidden responsive settings instances now skip document dismissal listeners. The visible panel is positioned absolutely inside the player's proven fixed frame, uses the same full width and `max-w-2xl` alignment, sits 0.5rem above the bar, and has an opaque background so reader text cannot bleed through it.
- The 0.5rem vertical separation is declared as an explicit inline `bottom: calc(100% + 0.5rem)` style so mobile Safari cannot drop the generated utility rule.
- The player and settings panel use the same shared outer-surface class: `rounded-2xl`, border, `bg-background/95`, `shadow-lg`, and backdrop blur.
- Final visual feedback showed reader text bleeding through the 95% background. The shared outer-surface class now uses fully opaque `bg-background` and no backdrop blur for both the player and settings panel.
- Added `0.25×` as the first supported playback speed. Because the UI and local-storage sanitizer share `READER_PLAYBACK_SPEEDS`, selection, typing, persistence, and restoration accept the new value together.
- Mobile verification showed `grid-cols-5` falling back to a single column in the served stylesheet. The selector now uses an explicit `repeat(5, minmax(0, 1fr))` grid template so all speed buttons remain on one horizontal line.
- Moved horizontal padding from the divided settings container onto each row so separators extend to the panel's outer borders while labels and controls retain their alignment.
- Removed the temporary alert and manual `togglePause` call. Opening now goes directly through controller-owned `setSettingsOpen`, allowing the auto-pause reason to own the pause and resume it on every close route.
