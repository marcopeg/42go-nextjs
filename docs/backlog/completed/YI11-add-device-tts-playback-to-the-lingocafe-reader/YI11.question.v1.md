# Refinement Questions v1 — Add Device TTS Playback to the LingoCafe Reader

## Questions

### 1. Which controls belong in the bottom playback bar for the first release?

Proposed baseline: play/pause, close, a draggable percentage/seek control, and the visible percentage. No previous/next-sentence buttons or playback-speed selector unless explicitly requested.

Answer:

good. would it be possible to also add a playback speed like to enable "slow playback"?

### 2. What should manual scrolling do while speech is actively playing?

Proposed behavior: it does not interrupt or seek the current utterance. Playback continues, and the reader centers the next sentence only when that sentence is outside the active viewport. The user explicitly seeks with the playback percentage control to change the spoken sentence.

Answer:

exactly, if the user scrolls with the player's progress bar, that changes which sentence is going to be played.

if the user scrolls the page, it doesn't impact the playback at all.

but the "auto scroll" featue of the playback should be active only when the current sentence is inside the viewport. the user should be able to scroll to the bottom of the page and the playback should continue without recentering the current sentence. the user should scroll manually to the currently spoken sentence to reactivate the auto scroll.

### 3. Should speech advancement update the book's persisted reading progress (`progress_bps`)?

Proposed baseline: no. Playback has its own page-local position; only user scrolling continues to update normal reading progress. This avoids a background utterance overwriting the place where the reader deliberately left the page.

Answer:

ok for me, but we should record the "audio.play" event with language, book id and chapter id in the payload. i would not record the sentence that is being played so to do not overload the events.

### 4. How should the reader choose its speech language and handle missing support?

Proposed behavior: request a device voice matching the book page's source/content language; if no exact voice exists, use the device's normal speech fallback and display an unobtrusive notice. If browser speech synthesis itself is unavailable, disable the FAB with a clear unavailable message.

Answer:

good for me. the voice language must match the book's language or no playback should be available.

NOTE: you should know that in the future we might move to an api call to generate the tts (like aws polly or similar), so you may want to structure the code so that it's reasonably easy to make the switch from device capability to api call.

### 5. During active playback, should tapping a sentence remain translation-only?

Proposed behavior: yes. A tap opens the existing translation popover but does not alter the sentence currently being spoken or the next playback position. The percentage seek control remains the explicit way to change playback position.

Answer:

exactly
