# Execution Notes — Add Device TTS Playback to the LingoCafe Reader
**Task**: ./YI11.task.md
**Plan**: ./YI11.plan.md

## Decisions

- Keep one playback controller in the route and pass view state into both responsive reader surfaces.
- Treat normalized primary language matches such as `sv` and `sv-SE` as the same language, while rejecting voices from a different primary language.
- Use the existing client event queue for one `audio.play` event whenever an utterance reaches its start callback.
- Build the sentence catalog from rendered sentence spans and their nearest block element so paragraph pauses follow the actual reader DOM.
- Keep translation state local to `BookPageReader`; sentence activation is also reported to the route-level playback controller.

## Problems Encountered

- The documented `john` / `john` browser account initially had an existing session but an incomplete profile. Submitting all visible required onboarding choices still returned "Profile is still incomplete."
- After logging out to try the seeded complete-profile account, both `jane` / `jane` and `john` / `john` returned "Login failed" on the public ngrok test URL, blocking authenticated reader smoke checks.
- Mobile Chrome placed the FAB over the top-left Back control because positioned descendants were nested under the Radix portal's fixed overlay, mobile `min-h-full` content panel, Modal flex body, and reader flex surface. Desktop Chrome emulation did not reproduce WebKit's containing-block behavior. The playback controls now use a normal-flow, non-scrolling flex footer beneath the reader scroll container, eliminating positioned ancestors and viewport offsets entirely.
- The correctly positioned mobile FAB still ignored taps because its outer footer used `pointer-events: none` and relied on a descendant `pointer-events: auto` override. Desktop Chromium hit-tested the child, while iOS WebKit treated the ancestor subtree as untouchable. The complete playback control subtree now uses normal pointer events.
