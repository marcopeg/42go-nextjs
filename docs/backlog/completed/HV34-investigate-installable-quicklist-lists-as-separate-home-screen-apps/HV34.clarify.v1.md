# Clarify Round v1 — Investigate Installable Quicklist Lists as Separate Home-Screen Apps

## Questions

### 1. Should installation be explicit opt-in or automatically available for every URL?

Recommended: 42Go should be capable of describing any same-origin URL, but only routes/resources registered by the application receive a dedicated install target. This guarantees a stable ID, authorized metadata, deliberate scope, and valid icons. A universal "install this URL" action would have to invent those values and could create unstable or duplicate apps.

### 2. Should the first delivery be framework-only or a complete vertical slice?

Recommended: deliver the reusable 42Go install-target infrastructure together with one Quicklist list implementation as its reference consumer. The Quicklist slice proves that dynamic database data, authorization, icons, manifests, and real browser installation work together. Framework-only success cannot prove the browser behavior that carries the risk.

### 3. Which scope strategy should version 1 target?

Recommended: build the smallest vertical spike with the existing Quicklist URLs and a shared `/quicklists/` scope, but make passing the physical-device matrix a release gate. Move to a dedicated non-overlapping launcher shell such as `/installed-lists/<id>/` only if the shared scope causes link-capture, navigation, or multiple-install problems. Mandating the separate shell immediately is cleaner but materially increases routing work before the browser behavior is proven.

## Answers

### 1.

Add one or more URL patterns in an AppConfig area. Matching patterns override the app-level installation defaults through the proposed resolver. Resolution must be fully dynamic: launch URL, name, icon, colors, and related fields may come from the database. Quicklist lists may eventually choose different names and icons.

### 2.

Deliver all framework-level preparation and configure Quicklist so each list can be installed as the reference vertical slice. In the first Quicklist pass, override only the launch path for the selected list and the application name derived from the list title. Keep the base Quicklist icon and colors initially.

### 3.

Proceed with testing and the proposed initial scope strategy. There is no requirement to discover, enumerate, or persist which lists are installed.

## Resolution Summary

- Dedicated install targets are explicit AppConfig URL-pattern overrides, not automatic metadata invented for every URL.
- AppConfig holds serializable pattern/resolver declarations; dynamic resolver implementations remain server-only and may load authorized database data.
- The first delivery is a complete framework-plus-Quicklist vertical slice.
- Quicklist version one dynamically overrides the list launch URL and name while inheriting the base app icon and colors.
- Shared-scope behavior will be tested; installed-list detection and enumeration are out of scope.
