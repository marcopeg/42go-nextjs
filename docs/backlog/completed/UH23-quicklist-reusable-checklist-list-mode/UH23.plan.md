# Plan — QuickList: Reusable checklist list mode

## Goal

Persist a Todo/Checklist mode in list settings, expose it through list settings, and replace Todo's completed-item cleanup action with a non-destructive checklist reset while preserving every other completion and ordering behavior.

## Milestones

### Milestone 1 — Future-proof QuickList persistence

- [x] Step 1 — Add the JSONB schema migration
  - Achieve: Give lists extensible `settings` and `metadata` JSONB storage, and give list items extensible `metadata` JSONB storage, without changing current behavior.
  - Create: A timestamped Knex migration under `knex/migrations/`.
  - Modify: None.
  - Delete: None.
  - Touch points: `quicklist.projects.settings`, `quicklist.projects.metadata`, and `quicklist.tasks.metadata` as non-null JSONB columns defaulting to `{}`.
  - Validation: Run the migration in development only; inspect the resulting columns/defaults and confirm existing list and task rows remain readable.
  - Notes: Production migration execution and deployment remain the operator's manual pre-deploy responsibility.

### Milestone 2 — Mode-aware, app-scoped API contract

- [x] Step 2 — Add validated mode persistence and reads
  - Achieve: Model `settings.mode` as `todo | checklist`, defaulting to `todo`, while preserving unknown settings keys.
  - Create: A small QuickList mode/settings helper and focused Node test coverage for defaulting and validation behavior where practical.
  - Modify: `src/app/api/quicklists/[projectId]/route.ts`, `src/app/api/quicklists/[projectId]/info/route.ts`, `src/app/api/quicklists/route.ts`, and client response types in `src/lib/quicklists/hooks/useQuicklists.ts`.
  - Delete: None.
  - Touch points: Detail and Info GET payloads expose mode; project PATCH accepts a validated mode update alongside title updates; new lists rely on the JSONB default; writes retain owner-or-collaborator edit access and include `app_id` isolation.
  - Validation: Exercise valid Todo/Checklist updates, invalid values, inaccessible lists, cross-app lists, ETag refresh behavior, and preservation of unrelated settings keys.
  - Notes: The existing project PATCH access check lacks explicit app scoping and must be corrected as part of this security-sensitive work.

- [x] Step 3 — Add atomic checklist reset and protect Todo cleanup
  - Achieve: Provide a checklist-only bulk reset that clears `completed_at` and `completed_by` without deleting or reordering tasks; preserve current Todo cleanup behavior.
  - Create: `src/app/api/quicklists/[projectId]/reset-checklist/route.ts`.
  - Modify: `src/app/api/quicklists/[projectId]/drop-completed/route.ts` and shared QuickList client types/hooks.
  - Delete: None.
  - Touch points: Owner-or-collaborator and app-scoped authorization, mode verification, a single transactional bulk update, project freshness/ETag refresh, and safe error responses.
  - Validation: Confirm reset preserves task IDs, titles, positions, and ordering while clearing completion markers; confirm cleanup remains available and destructive only in Todo mode and is rejected in Checklist mode.
  - Notes: Do not change the established checked-item grouping or manual drag ordering in either mode.

### Milestone 3 — List settings and mode-specific actions

- [x] Step 4 — Expose the Todo/Checklist tab control in list settings
  - Achieve: Let any user with edit access view and change the persisted list mode from the existing Info/settings page.
  - Create: A small reusable presentation component only if extracting the two-option control improves clarity.
  - Modify: `src/app/(app)/quicklists/[id]/info/page.tsx` and supporting hook/API types.
  - Delete: None.
  - Touch points: Accessible tab-like Todo/Checklist control, optimistic/busy/error feedback, refresh/cache synchronization, and persisted selection after reload.
  - Validation: Verify owner and collaborator flows, selected state after reload, disabled/busy handling, and invalid/write-error feedback.
  - Notes: The control is a mode selector, not a generic JSON editor; list and task metadata remain out of the UI in this delivery.

- [x] Step 5 — Switch the detail-page bulk action by mode
  - Achieve: Keep current Todo UI unchanged and render `Reset checklist` instead of `Drop completed tasks` for Checklist lists when items are checked.
  - Create: None unless a focused action component improves readability.
  - Modify: `src/lib/quicklists/hooks/useQuicklistData.ts` and `src/app/(app)/quicklists/[id]/page.tsx`.
  - Delete: None.
  - Touch points: Mode-aware client state, reset confirmation, optimistic/error recovery, cache updates, and existing polling behavior.
  - Validation: In Todo, check items and confirm cleanup still deletes them. In Checklist, check items and confirm reset clears checks without deleting or altering stored positions; ensure no other completion/order behavior changes.
  - Notes: Preserve the current bottom-action placement and only show an action when there are completed items.
