# Execution Notes — QuickList: Reusable checklist list mode
**Task**: ./UH23.task.md
**Plan**: ./UH23.plan.md

## Decisions

- Persist the list mode as `quicklist.projects.settings.mode`; supported values are `todo` and `checklist`, with Todo as the default.
- Add future-facing JSONB storage only where approved: list `settings` and `metadata`, plus task `metadata`.
- Checklist keeps all existing completion and ordering behavior; only its bottom bulk action changes.
- Development migrations may be run during this task. Production migration execution remains the operator's manual pre-deploy action.
- The existing project PATCH query now scopes writes by `app_id`, closing the gap identified during planning.

## Problems Encountered

- The standard public QuickList test URL (`https://ql42go.ngrok.app/`) returned ngrok error `ERR_NGROK_8012`: its upstream service was unavailable.
- A local development server was started through `make app.start`, but browser visual verification could not use it because the QuickList host match requires `quicklist.42go.dev` and the browser cannot route that host to this local process. Host-header API checks did verify QuickList app resolution and authenticated list reads.
- The first isolated API smoke cleanup used the wrong create-response shape and left one development-only list. It was identified by its exact UUID and deleted before the corrected smoke run.

## Deviations From Plan

- No product-scope deviation. Full interactive browser verification is deferred until the shared QuickList tunnel is healthy.
