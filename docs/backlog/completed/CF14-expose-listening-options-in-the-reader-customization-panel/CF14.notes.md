# Execution Notes — Expose Listening Options in the Reader Customization Panel
**Task**: ./CF14.task.md
**Plan**: ./CF14.plan.md

## Decisions

- Use the existing shared `Modal`; CF14 changes its reader-owned content only.
- Preserve one canonical playback preference controller and extract a shared editor for the two control surfaces.
- Represent settings auto-pause ownership with named open surfaces so independent panels cannot clear each other's pause reason.
- Resolve an empty initial device voice list after 1.5 seconds if `voiceschanged` does not fire, preventing an indefinite settings loader while still accepting later voice-change events.
- Prewarm on the default authenticated `/books` entry and retain provider initialization as the direct-reader fallback.
- Distinguish view navigation from setting selection: Reading/Listening uses a flat full-width tab bar, while Theme and Speed share one bordered segmented-setting component.
- Use one 1 px semantic `border-border` divider between the Reading and Listening navigation tabs.
- Promote the flat subview navigation into the shared `NavigationalTabs` component; the component owns its explicit separator and keyboard behavior.

## Problems Encountered

- Browser verification could not reach an authenticated reader. The ngrok login rejected both documented seed accounts (`john` and `jane`), and the in-app browser was the only connected browser session.

## Additional Requests

- The operator requested planning and immediate execution in the same workflow.
- After mobile review, the operator requested flat navigational tabs for Reading/Listening and the exact Theme segmented-control UI for Speed.
