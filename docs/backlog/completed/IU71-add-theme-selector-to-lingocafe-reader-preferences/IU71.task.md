# Add Theme Selector to LingoCafe Reader Preferences

## Elevator's Pitch

Add the existing profile-page theme selector to the LingoCafe reading preferences panel. Place it immediately after the live preview and before the font-size control so readers can change the app appearance from the customization flow.

## Business Gain

Readers can choose light, dark, or system appearance without leaving the reader. The control stays familiar because it reuses the profile page's tab-style theme UI and changes the same persisted preference.

## Current State

The reader preferences panel in `src/app/(app)/(lingocafe)/books/_components/BookReaderPreferencesPanel.tsx` starts its settings flow with Font size after the sticky preview. Reader preferences already select a theme-specific profile from the global theme state in the reader page, while the profile page has the established light/dark/system tab UI in `src/42go/components/ProfileBlock/blocks/ThemePreference.tsx`.

## Desired State

The reader preferences panel shows a Theme section directly after the preview and before Font size. It provides the same tab-style control and options as the profile page: Auto/system, Light, and Dark. Selecting an option updates the same global persisted application theme through the shared theme system, equivalent to choosing it from the profile page, and the reader updates to the corresponding theme-specific preference profile.

## Definition of Success

A reader can open Reading Preferences, see the Theme selector as the first configurable item after the preview, select Auto, Light, or Dark using the profile-style tab control, and immediately see the app and reader reflect the selection. Font size and all existing preferences remain available and retain their current behavior.

## Additional Context

The reader derives `activeReaderThemeProfile` from the shared `useTheme()` value in `src/app/(app)/(lingocafe)/books/[bookId]/[pageId]/page.tsx`; it supports `light`, `dark`, and `system` profiles. The existing profile theme selector is intended as the visual and interaction reference. Completed task GB40 documents the shared immediate theme-selection behavior; completed task IZ29 documents the current reader preferences panel layout and sticky preview.

## Assumptions

Use the existing shared `next-themes` integration and its persistence behavior. The reader-panel selector and profile-page selector are equivalent entry points for the same global theme preference. "Same tab-ui control" means matching the profile page's tab semantics, labels, icons, selected styling, and immediate-apply behavior as closely as practical. No new reader-specific theme storage is needed.

## Constraints

Keep the change scoped to the LingoCafe reading preferences panel and shared theme selector reuse/extraction only if genuinely needed. Place the Theme section after the preview and before Font size on desktop and mobile. Preserve the existing reader preference storage, theme-profile mapping, modal behavior, and preference controls. Do not add a second theme persistence path or change reader routes/API contracts.

## Acceptance Criteria

- [ ] Reading Preferences displays a Theme section immediately after the preview and before Font size.
- [ ] The theme control uses the same tab-style UI pattern as the profile page.
- [ ] The control offers Auto/system, Light, and Dark options with clear selected state and accessible tab semantics.
- [ ] Selecting an option immediately applies and persists the same global application theme as the profile-page selector through the shared theme system.
- [ ] Selecting a theme causes the reader to use the existing corresponding `light`, `dark`, or `system` reader-preference profile.
- [ ] Existing font-size, font-family, background, foreground, translation, and reset controls keep their current behavior.
- [ ] The panel remains usable on mobile and desktop, including the existing sticky preview behavior.
- [ ] `npm run qa` passes after implementation.
