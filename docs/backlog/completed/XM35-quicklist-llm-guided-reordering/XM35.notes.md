# Execution Notes — QuickList LLM-Guided Reordering
**Task**: ./XM35.task.md
**Plan**: ./XM35.plan.md

## Decisions

- Reuse `quicklist.projects.settings` for `sortingInstructions`; no database migration is needed.
- Treat the operator's final length statement as 250 Unicode characters for both list names and item text.
- Keep the existing `/items/reorder` API for compatibility and add the LLM-oriented `/reorder` contract beside it.
- Use the shared 42Go `Modal`; no feature-owned overlay shell.
- Count Unicode code points with `Array.from()` so astral characters are not counted as two UTF-16 code units.
- Require one strong ETag value. Missing/malformed `If-Match` returns 428; a well-formed stale value returns 409.
- Keep POST output compact: item ID and resulting position plus a replacement ETag.
- Keep sorting-instructions mutation separate from reorder mutation: strict `{ "sortingInstructions": string }` in and the same compact field out.
- Treat sorting guidance supplied with a sort request as durable list policy; persist it, then fetch fresh reorder context because the prior ETag is stale.

## Problems Encountered

- The direct Node test runner cannot resolve the app's `@/` import alias. The pure reorder contract was kept alias-free, while the route continues using repository-standard absolute imports to the server ETag helper.
- The in-app browser screenshot operation timed out. DOM/accessibility verification remained available and showed no browser console errors.
- The browser viewport override did not change the reported 1280×720 viewport, so an independent 390 px geometry check could not be completed in that environment.
- Live use exposed that argparse did not accept trailing positional `ITEM_UUID:POSITION` values after `--etag`. The client now uses repeatable `--item ITEM_UUID:POSITION` options and has a parser regression test.

## Deviations From Plan

- No migration was created because the existing `quicklist.projects.settings` JSONB column cleanly owns the new value.
- Desktop interaction and persistence were verified live. Mobile behavior was verified structurally through the shared `Modal` contract and responsive classes, but the browser environment did not honor its viewport override.
