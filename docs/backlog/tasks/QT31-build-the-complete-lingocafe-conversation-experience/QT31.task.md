# Build the complete LingoCafe conversation experience

## Elevator's Pitch

Turn the conversation corpus loaded by AS82 and YE24 into a complete signed-in LingoCafe feature: protected APIs, desktop and mobile navigation, starred discovery, category browsing, profile-derived level filtering, exact-conversation reading, persistent read/star state, word/sentence translation, and full-dialogue device voiceover.

## Business Gain

Learners can consume the new conversation library end to end in the development app, not merely store it. Everyday situations become browsable, level-appropriate practice that can be translated, heard, saved, and revisited alongside books.

## Current State

AS82 owns the 42go PostgreSQL schema and standalone conversation data contract. YE24 owns the books-side `conv-push` skill and full-corpus development-data load. LingoCafe already has profile language/level preferences, authenticated AppLayout pages, desktop/mobile menus, live translation with a shared translation-mode FAB, and device speech playback for book pages. No conversation routes, APIs, DTOs, discovery views, category navigation, dialogue reader, or conversation-specific state mutations exist yet.

## Desired State

Add protected browser-consumed APIs under `/api/lingocafe/conversations` that derive the user from the session and query the AS82 schema. Provide discovery data, visible roots, category children, materialized scenario matches, semantic variants, exact language/CEFR choices, ordered actor-attributed rounds, and current-user read/star state. Add idempotent read/unread and star/unstar mutations. Do not evaluate source YAML category queries at runtime; consume materialized membership.

Use GET `/api/lingocafe/conversations?band=...`, GET `/api/lingocafe/conversations/categories/[...categoryPath]?band=...`, GET `/api/lingocafe/conversations/[conversationId]`, and PUT/DELETE read and star resources beneath the exact ID. The server derives target language from profile; the client cannot override it. Missing supported corpus language returns a valid empty DTO, while incomplete profile is 422. Invalid band/path/ID is 400 and missing or invisible content is 404.

Add a client-only `/conversations` discovery page under `AppLayout`. Show a Starred section only when the signed-in user has stars for the current target language, regardless of the selected level band, with explicit language/CEFR badges. Show a learner-band filter and language-visible root categories. Initialize the band from `auth.users.profile.targetLevel`: `a1` -> Beginner/A1, `a2` -> Intermediate/A2+B1, and `b2` -> Advanced/B2. Store view overrides in the URL or equivalent navigation state without silently modifying the profile.

Add category routes that preserve a breadcrumb/path through the plural-parent graph, list visible child categories, and present materialized matching scenarios and semantic variants with exact conversations available for the profile target language and chosen band. Categories are navigation views, not exclusive scenario owners. Intermediate results must label A2 and B1 and require a deterministic learner choice when both exist. Handle missing language coverage without fabricating fallback conversations.

Every path node must be visible/language-applicable and every adjacent segment must be a direct stored parent edge. Roots have no canonical parent edge; do not promote a child because a parent is hidden. Runtime eligibility requires visible scenario, variant, and exact records plus language-applicable scenario/variant scopes. Explicit localizations are nullable and never fall back across language or level.

Add an immersive exact-conversation route that shows localized title and description, useful scenario/variant context, language/CEFR badges, star control, read state, and every ordered round in a calm chat-inspired interface. Actor names and turn order must remain understandable without relying on color or alternating alignment alone. Render allowed basic Markdown safely. Mark a conversation read only after its content loads successfully; keep unread as an idempotent API operation even if the first UI mainly exposes status.

Detail GET remains read-only. PUT state mutations require a currently eligible exact chain and preserve the first timestamp on repeat; DELETE may clean stale state when the exact row still exists. Actor and round arrays are strictly ordered; a missing actor or empty/malformed round set fails closed rather than returning partial dialogue.

Support translate-word and translate-sentence throughout the conversation area. Reuse the exact reader translation-scope preference, `ExpandableFab`, protected translation API/cache, language-choice behavior, and accessible popover interaction. Extract a shared translatable-text surface from the book reader where necessary instead of copying its state machine. Each text block must use its actual source language: current category metadata is canonical English, while exact titles/descriptions/rounds use the conversation language.

Extend translation with a discriminated context for book page, category, or exact conversation while retaining legacy flat book requests. Context/profile/text authorization must happen before cache lookup. The server derives authoritative source text and language; category source is English, conversation source is exact language, and target remains profile own language.

On the exact conversation page, reuse the device speech provider, playback controller, preferences, highlighting, and floating controls. Register speech units in round/sentence order, keep actor labels visual rather than spoken, and highlight the active sentence/round. Multiple actor voices are explicitly not required. When playback is active, it replaces the idle translation/voiceover FAB bar exactly as in the book reader.

Generalize playback identity to a content namespace/key while preserving existing book behavior. Conversation unit IDs include conversation ID, round position, and sentence index; actor labels are excluded from the speech catalog.

Add Conversations to the LingoCafe desktop top menu and mobile bottom menu with a suitable Lucide icon. Add explicit `page:conversations` protection; keep existing `api:lingocafe` protection unless refinement proves a separate API feature necessary. The mobile destinations become Books, Conversations, and Account and must fit the established navigation contract.

Use the actual development database populated by YE24 for final browser verification. The page must remain robust when the database is empty or contains malformed/retired records, but the acceptance path exercises the full imported corpus.

## Definition of Success

After signing into the development LingoCafe app, a learner can open Conversations from desktop or mobile navigation, browse the imported root/category graph, filter by the profile-derived learner band, choose and open an exact conversation, understand every speaker turn, translate words or sentences, listen to the full dialogue, star/unstar it, and see persistent read/star state after refresh. The flow works against the full corpus loaded by `conv-push`, passes QA/tests, and is visually verified on mobile and desktop.

## Additional Context

Depends on 42go-nextjs AS82 for schema/contract and books YE24 for the importer and development-data load. Reuse the current LingoCafe reader components and design system rather than creating parallel translation or playback stacks.

## Assumptions

- Runtime content visibility includes every imported non-retired/non-deprecated record so the current draft/review corpus remains testable; source status is preserved and may be tightened in a future publication workflow.
- Stars are shown only for the current profile target language but across all CEFR bands, with badges; changing target language changes the visible star set without deleting state.
- Read and star state attaches to the exact conversation ID.
- Repeated PUT preserves the existing read/star timestamp and reports whether state changed; DELETE supports stale-state cleanup without exposing other users.
- Category metadata remains canonical English until source localization exists; interactive translation covers it.
- Learning-goal browsing, search, corpus authoring, backoffice administration, and distinct actor voices are outside this task.

## Constraints

- Use client-only authenticated routes, `AppLayout`, browser fetch with same-origin credentials, and server-side policy enforcement.
- Derive user identity from the session; never accept a client user ID.
- Validate route/query/mutation input server-side and return stable DTOs and safe errors.
- Consume AS82 materialized category membership and language applicability; do not implement the YAML query engine in runtime code.
- Reuse the established translation cache/API, reader preference, expandable FAB, device speech provider, playback controls, and sanitized Markdown path.
- Do not fork translation or speech preferences and do not require a second voice per actor.
- Use semantic tokens, accessible labels/states, visible actor labels, minimum 44 px touch targets, safe-area offsets, reduced-motion behavior, and light/dark support.
- Keep starred/read writes idempotent and conversation existence-checked.
- Run targeted tests, `npm run qa`, and browser verification through `https://lc42go.ngrok.app/` near 390 px and desktop widths against the populated development database.

## Acceptance Criteria

- Protected APIs return discovery, visible roots/children, materialized scenario matches, variants, exact conversations, ordered rounds, and current-user state for validated language/band inputs.
- Profile target language is authoritative and cannot be overridden by query input; Spanish/German profiles currently receive usable empty results.
- Read/unread and star/unstar endpoints are idempotent, session-derived, and cannot affect another user.
- `/conversations` is protected, linked from desktop and mobile navigation, and unavailable to apps without `page:conversations`.
- The discovery page omits an empty Starred heading and otherwise shows current-language stars across bands with explicit language/CEFR badges.
- Beginner maps to A1, Intermediate to A2+B1, and Advanced to B2; the initial value comes from profile and a local override does not mutate profile.
- Language-visible root and child categories navigate through valid multi-parent paths without implying exclusive scenario ownership.
- Invalid adjacency, hidden path nodes, or language-inapplicable path nodes fail closed; hidden parents do not promote children to roots.
- Category results expose available exact choices and Intermediate never selects between A2/B1 nondeterministically.
- The exact conversation view renders localized metadata and every ordered actor/text round in an accessible chat-inspired layout with safe Markdown.
- Successful content load marks the exact conversation read and star state persists across reloads.
- Word/sentence translation works on discovery/category content and exact conversation content using the existing control, preference, API, and cache.
- Translation authorizes the context and text before cache access, preserves legacy book requests, uses English for categories and exact language for conversations, and never translates actor labels or UI chrome.
- Voiceover reads the exact conversation in order through the existing playback stack, highlights active content, and preserves pause/resume/seek/speed/settings/error behavior.
- The idle FAB layout and active-player substitution match the book reader and respect mobile safe areas.
- Loading, empty, missing-language, retired-content, malformed-data, unauthorized, translation-failure, and playback-unavailable states are usable and safe.
- The full path is manually verified against YE24-populated development data on mobile/desktop and light/dark themes.
- Targeted API/logic/component tests and `npm run qa` pass.
- Shared desktop/mobile menus remain active for nested conversation URLs using exact-or-descendant matching.

## Dos

- Extract reusable reader primitives when translation/playback logic is currently book-specific.
- Keep API DTOs small and explicit despite rich JSONB source metadata.
- Preserve category path context and learner band across navigation.
- Make speaker attribution textual and semantic, not color-only.
- Use the populated development corpus for the final acceptance walkthrough.

## Don'ts

- Do not duplicate category query semantics in API handlers.
- Do not build another translation cache, preference key, or playback controller.
- Do not expose raw editorial JSONB to the browser unless a field is intentionally part of a DTO.
- Do not hide the current corpus merely because its lifecycle values are draft/review.
- Do not add search, goal browsing, authoring, administration, or per-actor voice selection.

## Refined Decisions

- Canonical routes are discovery, catch-all category path, and exact reader; band and validated return context persist in URLs.
- Backend logic lives in a typed conversation data-access module with thin protected route handlers and no-store responses.
- The page reuses normal AppLayout for discovery/categories and an immersive reader surface for exact dialogue.
- Translation and playback are generalized shared reader primitives, not parallel implementations.
- Final acceptance uses the populated development database and signed-in desktop/mobile browser sessions.
