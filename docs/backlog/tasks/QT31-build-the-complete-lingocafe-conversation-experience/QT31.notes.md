# Execution Notes — Build the complete LingoCafe conversation experience
**Task**: ./QT31.task.md
**Plan**: ./QT31.plan.md

## Decisions

- Three independent refinement passes established the API, responsive UI, translation, playback, state, and browser-acceptance contracts.
- The user's explicit instruction to continue through the full development lifecycle is the accepted-plan and execution gate.
- Backend, frontend/navigation, and shared translation/playback work are delegated to separate agents with non-overlapping ownership.
- Discovery roots are returned only when their descendant graph contains an eligible exact conversation for the selected language and band.
- Explicit scenario/variant localizations remain nullable. Canonical fallback metadata retains its canonical source language so translation authorization never mislabels English as the exact language.
- State deletion is a blind, user-scoped, idempotent cleanup and does not reveal whether an unavailable conversation ID exists.

## Problems Encountered

- The shared default-auth user ID initially resolved before the LingoCafe app-scoped user with the same email. Session lookup now requires the active app ID before using the app-scoped email fallback.
- Final adversarial review found invalid-band fallback, unsupported-language roots, incomplete translatable metadata, canonical-language mislabeling, an unavailable-content existence oracle, and several translation/navigation accessibility gaps. All were corrected before completion.

## Deviations From Plan

- Conversation translation reused the existing cache, preference key, endpoint, sentence segmentation, and `ExpandableFab`, while exposing a conversation-specific translatable-text adapter instead of moving the entire book reader component in this task.

## Additional Requests

- Deliver a consumable development feature with the full database, populated corpus, and frontend running.
- Use sub-agents throughout refinement and lifecycle execution.
- Make the mobile multi-level chooser directly draggable from either the sheet or its backdrop: downward motion follows the pointer, short drags snap back, and committed drags or flicks dismiss.
- Remove the backdrop flicker observed after gesture dismissal by keeping the gesture fade as the sole overlay exit animation.

## Known Limitations

- The canonical corpus currently supports English, Italian, and Swedish; configured Spanish and German target profiles receive an explicit empty state.
- The signed-in acceptance account intentionally retains one starred/read conversation as persistent-state evidence.

## Post-completion Persona Follow-up

- Wrapper task NG69 and books task LL42 are exploring actor personas and avatars. This is follow-up scope and does not rewrite QT31's completed delivery.
- Proposed reader rule: resolve the main conversation cast from persisted `profile.ownLang`; use that language's cast when published and otherwise fall back to a universal male/female pair.
- The current supported `ownLang` values are `en`, `it`, `es`, `de`, `sv`, `fr`, `pt`, `nl`, `da`, `no`, `fi`, `pl`, `cs`, and `el`.
- Actor selection must not change the exact conversation text, IDs, read/star/progress state, translation source authorization, or actor-slot round attribution.
- A future reader child task should own API payloads, fallback selection, avatar rendering, cache invalidation, accessibility, and behavior when `ownLang` changes while a conversation is open.
- The content direction now uses rich recurring archetypes explicitly assigned to actor slots. Language packs contextualize the same archetype rather than replacing it with an unrelated person.
- Professional and situational actors should normally render a coherent flat role icon while retaining a textual speaker name or role label. The icon is supplementary and must not become the only speaker identifier.
- Books now has four circle-safe proposal SVGs for Mark Carter, Marco Conti, Sophie Clarke, and Sofia Rinaldi. A future reader task should consume published asset references rather than copy task-workspace paths or hardcode persona artwork.
- Books has now promoted those records and SVGs to canonical paths under
  `content/personas/<persona-id>/`. The reader must still consume
  them through the publication/API contract rather than reach into the books
  filesystem directly.
- Personas are shared content rather than conversation-owned records. Future
  reader storage/API design should permit reuse by other features while the
  conversation domain owns only its cast assignments.
- Stable conversation-facing persona IDs are `mark-carter` and `sophie-clarke`; localized names are presentation IDs resolved from `profile.ownLang`. The API must not model Marco or Sofia as independent learner-state identities.
- Books LL42 has now accepted and populated the source cast contract: every
  semantic variant exhaustively maps each scenario actor to either a shared
  persona ID or scenario fallback identity, and exact conversations inherit it.
  Reader work still waits for YE24/AS82 publication, but should consume that
  mapping directly rather than infer personas from actor order, actor names, or
  language.
- Books found 69 exact conversations with actor names embedded inside round text. A future migration must keep dialogue names, speaker labels, grammatical agreement, and avatar presentation consistent; client-only label substitution is unsafe.
- Reader/API assessment found the existing actor-map boundary is already the
  correct avatar seam. The detail API should resolve persona presentation from
  `profile.ownLang` and return the resolved display name, stable persona ID,
  presentation ID/context, public avatar URL, and optional default-avatar
  fallback once per actor. Rounds remain unchanged and carry only `actorId`.
- Proposed UI behavior reserves a fixed avatar gutter on both sides and renders
  the avatar plus visible actor label once at the start of each consecutive
  actor run. Later messages in the same run retain the gutter so bubbles do not
  jump. Scenario-sourced actors use a neutral initials/role fallback and never
  borrow an unrelated persona.
- Published avatar URLs should be derived from relative content-addressed asset
  keys through `LC_ASSETS_BASE_PATH`; the reader must not copy SVGs into the
  Next.js bundle or store environment-specific asset hosts in client data.
- Because the conversation feature is pre-release, the reader follow-up should
  target the rewritten final schema directly. It does not need optional persona
  fields, legacy missing-cast fallback, or dual-query compatibility. Explicit
  `source: scenario` remains supported; a missing cast row is malformed data.
