# Execution Notes — Build the complete LingoCafe conversation experience
**Task**: ./QT31.task.md
**Plan**: ./QT31.plan.md

## Decisions

- Three independent refinement passes established the API, responsive UI, translation, playback, state, and browser-acceptance contracts.
- The user's explicit instruction to continue through the full development lifecycle is the accepted-plan and execution gate.
- Backend, frontend/navigation, and shared translation/playback work are delegated to separate agents with non-overlapping ownership.
- Discovery roots are returned only when their descendant graph contains an eligible exact conversation for the selected language and band.
- Explicit scenario/variant localizations remain nullable. Canonical fallback metadata retains its canonical source language so translation authorization never mislabels English as the exact language.
- State deletion is a blind, user-scoped, idempotent cleanup and does not reveal whether an unavailable conversation ID exists.

## Problems Encountered

- The shared default-auth user ID initially resolved before the LingoCafe app-scoped user with the same email. Session lookup now requires the active app ID before using the app-scoped email fallback.
- Final adversarial review found invalid-band fallback, unsupported-language roots, incomplete translatable metadata, canonical-language mislabeling, an unavailable-content existence oracle, and several translation/navigation accessibility gaps. All were corrected before completion.

## Deviations From Plan

- Conversation translation reused the existing cache, preference key, endpoint, sentence segmentation, and `ExpandableFab`, while exposing a conversation-specific translatable-text adapter instead of moving the entire book reader component in this task.

## Additional Requests

- Deliver a consumable development feature with the full database, populated corpus, and frontend running.
- Use sub-agents throughout refinement and lifecycle execution.
- Make the mobile multi-level chooser directly draggable from either the sheet or its backdrop: downward motion follows the pointer, short drags snap back, and committed drags or flicks dismiss.
- Remove the backdrop flicker observed after gesture dismissal by keeping the gesture fade as the sole overlay exit animation.

## Known Limitations

- The canonical corpus currently supports English, Italian, and Swedish; configured Spanish and German target profiles receive an explicit empty state.
- The signed-in acceptance account intentionally retains one starred/read conversation as persistent-state evidence.

## Verification

- Development corpus: 79 categories, 61 scenarios, 67 variants, 724 exact conversations, 122 actors, and 7,317 ordered rounds; 181 exact conversations exist at each CEFR level.
- Focused automated checks: 18/18 conversation schema/API/translation/account-erasure tests pass; sentence-segmentation and translation-language regressions also pass.
- Full `npm run qa` passes, including ESLint, TypeScript, and the Next.js production build with all conversation page/API routes emitted. `git diff --check` passes.
- Signed-in browser walkthrough at `https://lc42go.ngrok.app/` verified desktop and 390 px mobile navigation, profile-derived Intermediate filtering, nine Swedish roots, a plural-path category breadcrumb, explicit A2/B1 choices, exact-reader dialogue with 12 attributed turns, persisted read/star state, and full-dialogue playback with active highlighting. No console errors or warnings were observed.
- Post-walkthrough adversarial fixes were revalidated through focused tests, TypeScript, production build, and a live development-database recursive-root query.
- A 390x844 browser acceptance pass verified the mobile level chooser on an A2/B1 grouped conversation. After a committed drag, both the dialog and backdrop are absent at the end of the 180 ms gesture-owned exit, with no residual Radix overlay animation.
- Frame-sampled follow-up verification confirmed committed dismissal continues monotonically from the finger-controlled opacity to `0` before unmount; close-time drag-state reset and the former 22% terminal-opacity mismatch were removed.
- The gesture implementation now lives in the platform-owned `42go/components/SwipeableBottomSheet` library component. Conversation UI supplies only its title, content, controlled open state, focus restoration, and post-close navigation.
- Backdrop taps use the same forced-start-frame, 240 ms sheet-and-opacity exit as committed drags. The component synchronously commits the transition, waits two animation frames, and only then changes its targets so React cannot collapse dismissal into one abrupt paint.
- iOS `prefers-reduced-motion` no longer collapses dismissal to zero milliseconds. It uses a shorter 180 ms transition so the sheet still communicates that it closed while reducing motion relative to the standard 240 ms path.
- Localhost mobile frame sampling under the authenticated admin account verified backdrop-tap dismissal: at 10/50/100/180 ms the sheet translated approximately 0/87/264/300 px while backdrop opacity moved 1.00/0.89/0.41/0.02, then both unmounted. UI verification now uses `http://localhost:3000` for this session.
