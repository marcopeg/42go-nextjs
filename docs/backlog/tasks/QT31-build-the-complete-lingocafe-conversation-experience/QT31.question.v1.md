# Refinement Questions v1 — Build the complete LingoCafe conversation experience

Answers are supplied on the operator's behalf from three independent repository-grounded refinement passes and the explicit instruction to execute autonomously.

## Questions

### 1. Which values may the client choose?

Answer: The server derives target language and user identity from the session profile. The client may choose only `band=beginner|intermediate|advanced`; absent or invalid values resolve from profile (`a1`, `a2`, `b2`) with unknown/null defaulting to Intermediate. A URL override never updates profile.

### 2. What are the canonical routes?

Answer: Use `/conversations`, `/conversations/categories/[...categoryPath]`, and `/conversations/[conversationId]`. Preserve `band` and a validated same-origin conversation `returnTo`. The API mirrors discovery, catch-all category paths, exact detail, and idempotent read/star resources.

### 3. How is the plural-parent category graph validated?

Answer: Every category path segment must be visible and language-applicable, and every adjacent pair must be a direct stored parent-child edge. Roots have no canonical parent edge; hidden parents do not promote children. Category results consume materialized memberships only.

### 4. What content is runtime eligible?

Answer: Exact, variant, and scenario must each be `is_visible=true`; language scopes must include the profile target language; exact language must equal it; CEFR must belong to the selected band. Stars ignore band but still require the current target language and visible parent chain.

### 5. How are A2 and B1 handled in Intermediate?

Answer: Return and render both as explicit choices, deterministically ordered A2 before B1 and then title/ID. Never choose automatically. Missing localizations remain null; do not invent cross-language or cross-level fallback.

### 6. What are read/star mutation semantics?

Answer: Detail GET remains read-only. After valid non-empty rounds render, the client sends idempotent read PUT. PUT requires a currently eligible exact chain and preserves the original timestamp on repeat; DELETE permits stale state cleanup when the exact row still exists. No endpoint accepts a user ID.

### 7. How must translation change?

Answer: Extend the existing endpoint with discriminated `book-page`, `category`, and `conversation` contexts while keeping the current flat book payload compatible. Authorize profile/context/text before cache lookup. Derive actual source language and allowed text from the context: category is English, exact conversation fields/rounds use exact language, target remains profile own language. Actor labels and UI chrome are not translatable.

### 8. How must playback be reused?

Answer: Generalize the existing playback identity from hard-coded book/page to a content namespace/key without breaking book calls. Conversation speech units follow round then sentence order; actor labels are never spoken. Reuse the existing provider, controller, preferences, highlighting, controls, and player substitution.

### 9. How should desktop/mobile navigation behave?

Answer: Add a protected Conversations destination with a message icon. Mobile order is Books, Conversations, Account. Shared menu active matching becomes exact-or-descendant so nested category/detail routes keep Conversations active.

### 10. What are the empty/error and browser acceptance rules?

Answer: Unsupported configured languages such as Spanish/German return a valid empty discovery DTO. Invalid params are 400, incomplete profile 422, invisible/missing content 404, malformed exact data fails closed. Browser acceptance uses john/john through the development ngrok URL at desktop and 390px in light/dark, exercising category navigation, explicit A2/B1, translation, playback, read persistence, and star persistence.
