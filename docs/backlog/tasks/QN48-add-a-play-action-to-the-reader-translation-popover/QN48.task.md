# Add a Play Action to the Reader Translation Popover

## Elevator's Pitch

Show an obvious listening action inside the LingoCafe reader translation popover for both full-sentence and single-word translations. Sentence mode restarts or starts reader playback according to the current playback state. Word mode pronounces the translated word through the same speech capability.

## Business Gain

Let readers move directly from understanding a sentence or word to hearing it in context. The control makes sentence-level playback discoverable at the exact moment it is useful, without forcing the reader to find the global playback control or guess where playback will begin.

## Current State

The reader opens the same translation popover when a user taps either a complete sentence or an individual word. The tap already selects the containing sentence in the playback controller. When playback is active and the `Pause for translations` preference is enabled, opening the translation popover automatically pauses playback. The popover currently shows loading, error, or translated text, but no playback action.

## Desired State

Add a clearly visible, accessible listening action to the translation popover in both translation scopes. Treat the popover as a split surface:

- Keep translation content on the left.
- Put the listening action on the right, vertically centered.
- Run a vertical divider from the popover’s top border to its bottom border between the two regions, so the action reads like the second half of a split button.
- Stack a Play icon above the label.
- Use `Listen from here` for the sentence action and `Play word` for the single-word action.
- Show the action while translation is loading, successful, or failed when the existing full `playback.canPlay` capability is true.

For full-sentence translation, the action follows this state matrix:

1. If opening the translation auto-paused active playback, pressing the action closes the popover, abandons the paused utterance, and starts from the translated sentence.
2. If playback is closed or idle, pressing the action closes the popover, opens playback, and starts from the translated sentence.
3. If playback is completed or failed, pressing the action closes the popover and starts a new run from the translated sentence.
4. If playback was already manually paused before the translation opened, pressing the action closes the popover, abandons the old paused position, and starts from the translated sentence.
5. If playback is actively speaking because `Auto-pause on translation` is disabled, hide the action.

If the reader closes the sentence translation popover without pressing `Listen from here`, playback that translation auto-paused resumes from its paused position.

For single-word translation, `Play word` is a one-shot isolated pronunciation:

- Keep the single-word translation popover open.
- Speak only the selected word once, using the same matching voice, book language, and configured playback speed as sentence playback.
- Require the same full `playback.canPlay` capability as sentence playback.
- Do not open, close, seek, advance, or otherwise require the global playback bar.
- Do not change playback percentage, playback highlights, or guided scrolling.
- Allow the reader to press `Play word` again while the same popover remains open.
- When no continuous session exists, return to idle after the word finishes while leaving the popover open.
- If continuous playback is actively speaking with `Auto-pause on translation` disabled, hide `Play word`.
- If translation auto-pause is enabled, allow `Play word` while the translation interaction has paused continuous playback. Cancel the paused sentence utterance to pronounce the word, then keep continuous playback paused while the popover remains open.
- Close the word popover only through the existing translation dismissal interactions, including tapping the active translation target again, tapping outside, or pressing Escape.
- If translation had auto-paused a running session, closing the word popover cancels any active word utterance and restarts the previously active sentence from its beginning, then continues playback.
- If the session was already manually paused before translation opened, closing the word popover does not auto-resume it. Because its utterance was canceled for word pronunciation, the next manual Resume restarts that same active sentence from its beginning.
- If no continuous session existed, closing the word popover cancels any active word utterance and leaves playback idle.

Every sentence `audio.play` event includes `type: "sentence"`. A one-word pronunciation emits one `audio.play` event with `type: "word"`. Both retain the existing privacy-safe `language`, `book_id`, and `page_id` fields and never include source text, translated text, word ID, or sentence ID.

The sentence interaction matches the reader’s prior implicit flow—closing the translation popover and then using playback—while making that action explicit inside the popover. Word pronunciation deliberately keeps the translation visible so the reader can listen again or study the word before dismissing it.

## Definition of Success

From a sentence translation popover, a reader can press one obvious `Listen from here` action and start playback from that translated sentence regardless of the prior playback position. Closing the popover without using the action resumes playback that translation auto-paused. From a word translation popover, a reader can press `Play word` to pronounce only that word as an isolated one-shot action without opening or advancing the playback bar, while the popover stays available for replay. Dismissing the word popover restores only playback that translation had auto-paused. Speech never overlaps, unsupported listening actions remain absent, analytics distinguish sentence and word use, and existing translation states stay intact.

## Additional Context

YI11 introduced device TTS playback, sentence selection, translation-aware auto-pause/resume, and a replaceable playback provider boundary. QQ09 added the sentence-versus-word translation scope while retaining a containing `sentenceId` for word targets. The current integration passes sentence activation and translation-open state from `BookPageReader` into the shared playback controller, but the translation popover itself does not receive a playback action or playback state.

This task concerns playback orchestration and UI only. It should remain compatible with the current device TTS provider and the future external-audio provider described by NJ02.

Existing `audio.play` events identify language, book, and page but do not distinguish sentence playback from one-word pronunciation. This task adds the non-sensitive payload discriminator `type: "sentence" | "word"` to measure use of both entry points.

## Assumptions

- The listening action appears during translation loading, success, and error states when the accepted capability predicate passes.
- “Playback was not running” includes closed, idle, completed, and failed states.
- Sentence actions use the existing selected-sentence and playback-controller flow.
- `Listen from here` always replaces any auto-paused playback position and starts from the translated sentence.
- Dismissing a sentence popover without using `Listen from here` resumes playback that translation auto-paused.
- A manually paused session is replaced by playback from the translated sentence.
- Single-word mode speaks only the selected word and does not seek to a word offset inside the containing sentence.
- Word pronunciation uses the current playback speed and full `playback.canPlay` capability but remains independent from the playback-bar UI and continuous position model.
- Word pronunciation emits one privacy-safe `audio.play` event with `type: "word"`; sentence playback events emit `type: "sentence"`.
- `Play word` keeps the popover open; existing dismissal interactions own closure.
- A continuous session auto-paused by translation resumes only when the word popover closes, restarting its active sentence because the prior utterance was canceled.
- A session that was manually paused before translation opened never auto-resumes when the word popover closes.
- The operator will perform manual browser testing; new automated interaction tests are not required by this task.

## Constraints

- Reuse the existing `ReaderPlaybackController`; do not create a second audio or speech session.
- Start sentence playback from the translated sentence whenever `Listen from here` is pressed, including when translation auto-paused another active sentence.
- Cancel or replace old speech before any restart so utterances never overlap.
- Keep ordinary sentence-popover dismissal separate from `Listen from here`: dismissal resumes auto-paused playback, while the action starts from the translated sentence.
- Speak only the selected word for word translations; do not silently fall back to the containing sentence.
- Use `Listen from here` for sentence mode and `Play word` for word mode.
- Gate both sentence and word actions with the existing full `playback.canPlay` capability.
- Keep word pronunciation isolated from playback-bar visibility, percentage, highlighting, seeking, and guided scrolling.
- Keep the word popover open after pronunciation and support repeated `Play word` actions without overlapping utterances.
- Keep translation-auto-paused continuous playback paused until the word popover closes.
- On every word-popover dismissal path, cancel any active word utterance before restoring the prior continuous-session state.
- Resume only sessions that translation itself auto-paused; never auto-resume a previously manual pause.
- Preserve translation request validation, caching, loading/error states, sentence and word highlighting, and popover accessibility.
- Preserve playback language/voice availability rules, guided scrolling, playback controls, and `audio.play` event privacy semantics.
- Add only the non-sensitive `type: "sentence" | "word"` discriminator to `audio.play`; never add source text, translated text, word IDs, or sentence IDs.
- Hide the action while playback is actively speaking with translation auto-pause disabled.
- Hide the action when the accepted listening capability predicate fails.
- Support both desktop and mobile reader surfaces.
- Run `npm run qa` after implementation.

- Do use the selected word text for word-only pronunciation.
- Do keep one-word pronunciation independent from playback-bar presentation and position.

## Don'ts

- Don't speak the containing sentence when the user invokes the word-pronunciation action.
- Don't preserve the old auto-paused position when the reader explicitly presses `Listen from here`.
- Don't restart or seek playback when the sentence popover is merely dismissed; resume the auto-paused utterance.
- Don't open or advance the playback bar for an isolated word pronunciation.
- Don't close the word popover merely because `Play word` was pressed.
- Don't resume continuous playback while the word popover remains open.
- Don't auto-resume a session that was manually paused before translation opened.
- Don't add word or sentence content or identifiers to analytics.
- Don't create a separate popover-specific playback engine or duplicate the global playback controls.
- Don't broaden the task into external TTS generation, new audio assets, or a translation redesign.
