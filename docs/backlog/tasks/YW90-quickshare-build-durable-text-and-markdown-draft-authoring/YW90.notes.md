# Execution Notes — QuickShare: Build durable text and Markdown draft authoring
**Task**: ./YW90.task.md
**Plan**: ./YW90.plan.md

## Decisions

- Text and Markdown remain separate explicit resource types. The shared catalog controls which types the initial split-button presents and leaves later type registrations available without a UI rewrite.
- Draft source remains database state; compilers run only from the persisted current draft immediately before explicit publication.
- Only text and Markdown are registered in the authoritative creation catalog. QU22 and HZ42 must register their types only with real authoring/compiler support.
- `ever_published` is durable resource evidence. Delete requires a distinct server-validated `delete-published` confirmation even after the resource has been unpublished.
- Publish locks and reads the current persisted draft revision before compiling. Delete locks the resource row while it purges delivery and deletes the record, preventing lifecycle races.
- Markdown compilation is server-only and uses `unified` with `remark-parse`, `remark-rehype`, `rehype-sanitize`, and `rehype-stringify`; raw HTML is not enabled.

## Problems Encountered

- The first Markdown compiler used `react-dom/server`, which Next 16 correctly rejects in an app route. It was replaced with the server-side Markdown AST pipeline above.

## Deviations From Plan

- The account handle confirmation from XO00 used `window.confirm`. It was migrated to the shared Modal in this task because the same disruptive-action contract applies to the delivered editor lifecycle.

## Additional Requests

- Keep the delivered surface reachable through the default app for seeded `john/john` and `admin/admin` testing, while server scope remains the request-derived `app_id`.
