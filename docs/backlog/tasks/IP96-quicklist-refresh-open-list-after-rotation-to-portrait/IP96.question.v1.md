## Questions

### 1. Which devices should qualify for the orientation-triggered refresh?

The existing landscape QR overlay identifies a phone through orientation, coarse pointer/no hover, and constrained viewport dimensions. Should this task use that same practical phone boundary, or should every browser/device that transitions from landscape to portrait refresh an open QuickList?

Answer:

Only phone devices qualify, such as iPhone and Android smartphones. Exclude tablets and desktop browsers. Use the existing practical phone boundary from the landscape QR behavior, or an equivalent smartphone-specific check.

### 2. What should happen when rotation occurs during an active list mutation or refresh?

Should QuickList remember the portrait transition and run one conditional background check as soon as the active work settles, or may it discard that signal and wait for the next scheduled/manual refresh opportunity?

Answer:

Discard the orientation signal when a mutation or refresh is active. Do not remember it, defer it, or run an orientation-triggered check after the active work settles.
