# Execution Notes — QuickList: Refresh Open List After Rotation to Portrait
**Task**: ./IP96.task.md
**Plan**: ./IP96.plan.md

## Decisions

- Use native `window.matchMedia` with the repository's established smartphone-landscape boundary; do not add a hook library.
- Keep orientation refresh inside the QuickList list-detail polling hook.
- Use the existing conditional ETag request and cache reconciliation path.
- Discard a portrait-transition signal when hidden, in flight, manually refreshing, or mutating. Do not defer it.
- Keep scheduled polling and foreground listeners disabled when the account preference is Off, while leaving the smartphone orientation listener active.
- A qualifying portrait check resets the next scheduled interval after it finishes, matching the existing serialized polling behavior.

## Problems Encountered

- The connected browser supports viewport rotation but does not emulate a coarse touch pointer. Its 844 × 390 landscape viewport correctly failed the smartphone media query, so it could verify the desktop exclusion boundary but not a real-device rotation.
- The `john` test account had no QuickLists, and creating persistent test data would not overcome the browser's missing touch-pointer emulation.
- Browser console inspection found no application errors. It reported one unrelated existing Next Image `sizes` warning for `/app-icons/quicklist/ui.png`.

## Deviations From Plan

None.

## Additional Requests

- Limit the feature to iPhone and Android-class smartphones. Exclude tablets and desktop browsers.
- Discard the signal if other list work is active.

## Known Limitations

- `npm run test:quicklist-refresh` passes all 12 tests, including the smartphone boundary, landscape-to-portrait decision, busy discard, and hidden-page discard.
- `npm run qa` passes ESLint, production compilation, TypeScript, and static page generation.
- The public QuickList tunnel and credentials login were verified at an 844 × 390 viewport. Real iPhone/Android rotation remains a hands-on verification item because the connected browser cannot emulate `(pointer: coarse)`.
- The change adds no visual token, component, layout, or interaction pattern that belongs in the LingoCafe design-system skill.
