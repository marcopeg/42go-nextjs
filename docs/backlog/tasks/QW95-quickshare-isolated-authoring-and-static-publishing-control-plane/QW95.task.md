# QuickShare: Isolated authoring and static publishing control plane

## Elevator's Pitch

Deliver QuickShare as a new, isolated 42 Connect application where authenticated accounts author durable text, Markdown, advanced web pages, and guided template mini apps, then explicitly publish versioned static bundles to a dedicated origin.

## Business Gain

QuickShare gives technical and non-technical accounts one dependable publishing control plane without changing QuickNotes or placing public traffic on the application, database, or session boundary. Guided templates make common mini apps publishable in minutes while advanced authors retain full HTML/CSS/JavaScript control.

## Current State

QuickNotes has separate existing implementation scope and prior backlog work. QuickShare does not yet exist as an app configuration, data space, editor, publishing projection, static origin, automation API, or automation skill.

## Desired State

QuickShare runs at quickshare.42go.dev as a new app-scoped account/editor surface. It owns draft source and template configuration in its own database schema and publishes only explicit versions to s.42go.dev through a shared Docker-volume projection served by a dedicated Nginx container. Each publish may emit `index.html` plus content-hashed CSS, JavaScript, images, fonts, and other sidecar assets. The public origin never calls Next.js, PostgreSQL, server rendering, or account-session authority.

## Definition of Success

A QuickShare account completes app-unique normalized-handle onboarding, repeatedly saves durable drafts, explicitly publishes text, Markdown, advanced web-page source, or a guided template instance, and receives stable public URLs. The initial Linktree-style links template can be configured and published without code. Public traffic is served directly by Nginx from immutable versioned bundles while the editor's host-only cookies never reach s.42go.dev.

## Additional Context

Core delivery order: (1) isolated app, account onboarding, and schema; (2) durable resource drafts and text/Markdown editor; (3) atomic versioned-bundle publication and Nginx origin; (4) Monaco web-page studio and publish-time compiler; (5) extensible mini-app templates with an initial Linktree-style links page; (6) personal tokens, CRUD automation API, and maintained QuickShare skill. All version-one resources are permanent. Plain text is HTML-escaped into a minimal document and Markdown is rendered to final HTML at publish time. Advanced web pages use authored HTML/CSS/JavaScript or TypeScript; modern JavaScript/TypeScript transpilation and CSS processing occur at publish time. Output is a bundle containing `index.html`, a manifest, and any content-hashed sidecar assets rather than requiring one inlined document. Arbitrary package imports and general dependency bundling are explicitly outside v1. The stable URL contract uses a globally unique short code at `s.42go.dev/{code}/` and optional handle-scoped custom ID at `s.42go.dev/{handle}/{customId}/`, backed by folder `index.html` entries. The default code remains stable across updates. Templates are versioned, schema-driven authoring modes that use the same resource and publish pipeline; later personal landing, curriculum/CV, and other mini-app templates are additive catalog work. Future discussion only: metering, basic access statistics, access blocking, redirects, and URL-shortener functionality with metrics. Telegram Mini App compatibility is a published-page boundary requirement only; HAL and bot integrations are outside core delivery.

## Assumptions

- The existing authenticated account platform can scope a new application without sharing product data.
- A shared Docker volume is sufficient for the first static-origin projection and does not alter the stable public contract.

## Constraints

Leave QuickNotes and its implementation scope untouched. QuickShare is a separate AppConfig, schema, account-scoped data space, and public-origin deployment. Drafts are authoritative; release bundles and filesystem output are projections. Publish must create a complete versioned/content-hashed bundle and atomically move the stable URL to the new current release. Keep public object keys migration-ready for a later private-S3-plus-CloudFront origin without implementing AWS now. Do not add temporary lifecycles, expiry, cleanup, public rendering in QuickShare, shared QuickNotes resources, viewer credentials, or HAL launch flows. Account cookies must remain host-only to quickshare.42go.dev.

## Acceptance Criteria

- The six child tasks below are executed in their listed dependency order.
- QuickNotes remains unmodified by the QuickShare delivery.
- The editor, database drafts, token API, compiler, template registry, bundle projection, and isolated Nginx public origin satisfy each child task's focused acceptance criteria.
- Text, Markdown, advanced web-page, and initial guided-template resources all publish through one atomic versioned-bundle contract that supports sidecar assets.
- A full account-to-save-to-publish-to-public-URL proof shows public requests do not reach the Next.js app or database and do not receive editor cookies.
- The backlog index is regenerated deterministically and each QuickShare task appears once.

## Dos

- Execute child tasks in listed order and preserve their ownership boundaries.
- Treat a published version as immutable output from the authoritative draft.

## Don'ts

- Do not fold QuickShare into QuickNotes or route public pages through the editor application.
- Do not make future metering, statistics, access blocking, redirects, or URL shortening delivery work.
- Do not require assets to be inlined or create a separate publication system for templates.
