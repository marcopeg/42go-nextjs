# Plan — QuickShare: Isolated authoring and static publishing control plane

## Goal

Supervise the complete QuickShare delivery from foundation through maintained automation skill. When this epic is executed, the supervisor must carry every child through implementation, verification, backlog completion, and downstream handoff in this exact order: `XO00 → IF14 → YW90 → QU22 → HZ42 → KQ66 → ZA41 → VG23`. The run does not stop after delegating work or after one child succeeds.

## Milestones

### Milestone 1 — Establish the supervisory execution protocol

- [x] Step 1 — Run preflight and freeze the dependency graph
  - Achieve: Confirm all eight canonical tasks and accepted plans exist, the index/order is deterministic, the worktree baseline is understood, and required local services/configuration are discoverable.
  - Create: Epic execution notes/checklist in the canonical task when execution begins.
  - Modify: Nothing outside backlog execution metadata during preflight.
  - Delete: Nothing.
  - Touch points: `docs/backlog/order.json`, all child task/plan files, current Git diff, migrations, Docker, localhost app, static-origin configuration.
  - Validation: Record unrelated pre-existing changes, verify no child is duplicated or skipped, run baseline focused checks and `npm run qa`, and note any pre-existing failures before implementation.
  - Notes: Preserve user changes. Do not reseed automatically if local credentials fail.

- [x] Step 2 — Enforce one accountable child-agent loop
  - Achieve: For each child, launch a dedicated implementation sub-agent with its canonical task, accepted plan, predecessor handoff, repository rules, and explicit requirement to finish all milestones and maintain task notes.
  - Create: A per-child supervisor checklist recording agent assignment, progress checkpoints, diff review, tests, fixes, acceptance, and handoff.
  - Modify: Epic execution notes after every gate.
  - Delete: Nothing.
  - Touch points: Sub-agent status, follow-up instructions, shared workspace, backlog-execute and backlog-complete workflows.
  - Validation: The supervisor polls active work, reads progress and diffs, sends targeted repair follow-ups, and never treats delegation as completion.
  - Notes: Run implementation children sequentially because contracts depend on predecessors. Parallel agents may perform bounded read-only review or independent tests only when they cannot race file edits.

- [x] Step 3 — Apply the supervisor acceptance gate to every child
  - Achieve: Independently verify plan checkboxes, acceptance criteria, authorization/security boundaries, tests, default-app behavior, and clean downstream contracts before proceeding.
  - Create: Focused review notes and defect follow-up list for each child.
  - Modify: Child task notes and plan progress through the proper backlog skills.
  - Delete: Temporary test artifacts through safe product lifecycle operations.
  - Touch points: Agent diff, targeted tests, `git diff --check`, migration status, browser/API/static-origin checks, `npm run qa`.
  - Validation: A child advances to completed only after defects are repaired and the supervisor reruns proportionate verification; failure blocks the next dependency.
  - Notes: The supervisor owns final judgment. Sub-agent self-report is evidence, not the gate.
