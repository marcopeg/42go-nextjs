## Questions

### 1. When a published resource changes or removes its custom ID, the new route does not take effect until the next Publish. Recommended contract: expose `publishedUrl` for the old route that still works and `nextPublicUrl` for the pending route; after successful Publish, `nextPublicUrl` becomes `publishedUrl` and the old route disappears. An unpublished resource has `publishedUrl: null` and only `nextPublicUrl`. Do you approve this UI and API model?

Answer:

Approved with a display rule: content-only edits do not change the URL and show no duplicate URL treatment. `publishedUrl` and `nextPublicUrl` differ, and the UI shows both, only while a published resource has a pending switch between its random short code and a custom handle-scoped ID. After successful Publish, the pending route becomes `publishedUrl` and the old route disappears. An unpublished resource has `publishedUrl: null` and its configured candidate in `nextPublicUrl`.
