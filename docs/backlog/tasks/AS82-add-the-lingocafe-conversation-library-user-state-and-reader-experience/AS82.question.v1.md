# Refinement Questions v1 — Add the LingoCafe conversation database foundation

This autonomous refinement round was answered from repository evidence and three independent review passes, as authorized by the operator.

## Questions

### 1. Should source lifecycle status control runtime publication?

Answer: No. Preserve source status and add explicit `is_visible`. The current corpus has no accepted exact conversations, so accepted-only filtering would yield an empty product. Deprecated/retired records are never visible.

### 2. Should category membership be exclusive or language-multiplied?

Answer: Neither. Store one materialized many-to-many category/scenario relation with provenance. Store language applicability on categories/scenarios and filter it at runtime together with available exact conversations.

### 3. How should actor references be enforced for ordered rounds?

Answer: Keep scenario-scoped actors and carry redundant `scenario_id` on rounds. Composite foreign keys prove that both the exact conversation and referenced actor belong to the same scenario.

### 4. How should publication update child relationships without harming user state?

Answer: Upsert top-level content and replace only explicitly scoped parent edges, memberships, actors, or rounds inside one advisory-locked transaction. Omission is never deletion. Reads/stars are never part of content SQL.

### 5. Does the frontend remain in AS82?

Answer: No. AS82 is the hard schema/contract gate. YE24 builds and runs the importer. QT31 owns protected APIs and the complete desktop/mobile experience.
