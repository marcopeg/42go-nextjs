# Make LingoCafe Conversation Favorites Level-Agnostic

## Elevator's Pitch

Store a learner's favorite against one semantic conversation variant in one language, rather than against one exact CEFR realization, then provide a Starred page where that favorite can be reopened at any available CEFR level for its saved language.

## Business Gain

- Learners save the language-specific conversation they care about once, instead of creating separate favorites for A1, A2, B1, or B2 versions of the same variant.
- The Starred experience becomes a dependable personal library: favorites remain discoverable and can be reopened for practice at the learner's chosen available level.

## Current State

- Conversation star state is keyed by `(user_id, conversation_id)`, where `conversation_id` identifies one exact language-and-CEFR realization.
- As a result, starring a conversation at one level does not represent the same main conversation at another level, and starred discovery is tied to exact-level rows.

## Desired State

- Represent a favorite using the durable language-specific variant identity: the owning semantic variant plus its language, not an exact language-and-CEFR `conversations` row. Enforce one favorite per user, variant, and language.
- Migrate existing exact-conversation stars safely into the new identity without losing a learner's favorites; collapse duplicates that map to the same main conversation deterministically while retaining a meaningful starred timestamp.
- Update the existing protected `/conversations/starred` page so it lists each saved language-specific variant once with meaningful title, situation/context, available CEFR levels, and read/favorite state. The existing Starred entry on the initial Conversations page remains the entry point.
- Render each favorite and its eligible CEFR choices with the same interaction as a normal variant listing in a category: one available level opens directly; several levels provide the established level chooser and direct level badges. Changing level must not create, remove, or duplicate the favorite.
- Keep the selected realization's reader behavior (rounds, read/progress state, translation, playback, visibility checks, and authorization) intact.

## Definition of Success

A learner who favorites a conversation at one level sees one entry in Starred, can select any available CEFR level for that same variant in its saved language, and opens the matching reader without having to favorite it again. The favorite remains correct after reload and migration of existing stars.

## Additional Context

- The supplied mobile reference shows the existing Starred list destination: a compact list of saved conversations reachable from the initial Conversations page, with an A1 indicator. The final implementation should follow the LingoCafe design system rather than copying it literally.
- The entry point and list route already exist: the initial `/conversations` page renders a `Starred` row when stars exist, linking to `/conversations/starred`. This task must preserve that navigation rather than add another mobile tab or header action.
- The current data model defines a `conversation_variants` row as the semantic sub-scenario and `conversations` as exact language-and-CEFR realizations. The favorite must use the variant plus language as its durable identity; verify the precise schema/API contract during implementation planning.
- QT31 delivered the existing conversation library and exact-conversation star UX; this task changes only favorite identity and favorite discovery/opening semantics.

## Assumptions

- Favorites are user-scoped and remain independent of read and progress state, which may stay tied to exact realizations unless a separate decision changes them.
- Only visible, language-applicable, eligible exact realizations may be listed or opened from a favorite; unavailable levels are not fabricated.
- Favorites reuse the normal category variant-listing behavior: a single eligible level opens directly; several eligible levels open the established picker and expose the available level badges. Profile settings are not silently changed by this selection.
- Existing exact-level star records map to their owning variant and exact language. Duplicate migrated records for one user/variant/language merge into one favorite using the earliest `starred_at` timestamp.

## Constraints

- Derive user identity from the authenticated session; do not accept a user ID from the client.
- Preserve app scoping, feature policy, visibility, language applicability, and authorization checks on every favorites and reader request.
- Use a migration that is reversible where repository conventions allow and does not broadly delete user state or conversation content.
- Keep reads, progress, and favorite mutations idempotent; do not turn a level selection into a write unless it is an explicit product preference.
- Implement authenticated pages as client components under `AppLayout`, with browser-side same-origin requests.
- Use existing LingoCafe navigation, semantic tokens, accessible controls, responsive behavior, and the shared reader stack.

## Acceptance Criteria

- The persistence model stores exactly one favorite per user, durable variant identity, and language, with no CEFR column forming part of that identity.
- Existing exact-conversation stars migrate deterministically to the new model without data loss; multiple legacy stars for one user/variant/language result in one favorite.
- Star/unstar actions on any exact realization of the same variant and language operate on the same favorite and are idempotent.
- The existing protected Starred page lists the signed-in learner's favorites once each and preserves its clear empty state when none exist.
- Each favorite exposes only its saved language's currently eligible CEFR realizations and reuses the category variant-listing interaction: direct opening for one level, or the established chooser and direct badges for several levels, without creating another favorite.
- Opening a favorite at a chosen level routes to and renders the correct exact conversation; reader visibility, read/progress, translation, and playback behavior continue to work.
- Hidden, retired, malformed, unauthorized, or unavailable exact realizations are not leaked through the favorite list or level chooser, while a remaining valid favorite is still usable when other realizations are unavailable.
- Favorites, switching between available levels, and legacy migration are covered by targeted data/API/UI tests; `npm run qa` passes.
- The flow is manually verified on the LingoCafe tunnel at desktop and near-390 px mobile widths, including light and dark themes.

## Dos

- Do use the durable variant-plus-language conversation identity after verifying it against the data contract.
- Do make language and CEFR availability understandable before a learner opens a saved conversation.
- Do reuse the current reader route and shared reader capabilities once an exact realization is selected.
- Do reuse the established category variant-listing, desktop popover, and mobile level-sheet interaction for favorites.
- Do preserve the existing Starred row on the initial Conversations page and its `/conversations/starred` destination.
- Do preserve timestamp semantics and deduplicate legacy state predictably during migration.

## Don'ts

- Do not store a separate favorite merely because the learner opens the same variant in its saved language at another CEFR level.
- Do not expose invisible or language-inapplicable exact content to make a favorite appear complete.
- Do not couple a level choice to a profile update or erase existing read/progress state.
- Do not create a parallel conversation reader, translation, playback, or user-identity mechanism.
