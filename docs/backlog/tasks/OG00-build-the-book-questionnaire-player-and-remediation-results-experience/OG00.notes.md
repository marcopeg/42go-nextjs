# Execution Notes — Build the Book Questionnaire Player and Remediation Results Experience
**Task**: ./OG00.task.md
**Plan**: ./OG00.plan.md

## Decisions

- Use a dedicated protected book questionnaire page.
- Keep play forward-only with explicit answer submission and no correctness
  feedback until results.
- Preserve passive exits; abandon only after explicit confirmation.
- Keep single-select rendering behind a response-mode component boundary.

## Problems Encountered

- Next.js intercepted the first remediation link and remounted the questionnaire
  route without its stable round query, which started an unwanted active round.
  Remediation links now use deliberate full-page navigation to the exact reader
  page, while the result route keeps its completed round ID in the URL.
- The available in-app browser does not expose viewport emulation. Responsive
  behavior was therefore checked through narrow-screen-first layout contracts,
  overflow-safe geometry at the available viewport, and the production build;
  a physical 390px emulation was not available in this environment.

## Deviations From Plan

- None in product scope. The responsive evidence uses source-contract tests and
  browser geometry rather than a tool-controlled 390px viewport.

## Known Limitations

- Version one renders `single-select` questions only. Unsupported response
  modes fail closed at the normalization/rendering seam so another renderer can
  be added without changing round orchestration.
- Round size remains the service default of 10; the contracts already preserve
  requested and actual counts for later learner settings.

## Completion Evidence

- Book eligibility is derived from active questionnaire, question, revision,
  and learning-item rows. The published pilot exposed 618 questions; an
  ineligible Swedish A2 book exposed no practice action. No answer key is added
  to book metadata.
- Browser exercise with the local `john` account verified conditional entry,
  one-question play, explicit submission, absence of correctness feedback,
  refresh/resume at question 2 of 10, confirmed abandonment, completion,
  9/10 scoring, independent answer reveal, and exact navigation to
  `sec_01-ch_02` in *Sverige tillsammans*.
- `Practice again` created a distinct adaptive round and stable `?round=` URL.
  The temporary verification round was explicitly abandoned afterward.
- Native radio controls were operable with the keyboard; Space selected an
  answer and enabled Submit. Fieldset, progressbar, dialog, expanded-state, and
  live-region semantics are present. At 1280px, `scrollWidth` equaled
  `clientWidth` (1280), with no horizontal overflow. Mobile-first padding,
  stacked controls, responsive result grids, and bounded dialog width are
  covered by focused source-contract tests.
- Focused tests: 5 UI, 5 runtime, and 11 schema/account-erasure tests passed.
  `npx tsc --noEmit`, `npm run qa`, and `git diff --check` passed. QA retained
  one pre-existing warning in `src/app/(app)/layout.tsx` concerning an internal
  `window.location.href` assignment; there were no errors.
