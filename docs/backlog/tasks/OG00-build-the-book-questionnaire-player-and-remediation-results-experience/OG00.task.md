# Build the book questionnaire player and remediation results experience

## Elevator's Pitch

Add the learner-facing book questionnaire flow: entry, 10-question single-select round, resume behavior, scoring, wrong-answer review, answer reveal, and navigation to the explanatory page.

## Business Gain

The new data and scheduling capability becomes a clear mobile and desktop learning loop grounded in the book.

## Current State

Books expose reading and completion but no questionnaire entry point or practice UI.

## Desired State

Eligible book pages expose one questionnaire action leading to the dedicated protected `/books/{bookId}/questionnaire` page. The player presents one single-select question at a time with native radio semantics, requires explicit submission, saves once, and advances automatically to the next unanswered item. Play is forward-only and does not reveal correctness before results. Refresh or ordinary navigation preserves and resumes the active round; an explicit `End round` action requires confirmation before abandonment. Results show score and focus on wrong items, display the learner's answer, reveal the correct answer only on request, open the linked book page, and offer `Practice again` for the next adaptive round. Rendering boundaries remain extensible for future response modes and round-size settings.

## Definition of Success

A learner can complete and recover a round comfortably on mobile and desktop, understand mistakes, and return to the exact explanatory book page.

## Additional Context

Depends on the adaptive service in [HK85](../HK85-implement-adaptive-questionnaire-rounds-with-fsrs/HK85.task.md). It does not change scheduling or content publication.

## Assumptions

The reader's existing book routes and responsive surface conventions are reused. Eligibility is derived from active published questionnaire content, not from a client-side allowlist.

## Constraints

Do not expose answer keys in initial client payloads or hide accessibility state behind visual-only controls.

## Acceptance Criteria

- [x] Questionnaire entry appears only for eligible books.
- [x] Player handles 10 single-select questions with progress and resume.
- [x] Loading, error, retry, abandoned, and completed states are clear.
- [x] Results accurately show score and wrong selected answers.
- [x] Correct answers require explicit reveal.
- [x] Explanation action opens the exact linked reader page.
- [x] Keyboard, screen-reader, mobile, and desktop verification passes.
- [x] Component boundary can add response modes and size settings later.
- [x] Passive exits preserve the round; confirmed explicit exit abandons it.

## Dos

Keep remediation prominent and the reading link contextual.

## Don'ts

Do not reimplement grading or FSRS logic in React.

## Open Questions

No blocking questions remain. The questionnaire uses a dedicated full-page route, forward-only explicit-submit play, passive resume, confirmed explicit abandonment, and post-results adaptive replay.
