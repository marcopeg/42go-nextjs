# Plan — Refine LingoCafe Reader Translation Popover Actions and Styling

## Goal

Give the LingoCafe translation popover a primary-tinted, touch-friendly layout that cleanly separates isolated sentence/word pronunciation from continuous audiobook playback.

## Milestones

### Milestone 1 — Separate isolated pronunciation from audiobook playback

- [x] Step 1 — Extend the translation playback controller contract

  - Delete: n/a
  - Touch points: speech-provider generation, translation auto-pause state, manual-pause recovery, continuous playback startup, privacy-safe `audio.play` event type.
  - Validation: TypeScript/build validation through `npm run qa`; static review against the refined playback state matrix.
  - Notes: Reuse one isolated-pronunciation implementation for sentence and word text. Do not create another speech engine.

- [x] Step 4 — Add the compact bottom action line
  - Achieve: Place the diagnostic cache marker on the left and two horizontally aligned controls on the right: `Play sentence`/`Play word` and `Start audiobook from here`.
  - Create: n/a
  - Modify: `src/app/(app)/(lingocafe)/books/_components/BookPageReader.tsx`
  - Delete: n/a
  - Touch points: success state, speech capability gating, compact 28 px neutral link controls, active pronunciation state, press feedback, focus rings, desktop 360 px width, mobile edge-to-edge layout.
  - Validation: Inspect sentence and word modes at approximately 390 px and desktop widths.
  - Notes: One-shot controls keep the popover open. The audiobook control closes it. After operator testing, both controls use a route-local 28 px neutral link action with trailing icons, 16 px inter-action spacing, a baseline shared with the cache-source marker, and a 2 px bottom inset. One-shot pronunciation uses a persistent neutral inverse fill while speech is active; audiobook startup holds the same fill for 600 ms before playback begins and the popover dismisses.
