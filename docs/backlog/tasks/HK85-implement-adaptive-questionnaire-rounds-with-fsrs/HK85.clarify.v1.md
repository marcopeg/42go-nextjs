# Clarify Round v1 — Implement adaptive questionnaire rounds with FSRS

## Questions

### 1. How many unfinished rounds may a learner have for the same questionnaire and mode?

### 2. Should the last answer complete and score the round automatically, or should completion require a separate action?

### 3. How should FSRS interval fuzzing remain both beneficial and testable?

## Answers

### 1.

Accepted. Allow at most one `in_progress` round per learner,
questionnaire, and mode. A start request resumes that round. The database owns
the uniqueness guarantee so concurrent starts converge on one round, while a
future mode may maintain its own active round.

### 2.

Accepted. Each answer is persisted, graded, and scheduled
atomically; the final unanswered item also completes and scores the round in
that transaction. Keep an idempotent finalize operation as a recovery and
explicit-client seam: it succeeds only when every pinned item has an answer.

### 3.

Accepted. Enable FSRS fuzzing, but derive a stable seed from the
learner, questionnaire, learning item, and review ordinal. This preserves the
small interval dispersion intended by FSRS while making retries and tests
reproducible. Store the exact parameter set and scheduler version with every
review.

## Resolution Summary

- One active round is allowed per learner, questionnaire, and mode; start
  requests resume it and a database constraint resolves concurrent starts.
- The final answer completes and scores the round atomically; finalize remains
  an idempotent recovery seam for fully answered rounds.
- FSRS interval fuzzing is enabled with a stable per-review seed so retries and
  tests reproduce the same schedule.
