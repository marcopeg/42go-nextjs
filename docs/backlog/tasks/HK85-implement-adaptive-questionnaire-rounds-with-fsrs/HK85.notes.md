# Execution Notes — Implement Adaptive Questionnaire Rounds with FSRS
**Task**: ./HK85.task.md
**Plan**: ./HK85.plan.md

## Decisions

- Allow one active round per learner, questionnaire, and mode; start resumes it.
- The final answer completes and scores the round atomically; finalize remains
  an idempotent recovery seam.
- Enable FSRS interval fuzzing with a stable per-review seed.
- Keep scheduler state at learning-item granularity.
- Pin `ts-fsrs@5.4.2`, whose runtime identifies itself as using FSRS-6.0.
- Use selection policy `fsrs-due-unseen-retrievability` version `1` and keep
  `standard` as an open stored mode even though it is the only public v1 mode.
- Expose correct-answer, rationale, and source-page remediation only after that
  item has an immutable answer row.

## Problems Encountered

- The first live answer took long enough for the verification client to stop
  waiting during a development hot compile. A database audit proved the
  transaction committed exactly once; subsequent endpoint reads and writes
  returned normally. The idempotent retry returned the stored result and did
  not append another review.

## Deviations From Plan

- Added `learning_steps` to current memory in the same additive migration as
  the active-round index. `ts-fsrs` short-term learning uses this card field;
  persisting it avoids degrading the selected FSRS-6 strategy.

## Additional Requests

- None.

## Known Limitations

- Version one exposes fixed 10-question, `standard`, single-select rounds. The
  database and service boundaries keep size and mode evolvable, but no learner
  settings or alternative response modes are exposed yet.
- A pre-existing lint warning remains in `src/app/(app)/layout.tsx`; it is
  unrelated to HK85 and does not fail QA.
