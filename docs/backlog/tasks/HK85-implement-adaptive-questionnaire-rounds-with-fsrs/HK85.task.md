# Implement adaptive questionnaire rounds with FSRS

## Elevator's Pitch

Build protected reader operations that create, resume, answer, score, and finalize 10-question book questionnaire rounds using versioned FSRS-6 scheduling.

## Business Gain

Learners receive efficient individualized reinforcement: due weak material returns sooner, retained material is spaced out, and unseen material expands coverage.

## Current State

No questionnaire API, scheduler, grading service, or answer persistence exists.

## Desired State

Use FSRS-6 at 0.90 desired retention behind an adapter. Each learner/learning item has scheduler state. Incorrect maps to `Again`, correct to `Good`. A round pins 10 distinct questions: due reviews ranked by urgency first, then unseen, then lowest predicted retrievability as fallback. Allow one active round per learner, questionnaire, and mode; a start request resumes it and database uniqueness resolves concurrent starts. Persist each answer immediately and idempotently, grade and schedule server-side in one transaction, and let the final answer complete and score the round atomically. Keep finalize as an idempotent recovery seam for fully answered rounds. Enable FSRS interval fuzzing with a stable per-review seed, and retain scheduler and selection-policy provenance.

## Definition of Success

Repeated rounds over deterministic histories produce explainable selection and correct schedules/scores under retry, refresh, concurrency, and withdrawal cases. The protected service contract leaves round size and mode open for later settings and interaction types.

## Additional Context

Depends on [TG18](../TG18-add-the-lingocafe-questionnaire-content-and-learner-state-schema/TG18.task.md) and the published pilot fixture supplied through [app PM03](../../../../../app/docs/backlog/tasks/PM03-publish-book-target-questionnaires-through-the-backoffice-reader-export/PM03.task.md). UI is separate.

## Assumptions

Version one uses fixed 10-question rounds and single-select answers; internal contracts remain open to other sizes and response modes.

## Constraints

Never trust client correctness or scheduling data. Do not repeat a question within one round or rewrite completed answers silently.

## Acceptance Criteria

- [x] Protected operations cover start/resume, answer, abandon, finalize, and results with explicit response contracts.
- [x] FSRS-6 adapter stores version, parameters, desired retention, rating, and card state.
- [x] Selection follows due, unseen, then lowest-retrievability order with no duplicates.
- [x] Correct/incorrect grading updates learning-item FSRS atomically and idempotently; the last answer completes and scores the round.
- [x] At most one in-progress round exists per learner, questionnaire, and mode, including under concurrent starts.
- [x] Enabled FSRS fuzz uses a stable per-review seed so retries and tests reproduce the same schedule.
- [x] Fixed 10 is configurable internally for later settings.
- [x] Retired questions never enter new rounds but historical rounds remain readable.
- [x] Deterministic, concurrency, authorization, and edge-case tests pass.

## Dos

Store raw learner choices separately from derived correctness and scheduler outcomes.

## Don'ts

Do not implement selection in the browser or use a fixed percentage bucket algorithm.

## Open Questions

No blocking questions remain. Answer insertion, server grading, learning-item review, memory-state update, and possible round completion share one transaction. One active round is permitted per learner, questionnaire, and mode. Start resumes it; the final answer completes it; finalize is idempotent recovery for a fully answered round. FSRS fuzzing uses a stable per-review seed.
