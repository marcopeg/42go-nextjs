# Plan — QuickShare: Publish atomic artifacts to an isolated Nginx static origin

## Goal

Create a compiler-agnostic, atomic static publication projection and dedicated Nginx origin. It accepts only complete validated bundles, keeps the database authoritative, and provides publish, unpublish, delete-purge, identifier-switch, and handle-folder operations without compiling resource types.

## Milestones

### Milestone 1 — Freeze the bundle and object-key contract

- [ ] Step 1 — Define and validate completed release bundles
  - Achieve: Accept `index.html`, a versioned manifest, and zero or more content-hashed sidecars through one portable contract.
  - Create: Server-only bundle types, manifest schema, reference/path/MIME/hash validators, fixture-bundle builders, and documented stable-versus-immutable key layout.
  - Modify: XO00 release/asset persistence adapters only where contract alignment requires it.
  - Delete: Nothing.
  - Touch points: Reserved namespace rules, relative asset references, object-storage portability.
  - Validation: Fixtures cover valid multi-file releases plus missing files, hash mismatch, traversal, namespace collision, duplicate paths, invalid MIME, and unreferenced/invalid references.
  - Notes: No text, Markdown, web-page, or template compiler belongs here.

### Milestone 2 — Build atomic projection and lifecycle operations

- [ ] Step 2 — Stage and activate immutable releases
  - Achieve: Write a complete release into staging, verify it, persist projection metadata, and atomically advance one stable route only after success.
  - Create: Publication configuration, filesystem adapter, staging/activation service, locking/idempotency strategy, and recovery cleanup for failed staging.
  - Modify: QuickShare publication-domain integration and environment examples.
  - Delete: Nothing.
  - Touch points: Configurable shared output root, same-filesystem rename/pointer semantics, PostgreSQL transaction coordination.
  - Validation: Fault-injection tests at every stage prove the previous route/release survives; concurrent publishes serialize safely; repeat requests are deterministic.
  - Notes: Retain immutable releases during ordinary republishes.

- [ ] Step 3 — Implement route switches, purge, and handle moves
  - Achieve: Create the candidate route before retiring the old route, purge complete resource output for Unpublish/Delete, and atomically rename handle-scoped entries without touching short-code routes.
  - Create: Stable-route activation, complete resource purge, and handle-folder rename services with explicit result/error contracts.
  - Modify: XO00 lifecycle coordination to promote state only after successful projection work.
  - Delete: Nothing.
  - Touch points: `publishedUrl`/`nextPublicUrl`, one- and two-segment routes, release asset ownership.
  - Validation: Tests cover short→custom, custom→new short, content-only republish, purge failure, delete ordering, handle collision, rollback, no redirects, and unaffected random routes.
  - Notes: A failed projection leaves database lifecycle state truthful.

### Milestone 3 — Serve only static output with Nginx

- [ ] Step 4 — Add the isolated public-origin container
  - Achieve: Serve `s.42go.dev` from a dedicated Nginx image/container and shared volume, with no fallback to Next.js or database-backed handling.
  - Create: Nginx image/config, compose service, health check, shared named-volume wiring, and environment documentation.
  - Modify: Development/production compose and build configuration as required.
  - Delete: Nothing.
  - Touch points: Docker Compose, publication output mount, hostname routing, MIME/cache/security headers.
  - Validation: Container tests prove stable HTML revalidation, immutable hashed-asset caching, correct MIME, disabled listing, traversal rejection, security headers, service-worker scope, and 404 without proxy fallback.
  - Notes: Editor cookies must be host-only and absent from public-origin requests.

### Milestone 4 — Prove the generic publisher independently

- [ ] Step 5 — Run fixture-bundle end-to-end acceptance
  - Achieve: Publish and update a fixture bundle, exercise identifier switches and purge, and fetch the result from Nginx without an authoring compiler.
  - Create: Publisher integration tests and test scripts/fixtures.
  - Modify: Canonical task notes with the final bundle and delivery contracts.
  - Delete: Temporary output generated outside controlled test directories.
  - Touch points: Local Docker volume, Nginx HTTP assertions, database lifecycle state, `npm run qa`.
  - Validation: Run focused tests, compose integration checks, `npm run qa`, and prove no Next.js/PostgreSQL/session dependency on public requests.
  - Notes: Hand the exact bundle API and failure semantics to YW90, QU22, and HZ42.
