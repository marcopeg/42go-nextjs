# Rename Public Themes to App Themes

## Historical Summary

`SA84` replaced unconditional per-app `/themes/<app-id>.css` links with a convention-first app-theme asset system. The change prevents missing stylesheet requests while keeping CSS token overrides separate from the `next-themes` light/dark/system preference mechanism.

Implementation commit `a90cb479e1a7646dc5f4179a2a303c9eac85e0f8` (`refactor: app-themes and app-icons`) delivered the folder migration, build-time registry, resolver, runtime injection, documentation, and removal of duplicate `InjectAppName.tsx`.

## Durable Outcome and Decisions

- Theme assets moved as follows:
  - `public/themes/app1.css` → `public/app-themes/app1/style.css`
  - `public/themes/app2.css` → `public/app-themes/app2/style.css`
  - `public/themes/calendar.css` → `public/app-themes/calendar/style.css`
  - `public/themes/quicklist.css` → `public/app-themes/quicklist/style.css`
  - `public/themes/lingocafe.css` → `public/app-themes/lingocafe/style.css`
- `public/app-themes/_default/style.css` is mandatory and always linked first. A registered `public/app-themes/<app-id>/style.css` is linked second so app token overrides win.
- Missing app-specific theme files are normal. `resolveAppThemeStylesheet(appId)` returns `defaultHref` for every app and returns `appHref` only when `APP_THEME_STYLESHEET_REGISTRY` contains that app ID. Rendering does not inspect the filesystem.
- `scripts/generate-app-themes-registry.mjs` scans app-theme folders containing `style.css`, writes `src/42go/app-themes/app-themes.registry.ts`, and fails when `_default/style.css` is absent. It runs before both normal and Docker production builds after the app-icon registry generator.
- The folder-per-app layout intentionally permits sibling theme assets such as fonts.
- `InjectAppID` became the single stylesheet injection owner; unused duplicate `InjectAppName.tsx` was deleted.
- No `/themes` route, rewrite, symlink, alias, or other compatibility layer was retained.
- The migration did not change AppConfig `theme.default` or light/dark/system preference semantics. App-theme stylesheets only override CSS tokens.
- Later commit `d54a10b52b0f92d54c7bd60ab2a6e9a604045f97` removed the unrelated `window.__APP_ID__` script from `InjectAppID`; the resolver-driven stylesheet behavior remains.

## Validation and Limitations

- `npm run qa` passed after registry generation, linting, and the production build.
- `rg "public/themes|/themes/" src contents docs/articles docs/memory-bank` found no live legacy references after implementation.
- Runtime checks covered the default fallback, QuickList app styling, and an app with no registered theme. Follow-up checks confirmed `public/app-themes/_default/style.css` and `public/app-themes/quicklist/style.css` were served as `text/css`.
- The repository's non-standalone `next start` path returned empty page bodies during the historical check, so the final evidence relied on the production build, resolver inspection, and static stylesheet delivery. This was a verification-environment limitation, not a known app-theme defect.
