# Plan — Let readers mark a book as read

## Goal

Add an explicit, reversible, book-level completion state that stays independent from reading progress, is reflected consistently across the bookshelf, book details, and final reader page, and emits canonical mark-read/unread events.

## Milestones

### Milestone 1 — Add Canonical Book Completion Storage

- [x] Step 1 — Create the dedicated completion migration
  - Achieve: Store one completion timestamp per authenticated user and book independently from `books_progress`.
  - Create: A new ordered Knex migration under `knex/migrations/`.
  - Modify: Nothing else in this step.
  - Delete: The obsolete `lingocafe.books_progress.completed_at` column after migration.
  - Touch points: New `lingocafe` completion table with user/book foreign keys, unique user/book identity, completion timestamp, and descending user/timestamp index; backfill existing non-null completion timestamps before dropping the legacy column.
  - Validation: Inspect generated schema operations; run the focused completion test and migration/QA validation.
  - Notes: Use cascading foreign keys so deleted users and books cannot leave completion rows behind.

- [x] Step 2 — Update the documented reader data contract
  - Achieve: Keep repository documentation aligned with the accumulated migration history.
  - Create: Nothing expected.
  - Modify: `docs/lingocafe/BOOKS_DATA_MODEL.md`.
  - Delete: Legacy documentation that describes `books_progress.completed_at` as reading progress state.
  - Touch points: Table ownership summary, progress columns, dedicated completion table, constraints, cleanup, and consumer expectations.
  - Validation: Documentation agrees with the final migration schema and runtime names.
  - Notes: The content export does not own user completion rows.
