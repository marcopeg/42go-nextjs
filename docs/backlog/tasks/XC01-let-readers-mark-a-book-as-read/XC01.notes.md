# Execution Notes — Let readers mark a book as read
**Task**: ./XC01.task.md
**Plan**: ./XC01.plan.md

## Decisions

- The operator explicitly requested `plan and execute`, so the newly created plan was accepted and execution started in the same turn.
- Completion is modeled as book-level state in a dedicated `lingocafe` table; reading position remains in `lingocafe.books_progress`.
- Named the dedicated table `lingocafe.books_completed`, keyed by `(user_id, book_id)` with `completed_at` as its ordering timestamp.
- The migration backfills legacy non-null completion timestamps before dropping `books_progress.completed_at`; rollback restores timestamps only for books that still have progress rows.
- Completion mutations are idempotent. Events are written only when the stored state actually changes, inside the same database transaction.
- Bookshelf cards use the existing Radix/shadcn dropdown primitive. The trigger is a sibling of the cover link, avoiding nested interactive controls and accidental navigation.
- Book details keep the green reading CTA primary and present completion as an outlined secondary action.
- The reader shows the completion CTA only when the API reports no next page and no existing completion timestamp.
