# Let readers mark a book as read

## Elevator's Pitch

Let an authenticated reader explicitly mark a LingoCafe book as read from the bookshelf, book-details page, or end of the reading journey, and let them explicitly reverse that choice later.

## Business Gain

Readers can close the loop on a finished book, keep their shelf state meaningful, and distinguish completed books from books that are merely in progress. This also creates a reliable completion signal for future reading history, recommendations, and engagement features.

## Current State

LingoCafe persists one `lingocafe.books_progress` row per user and book. The table includes a nullable `completed_at` timestamp, but `page_id` is mandatory and tied to a real book page, so that row cannot truthfully represent an externally completed book with no reading progress. The current reader, book-details page, and bookshelf do not expose a confirmed user action for marking a book as read. Existing bookshelf behavior derives `Currently Reading` from `readingAction.kind === "resume"`.

## Desired State

An authenticated reader can deliberately mark a book as read from all three agreed surfaces:

- a three-dot contextual menu on the book cover in `/books`
- a dedicated action on `/books/[bookId]`
- a completion action at the end of the actual last page in `/books/[bookId]/[pageId]`

Readers can explicitly mark a completed book as unread from the bookshelf three-dot menu or book-details page. Completion is stored in a dedicated book-level table in the `lingocafe` schema, independent from mutable reading-position state in `books_progress`. The migration copies any existing non-null `books_progress.completed_at` values into the dedicated table and then drops the redundant column. Marking a book read creates its completion record; marking it unread deletes that record. Neither operation changes saved `page_id` or `progress_bps`. Reading a completed book again does not delete its completion record.

Completed books appear in a dedicated `Completed` section at the bottom of the bookshelf, ordered by most recently marked read first, and no longer appear under `Currently Reading` or the general catalog. Section placement is sufficient for the first version; completed covers do not need an additional ribbon, checkmark, muted treatment, or other status decoration. Clicking a completed book cover opens its detail page.

On `/books/[bookId]`, a completed book retains the normal reading CTA: `Continue reading` when saved progress exists, otherwise `Read now`. The page also exposes `Mark as unread`.

Marking a book read emits `book.mark.read`; marking it unread emits `book.mark.unread`. On the final reader page, the completion CTA is omitted when the book is already completed. After either mutation, all affected surfaces consistently represent the canonical state, provide clear feedback, and avoid stale actions or navigation state.

## Definition of Success

A reader can mark a book as read from the bookshelf, details page, or final reader page without fabricating reading progress; can explicitly mark it unread from the bookshelf or details page; and sees a consistent completed state after reload. Completed books live in the bottom `Completed` section with the latest completion first, open their details page when selected, retain the appropriate reading CTA, and remain completed when read again. Removing completion returns a book to `Currently Reading` when progress exists or to the general catalog when it does not.

## Assumptions

- A dedicated `lingocafe` table is the canonical completion signal.
- The dedicated table records at least the user, book, and completion timestamp with one active completion record per user/book.
- Completion is scoped to the authenticated user and selected book.
- Marking a book as read is an explicit user action; merely opening or scrolling the last page does not automatically complete it.
- A completed book should no longer qualify for the existing `Currently Reading` section.
- A completed book should not appear in both `Completed` and another shelf section.
- Reading progress and completion are independent records.
- Marking a book unread is explicit and must not happen merely because the reader is opened or scrolled.

## Constraints

- Validate the book and authenticated user on the server; never accept an arbitrary user ID from the client.
- Keep the completion state consistent across `/books`, `/books/[bookId]`, and `/books/[bookId]/[pageId]`.
- Preserve existing start, resume, progress-saving, and navigation behavior for books that are not completed.
- Do not force the last page or `progress_bps = 10000` when marking a book as read.
- Do not create, update, or delete completion records from ordinary page-open or page-scroll progress writes.
- If the bookshelf uses a three-dot trigger, it must be keyboard accessible and must not hijack the cover's existing navigation click.
- Keep the `Completed` section at the bottom; broader future bookshelf organization is outside this task.
- Order `Completed` by most recently marked read first using the canonical completion timestamp.
- Do not add a completed-state cover ribbon, checkmark, muted styling, or other decoration in this version.
- Do not broaden this task into a general bookshelf redesign or reading-history feature.
- Run `npm run qa` after implementation.

## Dos

- Reuse the existing authenticated LingoCafe book and progress API patterns.
- Return canonical completion state from the API instead of deriving it independently on each client surface.
- Make the action label and resulting state understandable to assistive technology.
- Keep completion persistence separate from page and scroll progress.
- Treat completion as explicit bookshelf organization, not inferred reading progress.

## Don'ts

- Do not infer completion solely from reaching a scroll threshold.
- Do not trust client-provided ownership or user identity.
- Do not leave completed books classified as actively reading.
- Do not delete completion when a completed book is opened or scrolled.
- Do not force completion progress to the last page or 100%.
- Do not add special completed-cover decoration in this version.
- Do not implement unrelated ratings, reviews, achievements, or recommendation logic in this task.
