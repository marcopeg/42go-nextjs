# Plan — QuickShare: Establish personal API token lifecycle and authentication boundary

## Goal

Deliver one secure, immediately revocable bearer token per app-scoped QuickShare account and a reusable server-only authentication context for ZA41, without adding resource automation routes.

## Milestones

### Milestone 1 — Persist secure app-scoped credentials

- [ ] Step 1 — Add token storage and cryptographic primitives
  - Achieve: Generate high-entropy recognizable tokens, store only deterministic hashes and approved metadata, and enforce one active credential per app-scoped user.
  - Create: Additive QuickShare token migration plus server-only generation, parsing, hashing, prefix, and constant-time comparison modules.
  - Modify: Extract genuinely generic QuickList primitives only if QuickList behavior remains unchanged.
  - Delete: Nothing.
  - Touch points: `node:crypto`, `quickshare.api_tokens`, `auth.users`, unique app/user and hash constraints, lifecycle timestamps.
  - Validation: Migration constraints plus format, entropy, malformed-header, hash-only persistence, and safe-comparison tests.
  - Notes: Raw tokens, hashes, and Authorization values never enter logs or ordinary errors.

### Milestone 2 — Centralize lifecycle and bearer identity

- [ ] Step 2 — Implement create, rotate, revoke, status, and authenticate services
  - Achieve: Return raw material exactly once, immediately invalidate prior credentials, and resolve a verified `{ appId, userId }` principal.
  - Create: QuickShare token store and reusable bearer-authentication context/response helpers.
  - Modify: Nothing outside shared security primitives if extraction is justified.
  - Delete: Nothing.
  - Touch points: `getDB()`, `getAppID()`, atomic upsert, app-scoped user join, `last_used_at`, no-store responses.
  - Validation: Missing, malformed, unknown, rotated, revoked, and foreign-app tokens fail closed; callers cannot choose identity.
  - Notes: This is the stable handoff to ZA41 and knows nothing about resource CRUD.

### Milestone 3 — Add session-authenticated account controls

- [ ] Step 3 — Expose browser token lifecycle routes
  - Achieve: Let a signed-in user inspect safe status, create, rotate, and disable a token using NextAuth session authority only.
  - Create: Session-protected QuickShare API-access route handlers and schemas.
  - Modify: QuickShare API feature wiring.
  - Delete: Nothing.
  - Touch points: POST/create, PUT/rotate, DELETE/revoke, create conflict, safe status metadata.
  - Validation: Session and feature gates, one-time disclosure, rotate-without-token, no-store headers, and response redaction tests.
  - Notes: These browser routes never accept bearer authentication.

- [ ] Step 4 — Add profile UI with deliberate one-time disclosure
  - Achieve: Provide Create, Rotate, and confirmed Disable, clearly warning that the secret cannot be recovered.
  - Create: QuickShare API-access profile component and shared-modal disclosure/confirmation UI.
  - Modify: QuickShare and `src/config/default/config.ts` profile items/features.
  - Delete: Nothing.
  - Touch points: Clipboard behavior, semantic destructive buttons, mobile layout, loading/error states.
  - Validation: Local browser checks using both `john/john` and `admin/admin`; tokens remain separate `app_id=default` rows and account-isolated.
  - Notes: Do not place secrets in screenshots or tracked fixtures.

### Milestone 4 — Complete security and handoff gate

- [ ] Step 5 — Prove secrecy, revocation, and ZA41 readiness
  - Achieve: Leave a fully tested authentication boundary that later routes can consume without weakening it.
  - Create: Focused QuickShare API-access tests and package script.
  - Modify: Security/implementation notes in the canonical task.
  - Delete: Temporary tokens through the revoke path.
  - Touch points: Logs, errors, analytics, browser payloads, source control, default-app test identity.
  - Validation: Focused tests, tracked-secret scan, local seeded smoke, and `npm run qa` pass.
  - Notes: ZA41 starts only after old tokens fail immediately following rotation/revocation.
