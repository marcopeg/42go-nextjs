# Execution Notes — QuickShare: Establish personal API token lifecycle and authentication boundary
**Task**: ./KQ66.task.md
**Plan**: ./KQ66.plan.md

## Decisions

- Tokens use the `qs_` prefix plus 48 unbiased Base64URL characters (288 bits of entropy) and SHA-256 hash-only storage.
- One active token is bound to an app-scoped QuickShare account and app-scoped auth user through composite database foreign keys.
- Browser lifecycle endpoints require a same-app NextAuth session plus a current account/user database lookup. Bearer authentication ignores browser sessions completely.

## Problems Encountered

- Native Node TypeScript execution cannot resolve this repository's extensionless server imports. The focused database lifecycle test therefore uses the `tsx` loader with the `react-server` condition, and destroys its Knex connection after the test run.

## Deviations From Plan

- The token table also stores `account_id`, in addition to the planned app/user association, so bearer callers receive a database-backed account principal without a second ownership lookup.
