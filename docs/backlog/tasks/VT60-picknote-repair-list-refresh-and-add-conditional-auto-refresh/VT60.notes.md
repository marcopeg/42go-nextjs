# Execution Notes — PickNote: Repair List Refresh and Add Conditional Auto-Refresh
**Task**: ./VT60.task.md
**Plan**: ./VT60.plan.md

## Decisions

- Accepted plan on 2026-07-16.
- Final intervals are Off, Slow 30s, Medium 15s (default), and Fast 5s.
- Manual refresh always requests a full payload; scheduled and foreground refreshes use ETag/304.
- Enabled open lists perform an immediate conditional check when returning to the foreground; Off does not.
- The persisted profile key is `quicklistAutoRefresh`; absence or invalid runtime input resolves to `medium`, while the profile schema rejects unsupported saved strings.
- The custom tab-style segmented control stays under the QuickList feature, matches Theme Preference styling, and uses the central ProfileBlock save pipeline.
- The list ETag is a SHA-256 hash of the stable canonical visible representation. This trades a small server-side hash for collision-resistant change detection and bodyless 304 responses without a migration.
- Conditional requests use `If-None-Match`; manual requests omit it and therefore always receive a full 200 payload.
- Project title/tasks now render directly from the React Query project snapshot; optimistic mutations update that same snapshot instead of shadowing it in permanent local state.
- Mutation epochs and an in-flight guard prevent older polling/manual responses from overwriting newer local work.
- The overview and detail manual buttons await full fetches, disable/spin while busy, and the overview has no focus/reconnect polling.
- The list-detail poller uses serialized timeouts, pauses while hidden, coalesces `visibilitychange`/`pageshow`/focus resume signals, retries after active mutations, and restarts its interval after each check.
