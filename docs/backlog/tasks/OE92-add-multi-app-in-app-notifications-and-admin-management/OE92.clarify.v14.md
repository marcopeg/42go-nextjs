# Clarify Round v14 — Add Multi-App In-App Notifications and Admin Management

## Questions

### 1. How should an administrator configure whitelist/blacklist targeting?

Recommended backoffice wording and behavior:

- `Everyone in this app` is the default audience.
- `Only selected users` enables the whitelist.
- An optional `Hide from specific users` section configures the blacklist and
  takes precedence in either audience mode.
- Each section uses a mobile-friendly current-app user picker showing name,
  username, and email. Selected people appear as removable user rows/tags; the
  UI never says Allow/Deny.

For scalability, the picker can search current-app users server-side as the
administrator types instead of downloading the entire user table. This search
exists only in the backoffice editor, not on the user's notifications page.

## Answers

### 1.

Use one mutually exclusive audience mode:

- `Everyone in this app`
- `Only selected users`
- `Hide from specific users`

The backoffice current-app user picker filters by name, username, or email.
Selected people appear as removable user entries. Because whitelist and
blacklist modes cannot coexist, store `audience_mode` on the communication and
plain user membership rows in the normalized audience table; no per-row
`allow`/`deny` value is needed.

  are resolved.
