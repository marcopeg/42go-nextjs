# Clarify Round v7 — Add Multi-App In-App Notifications and Admin Management

## Questions

### 1. Add one more reaction template?

The recommendation is to add `Yes / No` as the only additional initial
template. It covers factual binary questions without misrepresenting them as
agreement or acceptance. Avoid synonymous templates such as Got it, Close, or
Proceed because they fragment analytics. Defer Remind me later because it
requires snooze lifecycle behavior rather than another reaction string.

### 2. Should the presentation-only field be named `presentation_style`?

The recommended values remain `info`, `warning`, `danger`, and `success`.
`presentation_style` controls only icon and color. Numeric `priority` controls
ordering. This makes the schema honest about the two independent concepts.

### 3. What belongs on the first notification-history page?

The recommended initial page is an inbox plus history: first show currently
eligible/unanswered in-app communications, then previously qualified or
responded communications ordered by most recent user activity. Each history
item shows status, title/body, first/last qualified display, reaction or poll/
input response, and availability/publication dates. Use browser pagination with
a server-paginated API rather than loading the user's entire history.

## Answers

### 1.

Add `Yes / No` to the initial hardcoded reaction-template registry. Do not add
the synonymous or lifecycle-expanding templates discussed in the question.

### 2.

Name the presentation-only field `style`, with `info`, `warning`, `danger`, and
`success` values matching the classic contextual-message UI convention.
`priority` alone controls ordering.

### 3.

The authenticated notifications page contains current active communications and
history. History is collapsed by default when active items need attention and
opens by default when there are no active items. History is server-paginated
ten items at a time and uses a `Load more` control.

Round v8 resolved the public URL as `/notifications` under the invisible
authenticated `(app)` route group.

## Resolution Summary

- The initial registry adds `Yes / No`.
- The presentation-only field is `style`; priority alone controls ordering.
- The notifications page combines active items with a conditionally collapsed,
  ten-at-a-time history at `/notifications`.
