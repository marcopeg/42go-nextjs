# Clarify Round v6 — Add Multi-App In-App Notifications and Admin Management

## Questions

### 1. Should mandatory poll validation use this precise rule?

For a non-skippable poll, the response is valid when it contains the configured
number of preset selections **or** a non-empty `Other` short input. In
single-choice mode, `Other` replaces a preset choice. In multiple-choice mode,
`Other` may accompany preset choices. Notes never substitute for a required
choice/Other response; notes are independently configured as optional or
required. A skippable poll may be dismissed with no selections, Other, or notes.

### 2. What exactly qualifies as one display-history event?

The recommended rule remains one event per component mount/route visit after at
least 50% of the notification has remained continuously in the viewport for
10 seconds while the document is visible. Leaving the viewport, hiding the tab,
changing route, or changing to the next message resets the timer. Normal React
rerenders do not create another event.

### 3. Is the user notification-history page in this implementation?

The recommended AppConfig boundary is an in-app communication section with
`showOnProfile` and `showHistoryLink`. If the link can be enabled in this task,
implement a minimal client-only, feature-flagged `/notifications` page now;
otherwise reserve `showHistoryLink` as false and move the route/UI to a later
task. In either case, the database indexes required by that page remain in the
current task.

## Answers

### 1.

For a mandatory single-choice poll, exactly one of a preset option or non-empty
`Other` input is accepted. Selecting a preset option and entering `Other`
together is a validation error in either direction. For a mandatory
multiple-choice poll, at least one preset option or non-empty `Other` is
required; `Other` may accompany selected options.

Notes are an independent per-poll switch. When enabled they are always optional
and never satisfy the mandatory poll answer. The user UI exposes notes through
a compact secondary affordance such as “Add notes to your answer”; exact visual
treatment can be settled during design.

### 2.

Accepted. Record at most one qualified display event per component mount/route
visit after at least 50% of the communication remains continuously visible for
10 seconds while the document is visible. Interruptions reset the timer and
ordinary React rerenders do not create another event.

### 3.

Implement the client-only notification-history page in this task and protect it
with an explicit AppConfig feature flag. AppConfig independently controls
whether the notification component links to that page. The component renders
the link only when both the link setting is enabled and the page feature flag is
present; contradictory configuration must fail safely with no link.

## Resolution Summary

- Mandatory single/multiple choice, `Other`, and optional notes validation is
  resolved.
- Qualified display events use the 50%-visible, continuous 10-second,
  once-per-mount/visit rule.
- The feature-flagged client-only notification-history page is in scope, with
  an independent AppConfig link toggle that cannot bypass the feature flag.
