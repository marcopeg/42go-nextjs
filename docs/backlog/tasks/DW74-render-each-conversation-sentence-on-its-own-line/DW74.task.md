# Render Each Conversation Sentence on Its Own Line

## Elevator's Pitch

In the LingoCafe conversation reader, render every detected sentence on a new visual line inside its existing conversation round. Reuse the same canonical sentence boundaries that power sentence translation and playback, make the sentence-identification path independently testable so inline Markdown such as italics cannot create false boundaries, and expose the layout behavior through a clean switch that can later be driven by reader preferences.

## Business Gain

Conversation rounds become easier to scan and follow, especially on mobile, without changing their speaker or turn structure. Translation and playback continue to operate on the exact sentence the learner sees. Chuck Norris breaks lines at sentences, not at asterisks.

## Current State

Conversation rounds are rendered by `ConversationTranslatableText` as adjacent inline sentence targets separated according to source whitespace. The shared pure utility in `src/lib/lingocafe/sentence-segmentation.ts` already identifies sentence boundaries for conversation translation, playback, book reading, and server validation, with focused coverage in `tests/lingocafe-sentence-segmentation.test.mts`. However, conversation sentences remain on the same flowing line within a round, and the reported mobile example shows an apparent false sentence boundary around italic Markdown: `Skeppet *Etna* krockade med saken.` is treated or highlighted as though the italicized name split it, leaving only `krockade med saken.` as the selected sentence.

## Desired State

Within each conversation round, every actual sentence starts on a new visual line while remaining inside the same actor turn and chat bubble. Consecutive sentence lines use the reader's normal line height, like soft line breaks, with no added paragraph-style vertical gap. This layout applies only to round dialogue; conversation titles and descriptions keep their existing flowing layout. Sentence lines must be derived from the same sentence-identification result used by translation and playback; rendering must not apply a second, divergent boundary algorithm. Inline Markdown boundaries, including emphasis in the middle of a sentence, must remain presentation-only and must not split one linguistic sentence into multiple translation targets, playback units, or lines. Isolate any remaining Markdown-aware identification/mapping logic into a pure unit-testable module or extend the existing shared sentence-segmentation module, keeping React rendering separate from boundary decisions. Expose sentence-per-line layout through an explicit, narrowly scoped component option. Enable it for round dialogue through one clearly visible value at the round call site or equivalent configuration point, so deactivation is a one-line change. Do not add a user-facing toggle in this task; the option must be ready to connect to a reader preference later without restructuring sentence rendering.

## Definition of Success

A multi-sentence conversation round displays one sentence per line, and tapping or playing any line addresses that same complete sentence. The exact italic example remains one sentence and one translation/playback target. Focused unit tests prove both ordinary multi-sentence splitting and formatting-markup continuity.

## Additional Context

The attached iPhone screenshot shows `Skeppet Etna krockade med saken.` with `Etna` italicized and only the trailing words behaving as the selected sentence. This is the permanent regression case. Existing task SO68 established the canonical language-independent sentence splitter; completed task QT31 established the conversation translation and playback surfaces.

## Assumptions

- A newline means a visual line break inside the existing conversation round, not a new actor round, list item, or chat bubble.
- The underlying round text, punctuation, Markdown formatting, actor attribution, and ordering remain unchanged.
- The same sentence identity and ordering must serve display, translation authorization, playback cataloging, highlighting, and start-from-here behavior.
- Basic allowed inline Markdown, including emphasis, may occur anywhere within a sentence.
- Sentence-to-sentence line breaks use normal line height and add no paragraph-style spacing.
- Sentence-per-line layout applies only to round dialogue in this task; titles and descriptions retain normal inline flow.
- A future task may expose the activation switch in the reader preference panel.
- The feature is enabled for rounds in this task, and deactivation must require changing only one explicit line.

## Constraints

- Reuse `src/lib/lingocafe/sentence-segmentation.ts` or a clean extension of it; do not introduce a conversation-only sentence splitter.
- Do not treat Markdown syntax tokens or React element boundaries as sentence terminators.
- Do not strip or flatten visible Markdown styling merely to simplify sentence detection.
- Do not create extra conversation rounds or alter stored content.
- Preserve stable sentence IDs and synchronization between rendered targets and the playback catalog.
- Keep the identification logic pure and cover it with focused unit tests; run `npm run qa` after implementation.
- Keep the layout switch independent from sentence identification and translation scope so a future preference can toggle presentation without changing sentence identities.

## Acceptance Criteria

- [ ] A conversation round containing two or more detected sentences renders each sentence on a separate visual line within the same round and actor bubble.
- [ ] Consecutive sentence lines use the normal reader line height with no extra vertical spacing.
- [ ] Conversation titles and descriptions retain their current flowing sentence layout.
- [ ] Round sentence-line layout is controlled through an explicit component option or equivalent clean activation boundary, enabled for rounds in this task.
- [ ] The implementation has one obvious round-level value or prop whose one-line change disables sentence-per-line rendering.
- [ ] Switching that option off restores the existing inline flow without changing sentence IDs, translation targets, playback units, or source content.
- [ ] No user-facing preference toggle is added in this task.
- [ ] Line breaks are inserted only between sentence segments returned by the canonical sentence-identification logic.
- [ ] `Skeppet *Etna* krockade med saken.` is identified and rendered as one complete sentence despite the inline italic span.
- [ ] In `Skeppet *Etna* krockade med saken. Det ...`, the first boundary occurs after `saken.`, never before or after `Etna`.
- [ ] Selecting sentence translation for the italic regression case submits the complete visible sentence, including `Skeppet Etna krockade med saken.` with Markdown syntax excluded from the translated plain text as required by the existing API contract.
- [ ] Playback catalog entries, active highlighting, pronunciation, and start-from-here use the same full sentence and remain aligned with the displayed line.
- [ ] Inline bold, italic, links, and adjacent plain-text fragments do not create false sentence boundaries; their visible styling remains intact.
- [ ] Existing punctuation, abbreviation, decimal, closing-quote, dialogue-dash, and Unicode terminator behavior remains covered and unchanged.
- [ ] Sentence-identification and any Markdown-to-visible-text mapping logic are isolated from React rendering and have focused unit tests, including the exact italic regression fixture and a normal multi-sentence round.
- [ ] The conversation reader remains accessible and responsive on a viewport near 390 px and on desktop.
- [ ] Focused tests and `npm run qa` pass.

## Dos

- Use one canonical sentence model to drive line layout, translation targets, sentence IDs, and playback units.
- Add the attached `Skeppet *Etna* krockade med saken.` case as a permanent regression fixture.
- Preserve source whitespace and punctuation within each sentence while making the inter-sentence separator a visual line break.
- Verify the result in the conversation reader on mobile and desktop.
- Keep the activation boundary ready for a future preference-panel control without adding that control in this task.

## Don'ts

- Do not split a sentence at `<em>`, `<strong>`, link, React child, or Markdown delimiter boundaries.
- Do not solve the layout by inserting line breaks into stored conversation text.
- Do not maintain separate display, translation, and playback splitters.
- Do not turn each sentence into a separate speaker bubble.
- Do not couple sentence-line layout to the word-versus-sentence translation preference.
