# Promote Events to Core App-Scoped Event System

## Historical Summary

- A core `events` PostgreSQL schema exists for platform events. - Events are app-scoped so each event belongs to a resolved `app_id` and analytics can filter or export by app without ambiguity. - The chosen physical layout is one core parent table such as `events.events`, partitioned by `created_at` with mandatory `app_id` and app/time indexes. - The core table does not use app-specific physical partitions in v1. App isolation is logical through `app_id`, not separate parent tables or list partitions. - The core table keeps indexing lean because PostgreSQL is a hot download buffer, not the live analytics store. Required indexing focuses on the export cursor and app-scoped extraction. - The schema supports generic events with a stable shape: `created_at`, `id`, `app_id`, `user_id`, `event_at`, `name`, `data`, and `meta`. Optional `source` or `session_id` can be included only if planning proves they are useful. - App-specific dimensions such as LingoCafe `book_id` and `page_id` move into the JSONB `data` payload instead of becoming core columns. - The schema preserves ingestion cursor semantics with `(created_at, id)` for export and treats `event_at` as behavioral time. - Existing LingoCafe event recording is migrated to the core writer. LingoCafe event names should use app-scoped dot names such as `book.info`, `page.open`, `page.scroll`, and `page.translate`; the row's `app_id` provides the app scope. Existing LingoCafe dimensions should be represented in `data`. - A server-only library under `src/42go/events` exposes a small interface to record one event or a batch of events with payload and metadata. - The server writer resolves or accepts `app_id`, prepares partitions, validates event names and payload boundaries, and inserts through Knex using `getDB()`. - Client event collection is enabled per app through AppConfig, not globally. - A protected server API endpoint accepts client-side event batches for the current app only when the current app enables the feature. The endpoint can require a valid session through config, and that should be the default for most apps. - Client-submitted rows must be associated with a server-trusted `user_id` when the endpoint requires a session. This is mandatory for abuse investigation. - A client-side facility provides a simple `trackEvent(name, data, options)` style interface with lightweight batching, configurable batch size/flush interval, frequent default flushing, flush-on-visibility/pagehide behavior, and no fragile dependency on analytics vendors. - The client receives enough app config to know whether event logging is available for unauthenticated calls. If app code tries to use unavailable logging, the client should emit a console warning and drop or skip the event safely. - Core user lifecycle events are recorded as `user.signup`, `user.login`, `user.logout`, `user.profile.created`, `user.profile.updated`, `user.consent.created`, and `user.consent.updated`. - Login and signup events include the auth method in `data`. Logout has no extra data requirement in v1. Profile and consent update events store `prev` and `next` snapshots in `data`. - Logout tracking is best-effort client-side in v1. - VI41's export work is superseded by core events export. The existing `lingocafe-events-export` skill should become `42go-events-export`, targeting the new core schema while preserving the paired CSV/Parquet mechanics. - A new local `42go-events-logging` skill documents how future features should integrate with core event logging. Its `SKILL.md` should stay short and link to load-on-demand subdocuments for details. - Documentation explains how app-scoped event exports are stored locally, likely by app and date or with app fields in Parquet partition paths, without mixing unrelated apps accidentally.

## Durable Outcome and Decisions

- Execution accepted one core parent table `events.events`, monthly range partitioning by `created_at`, mandatory `app_id`, and lean extraction indexes.
- Historical `lingocafe.events` rows are not migrated in WS58.
- Production cleanup of the old LingoCafe event table remains manual.
- Client event collection is off by default and enabled per app. LingoCafe enables `api:events` with session-required collection.
- Logout recording is best-effort client-side.
- LingoCafe event names do not repeat the app ID. The row is already scoped by `app_id = "lingocafe"`.

## Validation and Limitations

- `events.events` exists as a partitioned parent table.
- Current and future monthly partitions were created.
- App/time and app/name indexes exist on partitions.
- A direct event insert/select into `events.events` works.
- Light dump excludes `events.events` and obsolete `lingocafe.events`.
- Full dump includes `events.events` and emits required `events.events_YYYYMM` partition DDL.
- Limitations: Historical rows in `lingocafe.events` remain where they are. A smoke row named `system.smoke` was inserted into the local `events.events` table during validation, then the LingoCafe data seed cleanup removed LingoCafe core event rows during `npx knex seed:run`. Full browser auth/profile/logout event proof was not run in Playwright.
