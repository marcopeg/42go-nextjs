# Plan — QuickShare: Package maintained automation skill and deterministic client

## Goal

Ship a publishable QuickShare plugin whose low-dependency client obtains runtime truth from discovery, protects credentials, and performs deterministic confirmation-aware workflows.

## Milestones

### Milestone 1 — Scaffold maintained packaging and secure setup

- [x] Step 1 — Add the canonical QuickShare plugin and skill
  - Achieve: Register a repository-owned installable plugin with durable workflow guidance and no duplicated volatile API catalog.
  - Create: `assistants/plugins/quickshare/` manifests, `skills/quickshare/SKILL.md`, agent metadata, references, and repository-local discovery link.
  - Modify: Assistant marketplace catalogs and documentation.
  - Delete: Nothing.
  - Touch points: Codex/Claude-compatible metadata, names, versions, capability declarations.
  - Validation: Repository, plugin, and skill validators pass.
  - Notes: Keep QuickShare separate from QuickList and QuickNotes.

- [x] Step 2 — Implement scoped secret configuration
  - Achieve: Store base URL and token through hidden input in an approved untracked owner-readable project or global location.
  - Create: Low-dependency client/setup script and credential-selection helpers.
  - Modify: Skill setup guidance and KQ66 one-time disclosure UI only if a versioned connection envelope is adopted.
  - Delete: Nothing.
  - Touch points: Atomic writes, directory `0700`, file `0600`, project/global precedence, configurable origin.
  - Validation: Missing/malformed credentials, selection precedence, permissions, replacement, no-echo, and redaction tests.
  - Notes: Never accept tokens in URLs or ordinary command arguments.

### Milestone 2 — Implement the discovery-driven client

- [x] Step 3 — Authenticate and resolve live capabilities
  - Achieve: Fetch discovery first, validate its supported contract version, and resolve stable operations without caching stale details across invocations.
  - Create: Client HTTP, discovery, schema interpretation, sanitization, and error modules.
  - Modify: Nothing server-side unless a genuine ZA41 defect is found and repaired within its contract.
  - Delete: Nothing.
  - Touch points: Authorization header, timeouts, JSON parsing, deprecation/replacement metadata.
  - Validation: Mock success, auth failure, malformed/unsupported discovery, deprecation, and network tests; exceptions never contain credentials.
  - Notes: Discovery is runtime truth.

- [x] Step 4 — Add stable semantic lifecycle commands
  - Achieve: Support discover, list, read, create, save, publish, unpublish, and delete while deriving methods, paths, fields, and validation requirements dynamically.
  - Create: Command handlers and concise API/discovery reference.
  - Modify: `SKILL.md` with authenticate→discover→interpret→confirm→execute→report workflow.
  - Delete: Any hard-coded change-prone request schemas/options.
  - Touch points: JSON stdin/file payloads, explicit resource type, template ID/version, sanitized structured output.
  - Validation: Mock tests prove endpoint templates and payload requirements come from discovery.
  - Notes: Stable intent commands are allowed; volatile server facts are not.

- [x] Step 5 — Enforce disruptive-action confirmation
  - Achieve: Refuse Unpublish, published-resource Delete, and every discovery-marked disruptive operation until explicit operator confirmation is supplied.
  - Create: Confirmation policy/preflight helper.
  - Modify: Skill safety guidance and command interface.
  - Delete: Nothing.
  - Touch points: Preflight read, discovery effect metadata, non-interactive `--yes` equivalent.
  - Validation: Refusal without confirmation, correct stronger published-delete explanation, and execution only after confirmation.
  - Notes: The agent obtains consent; the client enforces the final gate.

### Milestone 3 — Test, smoke, and package

- [x] Step 6 — Add offline security and workflow tests
  - Achieve: Cover credential safety, discovery interpretation, request construction, confirmations, and sanitized error handling without live secrets.
  - Create: Python/client test suite and package test script.
  - Modify: Publishing/security documentation.
  - Delete: Generated caches.
  - Touch points: 401/403/404/409, validation/conflict/deprecation/network errors.
  - Validation: Client tests plus repository/plugin/skill validators pass.
  - Notes: The default suite contains no live token.

- [x] Step 7 — Run autonomous default-app smoke and final QA
  - Achieve: Use a temporary credential location and seeded local account to drive representative create/save/publish/read/unpublish/delete through the real client.
  - Create: Temporary untracked credentials only.
  - Modify: Fixes found during smoke validation.
  - Delete: Temporary token, credential file, resources, public output, and caches through safe lifecycle operations.
  - Touch points: Local default app, `john/john`, all resource families, static origin, secret-redacted output.
  - Validation: Actual discovery-driven workflow, browser/API cross-check, revoked token failure, validators, focused tests, and `npm run qa` pass.
  - Notes: Never touch the operator's existing global credential file.
