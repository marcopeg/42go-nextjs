# QuickShare: Package maintained automation skill and deterministic client

## Elevator's Pitch

Ship a maintained QuickShare skill and deterministic low-dependency client that authenticate, discover the live API contract, and execute safe share workflows for an agent.

## Business Gain

Users can ask an agent to create, edit, publish, unpublish, or delete shares without teaching it raw HTTP, while the skill remains stable as compatible API payloads and options evolve.

## Current State

QuickShare has no packaged agent skill, credential setup flow, deterministic client, or end-to-end agent smoke proof.

## Desired State

A repository-owned publishable QuickShare plugin contains a Codex-compatible skill, references, secure credential configuration, and an executable low-dependency client. The stable workflow is authenticate, call live discovery, interpret the returned contract, validate the intended operation, obtain confirmation for disruptive actions, execute, and report sanitized results. Change-prone resource schemas, template options, limits, and endpoint details come from discovery rather than SKILL.md.

## Definition of Success

After secure one-time configuration, an agent can discover capabilities and complete representative create/save/publish/read/unpublish/delete workflows through the deterministic client without printing credentials or relying on stale hard-coded payloads.

## Additional Context

Follow the proven QuickList plugin and credential-handling pattern where applicable: canonical source under assistants/plugins, a repository-local discovery link, project-scoped or global credential selection, owner-only credential-file permissions, configurable base URL, one-time connection material handled outside normal chat, and quiet sanitized output. The client should treat discovery as runtime truth while the skill explains intent, sequencing, confirmation, recovery, and safety.

## Assumptions

The versioned automation API and live discovery endpoint are complete and token-authenticated before this task begins. A small standard-library Python client or equivalently low-dependency implementation is sufficient.

## Constraints

Depend on KQ66 token lifecycle and completed ZA41 versioned API/discovery. Never embed, log, echo, screenshot, return, or commit bearer credentials. Do not accept tokens in URLs or ordinary command-line arguments. Do not hard-code change-prone request schemas or template options that discovery can supply. Keep this skill separate from QuickList and QuickNotes.

## Acceptance Criteria

- A publishable QuickShare plugin contains SKILL.md, agent metadata, API/discovery guidance, and a deterministic executable client.
- Secure setup stores base URL and token only in an approved untracked owner-readable location and supports deterministic project-local or global selection.
- Normal output, errors, logs, and examples never reveal bearer tokens or connection material.
- The client authenticates, fetches discovery, validates requested operations against the live contract, and constructs supported requests dynamically.
- The workflow obtains explicit operator confirmation before Unpublish, published-resource Delete, or any other discovery-marked disruptive operation it supports.
- Useful sanitized errors cover missing credentials, authentication failure, unsupported/deprecated capabilities, validation errors, conflicts, authorization failure, and network failure.
- Smoke tests cover capability discovery and representative create/save/publish/read/unpublish/delete behavior without live secrets in the default test suite.
- Plugin and skill validators pass.
- npm run qa passes.

## Dos

- Keep SKILL.md focused on durable workflow and safety while discovery owns volatile contract details.
- Reuse proven QuickList credential and client conventions where they fit.
- Make every mutation deterministic and confirmation-aware.

## Don'ts

- Do not duplicate the server's live schema catalog in static skill prose.
- Do not require an MCP server for version one.
- Do not expose secrets through chat, shell history, process arguments, or tracked files.

## Open Questions

None that blocks planning; exact plugin package metadata and client module decomposition belong to implementation planning.
