# Plan — Show all CEFR variants in the conversation library

## Goal

Keep conversations scoped to the authenticated learner's target language while making every available CEFR variant visible and directly selectable, regardless of profile target level.

## Milestones

### Milestone 1 — Remove the server-side level gate

- [x] Step 1 — Make browse discovery and category queries level-agnostic
  - Achieve: Return all eligible A1, A2, B1, and B2 conversations for the profile target language, while retaining the existing target-language and visibility rules.
  - Modify: `src/app/api/(lingocafe)/lingocafe/_lib/conversations.ts`, discovery/category route handlers, and browse ETag inputs as needed.
  - Touch points: Profile loading, category availability joins, eligible-conversation filtering, browse DTOs, and query validation.
  - Validation: Targeted API tests prove target language remains scoped, profile level is ignored, and category counts include all CEFR variants.
  - Notes: Legacy `band` inputs must not hide content; new internal/navigation URLs become bandless.

### Milestone 2 — Simplify client browse state and preserve selection UX

- [x] Step 2 — Remove band state and URL propagation from conversations
  - Achieve: Discovery, category, starred, reader return links, shell preference saves, cache keys, and types no longer select or propagate a learner band.
  - Modify: Conversation library shell, browse pages, shared types/helpers, and related client cache usage.
  - Touch points: `/conversations`, category, starred, reader return navigation, and `LanguagePreferencesMenu` save callback.
  - Validation: Changing only `targetLevel` leaves the active conversation route/results untouched; changing target language still reloads the scoped corpus.
  - Notes: Keep backward-compatible requests with `band` usable but inert.

- [x] Step 3 — Expand existing grouped-level controls
  - Achieve: Each grouped conversation row renders one direct, accessible CEFR button for every available exact level and presents the same complete choice set in desktop/mobile pickers.
  - Modify: `ConversationChoiceGroupRow` and its targeted tests only as necessary.
  - Touch points: Badge labels, accessible names, desktop popover, mobile bottom sheet, and exact conversation links.
  - Validation: A1/A2/B1/B2 choice groups are ordered and open the matching exact conversation on desktop and mobile.
  - Notes: Reuse existing list, badge, Radix, and SwipeableBottomSheet patterns; no new visual primitive is needed.

### Milestone 3 — Prove and verify the whole flow

- [x] Step 4 — Update regression coverage and run quality/visual checks
  - Achieve: Replace obsolete band-contract assertions with all-level and target-language-scope coverage, then verify the signed-in conversation UI at desktop and mobile widths.
  - Modify: Conversation tests and any concise execution notes.
  - Touch points: `tests/lingocafe-conversations-api.test.mts`, focused test commands, QA, and LingoCafe tunnel browser session.
  - Validation: Focused tests and `npm run qa` pass; the UI shows every available level button without horizontal overflow in light and dark themes.
  - Notes: Record unavailable browser/development-data prerequisites rather than faking visual evidence.

### Milestone 4 — Switch levels from the exact conversation reader

- [x] Step 5 — Add responsive reader-level navigation with floating-control clearance
  - Achieve: Return eligible sibling exact levels with the protected detail response and render an accessible navigator that marks the current level, preserves return navigation, sits in a fixed vertical desktop rail beside the reading column, and remains reachable above the mobile FAB/player.
  - Modify: Conversation detail data access/DTO, reader UI, and targeted conversation regression coverage.
  - Touch points: `loadConversationDetail`, `ConversationDetailResponse`, `ConversationReaderPage`, and reader verification.
  - Validation: Signed-in desktop and 390 px mobile reader views show A1/A2/B1/B2 links, level switching loads the selected dialogue, the desktop rail remains fixed while reading, and the mobile navigator clears the floating controls.
  - Notes: Use a safe-area-aware reading-column bottom padding because the playback player can replace the normal FAB; vertically align the mobile level row with the FAB controls, while keeping the group horizontal and divider-free.
