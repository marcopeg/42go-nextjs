# Show all CEFR variants in the conversation library

## Elevator's Pitch

Remove the profile-level filter from LingoCafe conversations so learners can discover every available CEFR variant—A1, A2, B1, and B2—for their configured target language. The conversation list already presents direct A2/B1 choice buttons when variants coexist; expand that behavior so no level is hidden by profile state.

## Business Gain

Learners can choose the difficulty that fits the moment without editing their profile first. The conversation library becomes a complete view of the target-language corpus, and level buttons make alternatives clear instead of silently excluding them.

## Current State

Conversation discovery and category APIs resolve a learner band from auth.users.profile.targetLevel: A1 maps to beginner, A2 to intermediate (A2+B1), and B2 to advanced. The client propagates the optional band query across discovery, category, starred, navigation, and return URLs. The data-access layer filters visible exact conversations to that band. ConversationChoiceGroupRow already renders a deterministic chooser and direct CEFR buttons when more than one exact choice is returned, currently most notably A2/B1.

## Desired State

For the authenticated user's configured target language, discovery, category, and starred conversation views expose all available exact CEFR variants: A1, A2, B1, and B2. Remove the profile targetLevel-derived band as a filter from the conversation browse contract and its client navigation state. Keep the target language server-derived from the profile; this task broadens CEFR visibility, not cross-language access. Preserve the existing multi-choice row interaction and render one direct CEFR button for every available exact level of a conversation, so learners can select the intended version. Category availability counts and empty states must reflect all visible target-language levels. Existing exact-conversation routes, read/star state, translation, and playback must continue to work.

## Definition of Success

A signed-in learner can open Conversations with any profile target level and browse the same complete set of target-language conversation variants across A1, A2, B1, and B2. Where a conversation has multiple variants, the list visibly offers one CEFR button per available exact level and each opens the correct exact conversation. No profile-level band silently hides an otherwise eligible target-language conversation.

## Additional Context

This is a focused follow-up to completed QT31. Relevant implementation spans the typed conversation browse API/data-access module under src/app/api/(lingocafe)/lingocafe/_lib/conversations.ts, the GET discovery/category handlers, and the client conversation library pages, shell, types, cache identity, URL helpers, and group-row UI. The existing LanguagePreferencesMenu can continue to save targetLang and targetLevel for other app areas. A targetLang change continues to reload conversations for that language, but a targetLevel update must not narrow the conversations corpus or force a conversation-band URL transition.

## Assumptions

The user's target language remains authoritative and server-derived from profile state.

All four CEFR levels are included when represented in that target language; absent levels are simply not shown.

The profile targetLevel remains stored and may still drive book filtering or other surfaces, but it no longer controls conversation-library visibility.

Starred conversations remain limited to the current target language and are shown across every CEFR level; their existing exact-conversation user state remains attached to each exact ID.

## Constraints

Use the existing LingoCafe conversation data contract and client-only authenticated AppLayout route conventions.

Do not expose conversations from a language other than the profile's target language.

Do not add a replacement manual level filter unless refinement explicitly expands scope; this task removes filtering rather than relocating it.

Preserve explicit CEFR labels, deterministic direct choice behavior, accessible controls, URL safety, cache correctness, and no-store/ETag behavior.

Update targeted tests and run npm run qa; manually verify through the LingoCafe public tunnel at desktop and approximately 390 px mobile widths.

- [ ] The profile targetLevel-derived band, its browse filtering, and unnecessary band propagation are removed or made inert across the conversation browse API, client pages, shell, cache/ETag identity, and navigation URLs.
- [ ] Changing the profile targetLevel does not narrow the current conversation discovery/category results or redirect the conversation view to a level-band URL.
- [ ] A scenario/variant with multiple exact CEFR choices renders one direct button for every available level, and each direct choice opens the matching exact conversation.
