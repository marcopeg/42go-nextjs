**Task**: ./FN40.task.md

## Decisions

- Keep target-language scoping server-derived from the profile.
- Remove CEFR band selection from browse APIs, DTOs, cache/ETag validators, and newly generated client URLs.
- Continue accepting legacy `band` query parameters by ignoring them, so old links remain usable without filtering results.
- Reuse the existing grouped conversation row: once the API returns all exact CEFR variants, it already renders one direct button and one picker choice per variant.
- Aggregate the materialized exact-level category availability rows (`a1`, `a2`, `b1`, `b2`) so category counts remain precomputed and reflect every visible level.
- The exact-conversation response now returns eligible same-language sibling levels for its scenario/variant. The reader marks the current level, preserves the originating category return URL, and renders levels as a fixed, vertically centered desktop rail at the viewport's right edge or a divider-free lower mobile navigator aligned with the FAB centers.
- Changing level inside the reader replaces the current reader URL and content in place instead of opening another intercepted modal; it resets the reader scroll position to the top so one swipe/back action returns to the conversation list.

## Known Limitations

Both reader surfaces reset the new level to scroll position zero; closing/swiping back returns to the originating list. Neither viewport had horizontal overflow or console errors.
