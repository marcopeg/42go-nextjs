## Questions

### 1. What final labels should appear in the Playback settings popover?

Suggested pair:

- `Reveal as you listen` — future text stays hidden until playback reaches it.
- `Dim previous sentences` — sentences before the current one remain visible with reduced contrast.

Other concise options include `Hide upcoming text`, `Progressive reveal`, `Dim played text`, and `Fade previous sentences`. Please choose the pair or provide different wording.

Answer:

I like "Reveal as you listen" and "Dim previous sentences"

### 2. Should both options default to off?

The proposed default is off for both settings. This preserves the current reader appearance for new users and for missing, malformed, or legacy local-storage data.

Answer:

yes, and they should be stored locally on the device for now.

### 3. How should sentence state be derived when playback starts or seeks into the middle of a page?

The simplest deterministic rule is positional: every sentence before the active sentence is treated as revealed and played, the active sentence is current, and every sentence after it is unplayed. This means the UI reflects the canonical playback index even if earlier sentences were not actually heard during this session.

Should CE70 use that positional rule?

Answer:

yes

### 4. What should happen after a backward seek?

The proposed rule is to recompute from the new active sentence. Sentences after it become hidden again when progressive reveal is enabled and return to normal contrast because they are no longer before the active position. This creates a movable reading curtain rather than a permanent “furthest point reached” marker.

Should backward seeking reset the visual frontier this way?

Answer:

yes

### 5. When should the progressive-reveal presentation remain active?

Proposed state rules:

- Playing: keep the current positional reveal/dimming state.
- Paused, including automatic pauses: freeze the same presentation at the current sentence.
- Playback completed: reveal the entire current page; all sentences may return to normal contrast.
- Playback closed, unavailable, or failed: reveal the entire page and remove played-text dimming.
- Page transition during continuous playback: initialize the new page from its active sentence using the same positional rule.

Accept these rules or specify changes.

Answer:

accept

### 6. Which page content should be hidden after the active sentence?

Sentence text is catalogued, but the page may also contain headings, paragraph spacing, summaries, separators, illustrations, and other non-sentence structure. Choose a rule:

- Hide or collapse every content block that lies wholly after the active sentence, while keeping the current sentence’s containing paragraph/block intact.
- Hide only future sentence text but preserve all surrounding layout and non-sentence content.
- Use another rule.

Answer:

anything after the currently played sentence should be hidden. but if the user exits the playback mode then all is visible again. if the users only pauses the playback, all stays hidden.

### 7. How should progressive reveal behave for assistive technology?

The proposed rule is that future content hidden by this mode is also removed from keyboard navigation and the accessibility tree until revealed. Users who need the full document can leave the optional setting off or disable it immediately.

Accept this rule or specify an alternative.

Answer:
we are not focused on assistive technologies. pick the easiest path.

### 8. How strong should played-text dimming be?

The proposed implementation target is theme-aware muted text at roughly 50–60% of normal visual prominence, while preserving readable contrast and leaving the active sentence, active word, and translation selection treatments untouched. Exact tokens/opacity may be tuned during visual verification in light and dark themes.
