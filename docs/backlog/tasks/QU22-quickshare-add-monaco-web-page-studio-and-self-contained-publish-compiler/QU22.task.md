# QuickShare: Add Monaco web-page studio and versioned asset-bundle compiler

## Elevator's Pitch

Let accounts author web pages in Monaco and publish a compiled static bundle with HTML plus cacheable sidecar assets.

## Business Gain

QuickShare can host durable personal landing pages and interactive pages while preserving the draft-to-explicit-publish contract.

## Current State

QuickShare has no web-page resource type, admin studio, preview isolation, build pipeline, or generated release bundle.

## Desired State

A Web Page resource stores HTML, CSS, and JavaScript or TypeScript draft source plus managed assets. An authenticated admin studio uses Monaco for editing and an isolated preview. At explicit publish, a deterministic pipeline transpiles modern JavaScript/TypeScript, processes CSS, fingerprints emitted files, and produces a release bundle containing `index.html`, a manifest, and content-hashed CSS, JavaScript, image, font, or other sidecar files. Browser-side JavaScript in the published page is allowed.

## Definition of Success

An owner can repeatedly save a web-page draft, explicitly publish it, and open a complete static bundle that no longer depends on editor runtime assets. Repeat visits reuse immutable cached sidecar assets while a republish updates the stable entry safely.

## Additional Context

This is a CodePen-like authoring and build pipeline, not a general package-hosting service. User-authored code is untrusted. Preview must not execute with `quickshare.42go.dev` account authority. Published code runs on the deliberately separate shared origin `s.42go.dev`, which carries no editor cookies or secrets. Because that is a shared execution origin, product documentation must not promise confidential per-page origin storage.

## Assumptions

- Source panels and managed uploads can produce multiple output files; inlining is optional optimization, not a publication requirement.
- Build output uses deterministic content hashes and a manifest consumed by the atomic publisher.

## Constraints

Depend on foundation, durable resource authoring, and static-origin publication. Compile at publish time, never from public request handling. Arbitrary package imports and general dependency bundling are outside version one. Do not add Telegram/HAL implementation work; retain only compatibility at the published-page boundary.

## Acceptance Criteria

- Web Page is an explicit QuickShare resource type with durable HTML, CSS, and JavaScript/TypeScript draft source.
- Monaco studio provides a usable authenticated authoring experience and validates/stores drafts account-safely.
- Publish transpiles supported modern JavaScript/TypeScript and processes CSS into a versioned static release bundle.
- `index.html` references content-hashed sidecar JavaScript, CSS, images, fonts, and other managed assets with correct relative or versioned URLs.
- Browser-side JavaScript executes from the static origin, while preview code cannot access editor cookies, tokens, DOM, or privileged APIs.
- Unsupported package imports/bundling fail clearly and are documented as out of v1 scope.
- Compiler failures never replace a currently published artifact.
- Relevant editor, compiler, static-output, and QA tests pass.

## Dos

- Produce deterministic manifests and let IF14 own atomic release and cache behavior.
- Keep compilation errors attached to source locations and preserve the prior publication.

## Don'ts

- Do not require one inlined HTML document.
- Do not execute authored code directly in the authenticated editor origin or allow general package installation in version one.

## Open Questions

The exact transpiler and CSS processor are implementation-plan choices; their supported syntax and limits must be documented before release.
