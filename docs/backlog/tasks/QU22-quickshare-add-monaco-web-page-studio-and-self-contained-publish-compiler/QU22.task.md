# QuickShare: Add plain web-page authoring and versioned asset-bundle compiler

## Elevator's Pitch

Let accounts author plain HTML, CSS, and JavaScript web pages in simple text areas and publish a static bundle with cacheable sidecar assets.

## Business Gain

QuickShare can host durable personal landing pages and interactive pages while preserving the draft-to-explicit-publish contract.

## Current State

QuickShare has no web-page resource type, admin studio, preview isolation, build pipeline, or generated release bundle.

## Desired State

A stable web-page type and its creation/authoring options register in the shared catalog consumed by the `+ New Share` popover and agent-readable API discovery.

A Web Page resource stores plain HTML, CSS, and JavaScript draft source plus managed assets. An authenticated editor uses simple text areas and an isolated preview. Creation follows the shared resource contract: it previews a generated short URL by default, or an available handle-scoped custom URL when the author supplies a custom ID. At explicit publish, a deterministic pipeline validates the supported source, fingerprints emitted managed files, and produces a release bundle containing `index.html`, a manifest, and content-hashed CSS, JavaScript, image, font, or other sidecar files. Browser-side JavaScript in the published page is allowed.

## Definition of Success

An owner can repeatedly save a web-page draft, explicitly publish it, and open a complete static bundle that no longer depends on editor runtime assets. Repeat visits reuse immutable cached sidecar assets while a republish updates the stable entry safely.

## Additional Context

This is a deliberately simple source authoring and publication pipeline, not a general package-hosting service or rich code editor. User-authored code is untrusted. Preview must not execute with `quickshare.42go.dev` account authority. Published code runs on the deliberately separate shared origin `s.42go.dev`, which carries no editor cookies or secrets. Because that is a shared execution origin, product documentation must not promise confidential per-page origin storage.

## Assumptions

- Source panels and managed uploads can produce multiple output files; inlining is optional optimization, not a publication requirement.
- Build output uses deterministic content hashes and a manifest consumed by the atomic publisher.

## Constraints

Depend on foundation, durable resource authoring, and static-origin publication. Validate and bundle only plain authored HTML, CSS, JavaScript, and managed assets at publish time, never from public request handling. Rich editing, TypeScript, CSS or JavaScript transpilation, arbitrary package imports, and general dependency bundling are outside version one. Do not add Telegram/HAL implementation work; retain only compatibility at the published-page boundary.

## Acceptance Criteria

- Web Page is an explicit QuickShare resource type with durable plain HTML, CSS, and JavaScript draft source.
- The shared creation catalog and discovery contract expose the web-page type and its supported plain HTML/CSS/JavaScript options without advertising deferred transpilation or package features.
- Simple authenticated text areas provide a usable authoring experience and validate/store drafts account-safely.
- Web-page creation previews the default final short URL and supports the shared available custom-ID choice that changes it to the handle-scoped URL.
- Publish validates and emits the authored HTML, CSS, JavaScript, and managed assets into a versioned static release bundle without transpilation or package processing.
- `index.html` references content-hashed sidecar JavaScript, CSS, images, fonts, and other managed assets with correct relative or versioned URLs.
- Browser-side JavaScript executes from the static origin, while preview code cannot access editor cookies, tokens, DOM, or privileged APIs.
- TypeScript, transpilation, CSS processing, package imports, and dependency bundling fail clearly and are documented as out of v1 scope.
- Compiler failures never replace a currently published artifact.
- Web-page resources inherit the shared Publish, Unpublish, and Delete lifecycle: Unpublish preserves source while purging delivery output, and confirmed Delete purges delivery output before removing the database resource.
- Relevant editor, compiler, static-output, and QA tests pass.

## Dos

- Produce deterministic manifests and let IF14 own atomic release and cache behavior.
- Keep compilation errors attached to source locations and preserve the prior publication.

## Don'ts

- Do not require one inlined HTML document.
- Do not execute authored code directly in the authenticated editor origin or allow transpilation, package installation, or dependency bundling in version one.

## Open Questions

The exact source validation and managed-asset rules are implementation-plan choices; they must preserve the plain HTML/CSS/JavaScript v1 boundary.
