# Plan — QuickShare: Add plain web-page authoring and versioned asset-bundle compiler

## Goal

Add a catalog-driven plain HTML/CSS/JavaScript resource with managed assets, isolated preview, and a deterministic compiler targeting the existing release-bundle contract.

## Milestones

### Milestone 1 — Register the web-page contract

- [ ] Step 1 — Define durable source and managed-asset validation
  - Achieve: Represent plain HTML, CSS, JavaScript, and managed files without implying TypeScript, transpilation, packages, or dependency bundling.
  - Create: Web-page draft schemas, asset metadata/storage adapters, limits, validation errors, and catalog registration.
  - Modify: XO00 resource persistence only through its existing typed extension points; shared creation picker receives the new type automatically.
  - Delete: Nothing.
  - Touch points: Content types, filenames, hashes, size/count limits, custom-ID creation contract.
  - Validation: Contract tests cover valid sources/assets and clear rejection of forbidden paths, unsafe metadata, unsupported transforms/imports, and ownership violations.
  - Notes: Discovery will serialize these live rules later; do not create a second schema list.

### Milestone 2 — Build simple authoring and isolated preview

- [ ] Step 2 — Add responsive source panels and managed-asset controls
  - Achieve: Let owners repeatedly save plain HTML/CSS/JS and assets using simple text areas and the shared resource lifecycle.
  - Create: Web-page editor container/UI/hook and asset-management components.
  - Modify: Shared library/editor routing and catalog-driven picker display.
  - Delete: Nothing.
  - Touch points: Design system, autosave/manual-save behavior, revision conflicts, default-app feature surface.
  - Validation: Browser tests with `john/john` cover create/save/reopen, asset add/remove, custom URL preview, mobile geometry, and account isolation.
  - Notes: The title says Monaco historically; the refined scope is deliberately simple text areas.

- [ ] Step 3 — Isolate executable preview from editor authority
  - Achieve: Render draft code where it cannot read QuickShare cookies, tokens, parent DOM, or privileged APIs.
  - Create: Sandbox/preview document builder and restrictive communication contract.
  - Modify: Web-page editor preview integration and security policy where required.
  - Delete: Any same-origin executable preview prototype.
  - Touch points: Sandboxed iframe, CSP/sandbox attributes, blob/srcdoc behavior, host-only cookies.
  - Validation: Adversarial browser tests attempt cookie, storage, parent DOM, navigation, and API access; permitted page behavior still previews.
  - Notes: Document that published pages share `s.42go.dev` and are not promised confidential origin storage.

### Milestone 3 — Compile deterministic multi-file bundles

- [ ] Step 4 — Emit hashed CSS, JavaScript, and managed assets
  - Achieve: Validate source and produce `index.html`, manifest, and content-hashed sidecars that resolve from immutable release keys.
  - Create: Web-page compiler, HTML reference injection/rewriting, asset hashing, MIME mapping, and source-located diagnostics.
  - Modify: Catalog compiler registration and shared publish orchestration.
  - Delete: Nothing.
  - Touch points: IF14 completed-bundle validator, relative/versioned URLs, deterministic ordering.
  - Validation: Bundle snapshots, hash determinism, sidecar/reference verification, executable JavaScript, cache reuse, and failure-preserves-prior-publication tests.
  - Notes: No package installation or source transformation.

### Milestone 4 — Verify lifecycle and public delivery

- [ ] Step 5 — Complete local end-to-end acceptance
  - Achieve: Save, publish, republish, switch URL, unpublish, and delete a representative multi-file web page.
  - Create: Web-page API/editor/compiler/public-origin integration tests.
  - Modify: User-facing v1 limitation documentation and task notes.
  - Delete: Test output through publisher purge only.
  - Touch points: Default app seeded users, Nginx, cache headers, confirmation UX.
  - Validation: Focused security/editor/compiler tests, static-origin browser proof on desktop/mobile, and `npm run qa` pass.
  - Notes: Confirm the old publication survives every validation/compiler failure.
