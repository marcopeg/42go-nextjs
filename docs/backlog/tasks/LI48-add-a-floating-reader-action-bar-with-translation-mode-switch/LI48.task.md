# Add a Floating Reader Action Bar with Translation Mode Switch

## Elevator's Pitch

Add a floating bottom action bar to the LingoCafe reading page with left, center, and right slots. On mobile, put an expandable translation FAB in the left slot and the inactive voiceover start FAB in the right slot. On desktop, group the translation FAB beside the voiceover FAB in the right slot. The translation FAB opens labeled word-versus-sentence actions with the current mode checked. While voiceover is active, hide this entire idle bar and show the existing voiceover controls in its place.

## Business Gain

Readers can change translation granularity without opening the full reading-preferences panel, while the bottom controls gain one coherent and extensible layout. The most frequent reading actions stay thumb-reachable and stop floating as unrelated buttons.

## Current State

QQ09 added a device-local sentence-versus-word translation preference in the reader customization panel, with sentence mode as the safe default. The active reader immediately follows that preference. YI11 added a voiceover FAB fixed at the bottom-right while playback is inactive; when playback opens, that FAB is replaced by the full floating playback controls. There is no shared idle bottom-bar layout, no quick translation-mode control on the reading surface, and the voiceover FAB positions itself independently.

## Desired State

Introduce a reusable transparent floating bottom action-bar shell for the LingoCafe reading page. The shell has left, center, and right slots, has no shared background surface, and respects mobile safe-area insets. On mobile, its left slot contains one 56 px circular expandable FAB with a stable, recognizable translation icon while voiceover stays in the right slot. On desktop, the translation FAB moves into the right slot beside voiceover. Tapping the main FAB on touch devices does not change mode immediately; it expands two separately surfaced, labeled actions: `Translate word` and `Translate sentence`. On desktop, mouse hover opens the actions without requiring a click, while click and keyboard activation remain available. The current mode carries a visible tick. Selecting an action updates the established translation-scope preference and closes the action list. The control reads and updates the same canonical reader preference introduced by QQ09, applies immediately, persists through the existing local preference flow, and stays synchronized with the full Reading Preferences panel.

Build the expandable behavior as a reusable FAB primitive rather than reader-only markup. The primitive supports one direct action, multiple ordinary menu commands, or multiple mutually exclusive selectable options. In multi-action mode, activating the main FAB only expands or collapses its actions. Its API exposes an expansion placement/alignment property so actions can emerge above, below, left, or right as appropriate; this reader instance uses top-start on mobile and top-end on desktop. Expanded actions appear as individual, generously sized buttons rather than inside a conventional popover card. They use a simple short fade in and fade out, with animation disabled for reduced-motion users. Desktop hover opening requires a 300 ms dwell to reject incidental pointer travel. Selectable options update their tick immediately, then commit and begin closing after a 300 ms feedback pause; ordinary menu commands remain immediate.

Keep the main FAB visually dominant with the established solid primary/accent fill. Expanded action buttons use semantic neutral surfaces, foregrounds, borders, and restrained elevation: light neutral surfaces in light mode and dark neutral surfaces in dark mode. Do not hard-code white or black. The current mode remains obvious through its tick and accessible selected state; accent may reinforce that small selected marker, but the entire action list must not become a stack of equally heavy primary buttons.

Promote this expandable FAB into the shared LingoCafe design system. The implementation task includes the reusable component, its typed direct-action and multi-action API, placement contract, motion and reduced-motion behavior, keyboard/focus behavior, theme variants, usage documentation in the smallest relevant design-system reference, and any corresponding starter asset required by that design-system package.

The right slot contains the existing start-voiceover FAB and preserves its current capability gating and start behavior. The center slot is available for layout balance and future reader actions; it may remain empty in this task.

The idle floating bar is shown only while voiceover/playback is closed. As soon as voiceover opens, the whole idle bar disappears and the existing floating voiceover options/player bar substitutes for it. Closing voiceover restores the idle bar with the current translation mode still selected. If one slot's action is unavailable, the shell must remain visually stable and must not imply that the unavailable action can be used.

## Definition of Success

On the LingoCafe reading page, a mobile reader can change word/sentence translation mode from a bottom-left floating control and start voiceover from bottom-right. A desktop reader gets both controls grouped at bottom-right and can reveal translation choices on hover. Neither surface shows idle controls competing with the active voiceover bar. The quick control and the full preferences panel always represent one shared persisted setting.

## Additional Context

The operator-supplied mobile reference shows the current green voiceover FAB floating at the bottom-right of the reading page. The requested composition mirrors a translation control at bottom-left and turns both into children of one floating bar. This task builds on the completed QQ09 translation-scope behavior and YI11 playback behavior; it should reorganize and expose those controls rather than create new translation or playback state.

## Assumptions

- Sentence translation remains the default for new, missing, malformed, and legacy preferences.
- The quick control changes the existing device-local translation-scope preference; it does not add profile or server persistence.
- The active playback/voiceover controls remain the existing playback bar and replace the idle action bar for the full time playback is open, including paused and delay states.
- The center slot may be empty initially.
- The floating bar is a transparent positioning shell; each populated slot owns its own floating control surface.
- The collapsed translation control is one circular FAB with one stable translation icon, not a segmented control or a mode label.
- The selected translation mode is shown by a tick on the corresponding labeled expanded action.
- The expandable FAB is intended to be a reusable UI primitive that can perform one direct action or reveal multiple actions.
- The main FAB uses the solid primary/accent treatment; expanded actions use lighter semantic neutral treatments.
- The expandable FAB and its stable contract belong to the shared LingoCafe design system.
- The bottom action bar is a reader-level layout component that places translation opposite voiceover on mobile and beside voiceover in the desktop right slot.
- Translation and voiceover actions retain their existing feature and capability gates.

## Constraints

- Use one canonical translation-scope value and the existing reader-preference storage, sanitization, defaults, and update flow.
- Do not fork translation state between the quick control and the Reading Preferences panel.
- Move the existing inactive voiceover start action into the right slot without changing its speech capability gate, analytics, starting context, or accessible name unless deliberate copy refinement requires it.
- Hide the complete idle action bar whenever playback is open; do not layer it behind or beside the playback controls.
- Respect bottom, left, and right safe-area insets and keep controls reachable without obscuring reader content or native browser chrome.
- Keep the slots geometrically stable when the center is empty or an action is unavailable.
- Use semantic, keyboard-accessible controls with a visible selected translation mode and suitable accessible labeling.
- Use a recognizable Lucide translation/languages icon or an equally clear established translation symbol for the collapsed FAB; do not invent an ambiguous custom glyph when a proven icon exists.
- In multi-action mode, the main FAB only opens and closes the available actions; it must not also trigger a default action.
- Provide a configurable expansion placement/alignment API; the reader translation instance expands top-start on mobile and top-end on desktop.
- Render expanded actions as independent minimum-44 px labeled buttons, not as rows inside a shared popover card.
- Make expanded actions generously sized and highly legible while keeping their surface neutral and subordinate to the main primary FAB.
- Use semantic theme tokens for expanded action backgrounds, foregrounds, borders, focus rings, and shadows; do not hard-code white/black pairs.
- Use accent sparingly for the current-mode tick or restrained selected treatment rather than filling every expanded action with primary green.
- Use a short fade in/out without slide, scale, stagger, or spring motion, preserve stable reader geometry, and respect `prefers-reduced-motion`.
- Open the desktop action list on mouse hover, keep it open while the pointer crosses between the FAB and its actions, and preserve tap-driven behavior on touch devices.
- Delay desktop hover opening by 300 ms so crossing the FAB does not flicker the action list.
- For selectable options, update the visible and semantic selection immediately, then delay the callback and close by 300 ms; do not apply that delay to ordinary submenu commands.
- Suppress focus treatment on the transparent menu container while preserving visible focus rings on its actionable children.
- Manage focus correctly: opening exposes and focuses or makes available the actions, Escape and genuine outside interaction close the list, and focus returns to the main FAB as appropriate.
- Add the implemented expandable FAB pattern to the smallest relevant LingoCafe design-system reference and update an affected starter asset when the design-system package requires one.
- Preserve translation authorization, validation, caching, highlighting, popover, and dismissal behavior.
- Preserve voiceover playback, pause, seek, settings, highlighting, guided scrolling, and close behavior.
- Run npm run qa and visually verify the reader through the LingoCafe public test tunnel on a mobile viewport near 390px and on desktop.

- The inactive LingoCafe reader renders one floating bottom action-bar shell with left, center, and right slots.
- On mobile, the translation mode control occupies the left slot and the start-voiceover FAB occupies the right slot.
- On desktop, the translation mode control occupies the right slot beside the start-voiceover FAB.
- The positioning shell has no shared visible background; its populated controls appear as independent floating elements.
- The collapsed translation mode control is one 56 px circular FAB rather than a segmented control or persistent pair of buttons.
- The collapsed FAB uses one stable, recognizable translation icon.
- The collapsed FAB retains the established solid primary/accent fill.
- Activating the main translation FAB opens its actions without changing the current translation mode.
- The expanded UI shows separate `Translate word` and `Translate sentence` buttons above the FAB, aligned top-start on mobile and top-end on desktop.
- The currently selected mode has a visible tick and an accessible selected-state announcement.
- Expanded actions use large, independently surfaced, theme-aware neutral buttons; they are not all filled with the main FAB's primary color.
- Light and dark reader themes produce suitable neutral action surfaces without hard-coded white or black styling.
- Selecting either action updates the mode, closes the action list, and returns focus appropriately.
- The reusable expandable FAB supports a direct-action configuration and a multi-action configuration.
- The reusable expandable FAB exposes an expansion placement/alignment property; this reader instance uses responsive top-start and top-end placement.
- Expanded actions use a short fade in and fade out without slide, scale, stagger, or spring effects.
- Reduced-motion preference disables the fade without hiding state changes.
- Desktop mouse hover opens the translation actions without requiring a click and moving between the FAB and action cluster does not dismiss them prematurely.
- Desktop mouse hover must remain over the trigger for 300 ms before the translation actions open.
- Mobile and other touch input use tap to open and close the translation actions.
- Selecting a translation option moves the visible and accessible tick immediately, then applies the setting and starts closing after 300 ms.
- Multi-action FABs without a selected action operate as immediate ordinary command menus without ticks or selection delays.
- The transparent menu container never displays a first-open outline or focus ring; keyboard focus remains visible on the focused action.
- Escape, outside interaction, selecting an action, playback opening, and reader navigation close the expanded action list safely.
- The expandable FAB is exported as a shared reusable LingoCafe component with typed direct-action, multi-action, and placement options.
- The final reusable component contract is documented in the LingoCafe design system and any required corresponding starter asset is updated.
- The center slot may render empty without shifting the left and right actions away from their edges.
- The translation control clearly communicates whether word or sentence mode is selected.
- Changing the floating control takes effect immediately for the next translation interaction.
- Changing the floating control updates the same value shown in the full Reading Preferences panel, and changing the panel updates the floating control.
- The selected mode persists and restores through the existing local reader-preference mechanism.
- Missing, invalid, or legacy stored values still resolve to sentence translation.
- Starting voiceover from the right slot opens the existing playback controls and removes the complete idle floating bar from the rendered interaction surface.
- The idle action bar remains hidden while playback is playing, delayed, paused, or otherwise open.
- Closing the playback controls restores the idle bar with the current translation mode selected.
- When voiceover is unavailable, no unusable voiceover button is shown; the remaining bar content stays intentionally aligned.
- When translation is unavailable, no unusable translation-mode control is shown; the remaining bar content stays intentionally aligned.
- The bar respects device safe areas and does not cause horizontal overflow at a viewport near 390px wide.
- The controls remain keyboard operable and expose the active translation mode to assistive technology.
- Existing word/sentence translation and voiceover behavior do not regress.
- npm run qa passes.

## Dos

- Do treat the floating bar as the shared idle container for bottom reader actions.
- Do keep left and right placement visually opposed on mobile and group both actions in the right slot on desktop.
- Do reuse the established translation and playback controllers.
- Do use explicit text labels and a tick in the expanded actions so mode selection never depends on decoding two similar icons.
- Do keep the solid primary treatment on the main FAB and use semantic neutral surfaces for its expanded actions.
- Do verify the transition between idle, playing, paused, and closed playback states.

## Don'ts

- Don't leave the voiceover FAB independently fixed outside the new idle bar.
- Don't show the translation switch underneath, beside, or above active voiceover controls.
- Don't create a second translation preference key or separate in-memory mode.
- Don't redefine word/sentence translation semantics or voiceover playback behavior.
- Don't fill the center slot with a new feature in this task.
- Don't put the two translation choices inside a generic rectangular popover panel if the intended speed-dial treatment is confirmed.
- Don't render every expanded action as another solid primary/accent button.
- Don't hard-code white expanded actions for light mode or black expanded actions for dark mode.
