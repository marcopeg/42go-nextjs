# Execution Notes — Add a Floating Reader Action Bar with Translation Mode Switch
**Task**: ./LI48.task.md
**Plan**: ./LI48.plan.md

## Decisions

- Use Radix Dropdown Menu as the accessibility and positioning engine for the non-modal expandable FAB.
- Keep the speed dial outside the shared Modal abstraction because it has no scrim, dialog surface, or trapped-focus contract.
- Use the existing `readerTranslationScope` and `updateReaderTranslationScope` flow; add no preference state or storage key.
- Pass only reader CSS custom properties through the Radix portal so expanded actions inherit reader colors without accidentally creating a shared panel background.
- Key each reader action bar by page ID so navigation closes any open speed dial without adding a second state controller.
- Open translation actions on mouse hover at desktop widths while preserving tap activation for touch input and normal keyboard behavior.
- Use a simple fade for opening and closing actions; remove the original directional spring and stagger treatment.
- Keep translation opposite voiceover on mobile, but group translation immediately beside voiceover in the desktop right slot.
- Use a 300 ms desktop hover-intent delay before opening, while retaining the short close bridge between the trigger and portaled actions.
- In selectable mode, optimistically move the Radix radio selection and visible tick, then commit the callback and close 300 ms later. In ordinary command-menu mode, preserve immediate callbacks and normal dismissal.
- Remove the transparent Radix content container's focus-visible ring so first opening cannot draw a rectangle around the complete action cluster; individual actions retain their focus rings.
- Mobile Safari still painted first-focus chrome after a full reload despite the utility reset. The portaled transparent container now enforces no border, outline, box shadow, or WebKit tap highlight through inline styles while leaving option-level focus presentation intact.

## Problems Encountered

- Passing the complete reader style object into the portaled action content would have added an inline reader background to the otherwise transparent menu container. The integration now filters the object down to `--reader-*` variables only.
- The public LingoCafe tunnel accepted the documented `john` credentials, but the account is stopped by mandatory profile and consent onboarding before the bookshelf. Live reader interaction was not forced because doing so would mutate consent/profile data.
- The mobile and desktop reader surfaces used the page ID for both the scrolling content and floating action bar sibling keys, producing React's duplicate-key warning. The action-bar keys now include unique desktop/mobile prefixes while retaining navigation remount behavior.
