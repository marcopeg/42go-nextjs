# Add the LingoCafe questionnaire content and learner-state schema

## Elevator's Pitch

Create the reader-owned relational contract for book questionnaires, learning items and page links, immutable question content, answer sets, learner rounds, answers, scores, and learning-item FSRS state.

## Business Gain

The reader gains an integrity-safe runtime foundation that preserves historical results while content evolves and cleanly separates publisher-owned content from learner-owned history.

## Current State

The `lingocafe` schema has books/pages and reading state but no questionnaire tables or standalone importer contract.

## Desired State

Add an additive Knex migration and `QUESTIONNAIRES_DATA_MODEL.md`; normalize one questionnaire per book, variable question pools, learning-item/page relations, single-select content with response-mode extensibility, immutable revisions identified by content digest, answer sets/options, 10-question rounds with generic size fields, answer choices, scores, and per-user/per-learning-item FSRS-6 state. Round items retain the exact question revision and answer set rendered. Version one maps a wrong result to `Again` and a correct result to `Good`, persists the applied FSRS rating, and leaves `Hard`/`Easy` available to later modes. Define retention, withdrawal, foreign keys, indexes, account erasure, and safe publisher ownership.

## Definition of Success

The migration and contract can represent the pilot, reject invalid cross-book relations, preserve old revisions referenced by answers, and support downstream publisher and service tasks without repository-external knowledge.

## Additional Context

Depends on the `books` package contract in [CM87](../../../../../books/docs/backlog/tasks/CM87-define-the-standard-book-target-questionnaire-package/CM87.task.md) for source semantics. It does not build APIs or learner UI.

## Assumptions

PostgreSQL/Knex remain authoritative. Content publication never writes user-state tables. First release uses single-select and FSRS-6 at 0.90 desired retention. Questions are retrieval prompts for learning items, so future prompt variants reinforce one concept-level memory state instead of creating independent schedules.

## Constraints

Do not amend historical migrations, store the whole model as opaque JSON, or cascade content reconciliation into learner history.

## Acceptance Criteria

- [x] Additive migration creates constrained content and user-state tables.
- [x] One questionnaire is tied to one book while its pool size is variable.
- [x] Learning-item page links enforce the exact composite book/page identity.
- [x] Immutable question revisions and answer sets preserve historical rendering.
- [x] Round and answer tables support generic size while version one uses 10.
- [x] Per-user per-learning-item FSRS state stores scheduler/version/parameters and due-state inputs.
- [x] Account erasure deletes/reports questionnaire learner state.
- [x] Standalone contract documents safe import, withdrawal, and ownership.
- [x] Migration and constraint tests pass without changing existing data.

## Dos

Use explicit keys, checks, indexes, and source audit fields.

## Don'ts

Do not add routes, adaptive selection, or frontend work here.

## Open Questions

No blocking questions remain. Stable content identities are separated from immutable question revisions; historical round items reference the exact revision and answer set shown. FSRS state belongs to learning items, and binary results persist their derived four-grade rating so later interaction modes remain compatible.
