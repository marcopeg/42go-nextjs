# Plan — QuickShare: Add extensible mini-app templates and an initial links page

## Goal

Add a versioned maintained-template framework and an accessible links-page template that uses the existing resource, editor, compiler, and publisher contracts without introducing a second publishing path.

## Milestones

### Milestone 1 — Establish the maintained template registry

- [x] Step 1 — Define stable template/version contracts
  - Achieve: Register template metadata, configuration validation, editor form definition, preview, renderer, upgrade rules, and discovery-ready descriptors in one typed source.
  - Create: QuickShare template registry/types, version resolver, schema/form contract, render interface, and upgrade result types.
  - Modify: Shared resource catalog so template creation choices are contributed from the registry.
  - Delete: Nothing.
  - Touch points: Stable template IDs, semantic/integer versions, JSON-schema-compatible validation, pinned instance versions.
  - Validation: Registry uniqueness, deterministic lookup, serialization, invalid configuration, missing version, and no-silent-upgrade tests.
  - Notes: Application code owns renderers; account data owns configuration.

- [x] Step 2 — Implement explicit template upgrades
  - Achieve: Preview, validate/migrate, and accept a version upgrade without changing the draft or publication when validation fails.
  - Create: Upgrade service and comparison/confirmation DTOs.
  - Modify: Template instance domain service and revision history integration.
  - Delete: Nothing.
  - Touch points: Optimistic revisions, source-version preservation, migration diagnostics.
  - Validation: Pinned old instances render deterministically after a catalog update; failed upgrade is non-mutating; accepted upgrade creates a normal new draft revision.
  - Notes: Publishing never upgrades implicitly.

### Milestone 2 — Deliver the initial links-page template

- [x] Step 3 — Define and render links-page configuration
  - Achieve: Support profile image, display name, biography, ordered links, and documented visual options with accessible static output.
  - Create: Version-one links template schema, defaults, form definition, preview, deterministic renderer, styles/assets, and catalog metadata.
  - Modify: Template registry registration.
  - Delete: Nothing.
  - Touch points: URL validation, ordered collections, alt text, color contrast, keyboard/focus states, responsive output.
  - Validation: Schema boundary tests, sanitization/XSS tests, deterministic bundle snapshots, accessibility checks, and valid IF14 manifest output.
  - Notes: User configuration cannot execute code.

### Milestone 3 — Add guided authoring

- [x] Step 4 — Integrate template choices into creation and editing
  - Achieve: Show maintained templates under `+ New Share`, create pinned instances, guide configuration/reordering, and retain the shared URL and lifecycle behavior.
  - Create: Template picker presentation, schema-driven form controls, links editor, reorder control, preview, and upgrade UI.
  - Modify: Shared library/editor routing and default/QuickShare feature exposure only as needed.
  - Delete: Any hard-coded template list outside the registry.
  - Touch points: Mobile layout, drag/keyboard reorder, image handling, custom-ID availability, draft revisions.
  - Validation: Seeded `john/john` browser flow covers create/edit/reorder/save/reopen/preview and `admin/admin` isolation; picker and future discovery read the same registry.
  - Notes: Use plain guided controls, not a code editor.

- [x] Step 5 — Publish through the shared bundle pipeline
  - Achieve: Compile the pinned template/config revision into a complete bundle and reuse Publish, Unpublish, Delete, identifier-switch, and purge orchestration.
  - Create: Template compiler adapter and renderer diagnostics.
  - Modify: Shared compiler registry/publish service.
  - Delete: Nothing.
  - Touch points: QU22 asset-bundle conventions, IF14 validation/activation, YW90 confirmations.
  - Validation: Publish/update/URL-switch/unpublish/delete tests; renderer/upgrade failure preserves current public output.
  - Notes: Never store rendered output as the editable source of truth.

### Milestone 4 — Prove extensibility and quality

- [x] Step 6 — Complete template acceptance and extension proof
  - Achieve: Demonstrate that another maintained template could be added through registration and implementation alone, without core schema or publisher changes.
  - Create: Template contract tests, links-page visual fixtures, and maintainer extension documentation.
  - Modify: Task notes and focused test scripts.
  - Delete: Any temporary demonstration registration not intended for release.
  - Touch points: Default app, QuickShare app, static Nginx origin, mobile/desktop, light/dark authoring UI.
  - Validation: Focused registry/render/UI/publication tests, accessibility/visual review, and `npm run qa` pass.
  - Notes: Landing-page and curriculum templates remain future work.
