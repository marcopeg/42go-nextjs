# Clarify Round v2 — Install Context, UI, and Access

## Questions

### 1. Which Quicklist paths should resolve to the same per-list install target?

Recommended: every validated `/quicklists/<uuid>` route and its nested pages, such as `/info`, resolve to the same stable app ID and canonical `startUrl: /quicklists/<uuid>`. This means Add to Home Screen works consistently from the list or its settings without launching back into the settings page.

### 2. What installation UI should Quicklist version one expose?

Recommended: add an **Install this list** action to the existing list Info page using the reusable 42Go install component. Chromium receives the native prompt when available; iOS/iPadOS and Safari receive concise manual instructions. Native browser Add to Home Screen continues to work directly from any matched list route.

### 3. Who may receive and install a list-specific manifest?

Recommended: any authenticated owner or collaborator who can currently open the list. The manifest resolver applies the same authorization as list access and returns 404 otherwise. Installation does not grant or preserve access after collaboration is revoked.

## Answers

### 1.

Yes. Each list is a virtual app. Every validated route for that list resolves to the same stable installation identity and canonical list launch URL.

### 2.

Yes. Add **Install this list** to the existing list Info page using the reusable 42Go installation UI.

### 3.

Anyone with current access to a list may install it, including owners and collaborators. Normal authorization still applies on manifest resolution and every later launch.

## Resolution Summary

- Every Quicklist list is one virtual app, and all its matched subroutes resolve to the same identity and canonical detail-page launch URL.
- The existing Info page receives the reusable **Install this list** action; native Add to Home Screen also works from every matched list route.
- Any owner or collaborator with current list access may resolve and install the virtual app. Revoked access blocks future manifest resolution and launches.
- No product-level clarification remains; technical uncertainties are explicit spike and device-test work for planning.
