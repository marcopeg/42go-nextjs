# LingoCafe Events Analytics Export

## Historical Summary

- A decision is made for the durable local analytics storage formats: immutable CSV batches for human-readable access and immutable Parquet batches for Python/DuckDB analysis. - A new agent skill exists for downloading LingoCafe events from a database URL supplied through an environment variable. - The skill can pull only new event rows since the last successful local dump using a durable cursor based on `(created_at, id)`. - Downloaded data is stored locally in a deterministic gitignored repository folder, such as `.local/lingocafe-analytics`. - Each export run writes one paired CSV file and one paired Parquet file with the same batch ID. - The accepted default layout is `.local/lingocafe-analytics/events/csv/`, `.local/lingocafe-analytics/events/parquet/`, `.local/lingocafe-analytics/events/state.json`, and `.local/lingocafe-analytics/events/manifest.jsonl`. - The first version exports raw `lingocafe.events` only; signup analysis should come from signup events instead of offline `auth.users` snapshots. - The local filesystem archive, not PostgreSQL, becomes the durable source of truth for historical event analytics. - The export process is read-only against PostgreSQL and does not drop, delete, truncate, or clean up source event rows. - The process supports repeated runs without duplicating rows or corrupting previous local data. - If the script dies before a batch completes, rerunning should overwrite the incomplete batch rather than advancing the cursor or creating duplicate exported records. - The task produces a `{id}.output.md` artifact documenting the final decision, storage layout, cursor semantics, commands, and example analysis workflow.
