# Add CSS-column pagination as an optional LingoCafe reading mode

## Elevator's Pitch

Let readers switch between the existing vertical scrolling experience and a Kindle-like horizontal paginated experience. Use browser-native CSS columns for the first version and retain the existing blue in-chapter progress bar.

## Business Gain

Offer a focused screen-by-screen reading experience while retaining the familiar scrolling mode and minimizing custom layout code and new dependencies.

## Current State

- A stored book page is a content section, often a chapter, rendered as vertically flowing interactive Markdown.
- BookPageReader provides sentence and word targets for translation and playback. BookReaderSurfaces owns reader chrome and navigation.
- The blue progress bar at the bottom of the reader title/header block shows progress within the current content section. Position restoration currently uses vertical scroll memory and progress percentages.
- The existing Page X of Y label counts stored sections, not computed screen pages.

## Desired State

- Expose a reading-experience option in reader preferences labeled Vertical scroll and Paginated (experimental). Vertical scroll is the default; pagination requires explicit user activation.
- Store the selected mode in localStorage for the current browser/origin, shared across books and independent of theme. Missing, invalid, or unavailable storage defaults safely to vertical scroll; a user can still choose a mode for the current session when persistence is unavailable.
- Keep vertical reading available. In paginated mode, flow the current section into fixed-height CSS columns sized to the available reading viewport and move horizontally by one screen.
- Keep the existing blue in-chapter progress bar in its current location at the bottom of the title/header block. Derive its progress from the horizontal reading position in paginated mode.
- Preserve chapter navigation, contents, translation, selection, reader typography/themes, and audio playback across both modes.
- In paginated mode, a forward turn from the final screen opens the next chapter at its first screen. A backward turn from the first screen opens the previous chapter at its last screen. Apply this consistently to swipes, arrow buttons, and keyboard navigation; stop at book boundaries without wrapping or automatically marking the book read.
- Keep the reading location when switching mode, changing typography, resizing, rotating, or reopening the reader. Use a content anchor (section identity plus sentence/text offset) for local restoration across layout changes, rather than persisting a screen index as the durable position. Respect explicit navigation/URL progress first, use a valid local anchor for same-section restoration, and fall back to existing progress percentages when an anchor is absent or invalid. Anchor storage format and DOM mapping are implementation-plan decisions; no new server profile setting is required.
- Skip computed page-number displays, chapter screen-count labels, whole-book page totals, and total-page estimation in this version.

## Definition of Success

A reader can choose either mode, read a complete chapter without missing or clipped content, follow chapter progress in the same blue bar, and continue using translation and audio without losing their place.

## Additional Context

- Operator decisions: introduce a vertical/paginated switch; implement version one with CSS columns; defer page numbers; retain the current blue in-chapter progress bar below the title block.
- CSS columns should own line wrapping and fragmentation; a small controller can own horizontal page movement and location mapping. CSS specification: https://www.w3.org/TR/css-multicol-1/
- Primary code: src/app/(app)/(lingocafe)/books/_components/BookPageReader.tsx, BookReaderSurfaces.tsx, BookReaderPage.tsx, reader-scroll-target.ts, reader-scroll-memory.ts, reader-preferences.ts, useReaderPreferences.ts, and reader-playback/.
- Coordinate with SE90, which changes mobile vertical scroll ownership for native Safari chrome behavior. Horizontal pagination is an intentional mode-specific layout and must not undo the vertical-mode work. Do not assume horizontal swipes will collapse Safari browser chrome.
- Round 1 confirmed seamless chapter transitions in both directions. Round 2 confirmed experimental opt-in pagination and localStorage persistence.
- Future direction only: after the experience matures, consider moving the mode preference into the profile and potentially making pagination the default. This requires a separate decision and is outside this task.
- Updated operator decision: in paginated mode, replace stored-page labels with a tappable chapter position derived from chapter-kind contents entries. Parts and other sections show their prefix/title. Combine arrows, translation mode, chapter position, and audio into one bottom row. Retain position-based progress semantics. In paginated mode, the first screen is 0%, the last is 100% when more than one screen exists, and a single-screen chapter remains 0%, matching the current no-scroll-range behavior. The bar indicates position, not proof of reading or automatic completion.

## Assumptions

- Scope is the LingoCafe book reader; conversation-reader pagination is not included.
- Confirmed default: vertical scroll until explicit activation of experimental pagination. Persist this opt-in locally, using the existing reader-preference store.
- Initial implementation scope: one reading column per screen on mobile and desktop, preserving the established maximum text width. Two-page spreads are deferred.
- Stored section IDs and chapter content remain unchanged; computed screens are a presentation concern.

## Constraints

- Use CSS columns for initial pagination; do not introduce an EPUB conversion pipeline or ebook rendering engine.
- Do not calculate or preload the whole book solely to estimate page totals. Internal current-section geometry needed for navigation and progress remains in scope.
- Preserve server authorization, translation identifiers, chapter routes, and existing progress override semantics.
- Keep temporary overlays and floating controls outside text fragmentation where needed, with correct safe-area spacing and no text occlusion.
- Follow the LingoCafe design-system skill and relevant Next.js local documentation during implementation.

## Acceptance Criteria

- [x] Reader preferences offer an accessible Vertical scroll / Paginated (experimental) selector. New or unset preferences use vertical scroll; pagination activates only after explicit selection.
- [x] The chosen mode persists across reloads and books in localStorage, independently of theme. Invalid/missing storage falls back to vertical, and unavailable storage does not break reading or session-only selection.
- [x] This release adds no profile synchronization and does not promote pagination to the default.
- [x] Vertical mode retains its existing reading, navigation, and progress behavior.
- [x] Paginated mode flows complete chapter content through CSS columns and supports horizontal screen-by-screen navigation on mobile and desktop, including keyboard controls.
- [x] The blue in-chapter progress bar remains directly below the title/header block. In paginated mode, settled screen positions map from 0% on the first screen to 100% on the last screen for multi-screen chapters; single-screen chapters show 0%, preserving existing no-scroll-range semantics. Navigation resets it for the new chapter and never implies automatic book completion.
- [x] No computed page-number display, whole-book page count, or estimated total is introduced.
- [ ] Mode switching, typography changes, viewport resizing/rotation, overlay dismissal, and reopening preserve the content location without unexpected chapter jumps.
- [ ] Sentence/word translation and text selection work when text spans column boundaries; swiping does not accidentally trigger translation or dismiss the reader.
- [ ] Audio highlighting, sentence following, and chapter continuation work in both modes; paginated playback reveals the screen containing the active text.
- [ ] Forward navigation from the last screen opens the next chapter at its first screen; backward navigation from the first screen opens the previous chapter at its last screen. Swipes, arrow buttons, and keyboard actions share this behavior.
- [x] Book boundaries stop navigation without wrapping or automatically marking the book read; Contents remains available for explicit chapter jumps.
- [ ] Long paragraphs, headings, lists, and other supported Markdown content remain readable without clipped text or accidental empty screens.
- [ ] Mobile Safari and installed/PWA checks account for changing viewport height and safe areas; the existing vertical scroll contract is preserved.
- [ ] Verify approximately 390, 768, and 1280 px widths, reader themes, keyboard access, reduced motion, and font-size extremes; run npm run qa after implementation.

## Dos

- Reuse the existing interactive Markdown renderer and preference controls.
- Measure after layout and fonts settle, and recompute on relevant viewport/typography changes without resetting the reading location.
- Distinguish content-section identity from transient screen positions in naming and state.
- Add focused regression coverage for location restoration, progress, and navigation where meaningful.

## Don'ts

- Do not split source Markdown into arbitrary character or word chunks to construct pages.
- Do not treat existing chapter-count labels as screen-page counts.
- Do not add ornamental page-curl animation, two-page spreads, or unrelated reader redesign.
- Do not expand this draft into whole-book measurement or content-format migration.

## Open Questions

None blocking planning. The plan must specify anchor serialization/invalidation, geometry measurement, and integration with existing progress override rules. Paginated mode shows chapter position, excluding non-chapter sections; no screen-page numbering is introduced.
