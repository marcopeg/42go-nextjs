# Execution Notes — QuickShare: Establish isolated app, account onboarding, and data model
**Task**: ./XO00.task.md
**Plan**: ./XO00.plan.md

## Decisions

- QuickShare has its own `quickshare` PostgreSQL schema. Every product row carries `app_id`; the default app is deliberately a separate tenant for local seeded-user testing.
- Publishing remains a server-only contract in this task. Drafts and release metadata are authoritative database state; no delivery output is created here.
- `resource_route_claims` reserves both candidate and published routes, preventing collisions while a published resource waits to switch identifiers. Short codes are globally unique; custom claims are account-scoped because only the production `quickshare` tenant can project to `s.42go.dev`.
- Published custom-handle changes require a `QuickShareHandleRenameCoordinator`; the account service deliberately refuses to commit such a change until IF14 supplies the atomic delivery-folder rename.

## Problems Encountered

- The repository-local backlog skill shim is absent. The canonical installed backlog-execute transition script was used instead.
- The available in-app browser had no connected browser. Route/host verification used the running local server instead: localhost resolved `default`, a `quickshare.42go.dev` Host header resolved `quickshare`, `/quickshare` rendered on both expected app surfaces, and the unauthenticated API returned 401.
