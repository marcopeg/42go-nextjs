# Plan — Restore Native Safari Browser-Chrome Collapse Across LingoCafe Mobile Reading Surfaces

## Goal

Move the three targeted LingoCafe mobile surfaces to root-document vertical scrolling so Safari can manage its native browser chrome, while preserving the existing desktop scroll model and reader behavior.

## Milestones

### Milestone 1 — Restore document flow for mobile library and details

- [x] Step 1 — Remove the Conversations library's contained mobile scroller
  - Achieve: Let the root document own mobile vertical scrolling and reset it on library navigation.
  - Create: Automated contract coverage for the mobile shell behavior.
  - Modify: `ConversationLibraryShell` only; leave `AppLayout.containedMobileScroll` available to unrelated consumers.
  - Delete: The Conversations call site's contained-scroller dependency.
  - Touch points: Mobile toolbar, bottom navigation, route transitions, safe-area padding.
  - Validation: Source/unit contracts plus 390 px and desktop regression checks.
  - Notes: Do not change Backoffice Users behavior.

- [x] Step 2 — Put mobile Book Details into normal document flow
  - Achieve: Preserve the immersive mobile treatment, sticky header, and reading action without a fixed viewport or nested vertical scroller.
  - Create: Mobile flow and responsive-handoff coverage.
  - Modify: Mobile Book Details layout classes and content spacing.
  - Delete: Fixed `inset-0`, `100dvh`, and nested `overflow-y-auto` ownership from the route surface.
  - Touch points: Mobile back header, BookInfoContent, desktop AppLayout rendering.
  - Validation: 390 px, 768 px, and 1280 px geometry; no horizontal overflow.
  - Notes: Desktop component and spacing remain unchanged.

### Milestone 2 — Introduce a shared reader scroll target

- [x] Step 3 — Model document and element scrolling behind one typed contract
  - Achieve: Provide shared metrics, viewport bounds, event subscription, querying, and scrolling for mobile document and desktop element targets.
  - Create: `reader-scroll-target` utility and focused unit tests.
  - Modify: Reader progress/restoration and playback consumers to use the contract.
  - Delete: Duplicated direct assumptions that every reader target is an independently scrolling element.
  - Touch points: Progress basis points, restoration, header title state, sentence focusing, visibility, playback continuation.
  - Validation: Unit tests for top/middle/end progress, bounded restore, document viewport geometry, and element parity.
  - Notes: The document target must account for the sticky 64 px mobile reader header.

### Milestone 3 — Make the mobile book reader route-level

- [x] Step 4 — Remove the body-locking reader Modal on mobile only
  - Achieve: Render the mobile Reader in normal document flow while retaining the full-screen Modal and element scroller on desktop.
  - Create: A responsive desktop-only Modal boundary if needed.
  - Modify: Reader route composition and mobile surface layout.
  - Delete: Mobile nested `overflow-y-auto` and body lock from the primary reader surface.
  - Touch points: Sticky header, fixed playback/FAB controls, swipe navigation, page transitions, nested Preferences and Contents modals.
  - Validation: Mobile document scroll, desktop containment, overlay close restoration, safe-area offsets, PWA smoke behavior.
  - Notes: Temporary overlays continue using the shared Modal; no bespoke overlay is introduced.

- [x] Step 5 — Preserve reader state across both scroll modes
  - Achieve: Keep URL/server progress precedence, one-time restoration, idle/final saves, playback auto-scroll, manual-scroll detection, and page continuation correct.
  - Create: Regression tests for scroll-target selection and integration contracts.
  - Modify: Reader lifecycle effects and playback scrolling.
  - Delete: Direct mobile `scrollRef.current.scrollTop` assumptions.
  - Touch points: Progress save timers, restored-page key, header title mode, playback focus, overlay scroll locking/restoration.
  - Validation: Automated tests plus manual top/middle/end restoration checks.
  - Notes: Desktop metrics must remain byte-for-byte equivalent in behavior where practical.

### Milestone 4 — Verify and document the result

- [x] Step 6 — Run automated and visual regression checks
  - Achieve: Confirm mobile root scrolling, desktop preservation, responsive handoff, themes, and controls.
  - Create: Execution notes with device-dependent limitations.
  - Modify: Plan checkboxes and task notes only after evidence is collected.
  - Delete: None.
  - Touch points: Conversations, Book Details, Book Reader, Books, Profile, Backoffice Users.
  - Validation: Targeted tests, `npm run qa`, browser checks near 390/768/1280 px, and physical-iPhone/PWA checks when available.
  - Notes: Desktop emulation cannot prove Safari browser-chrome collapse; record that boundary explicitly.

### Milestone 5 — Close the conversation-reader gap reported on device

- [x] Step 7 — Move the mobile conversation reader onto the document scroller
  - Achieve: Give conversation reading the same native mobile scroll ownership as the book reader while preserving its desktop full-screen Modal.
  - Create: Conversation-reader source-contract coverage in the mobile-scroll regression test.
  - Modify: Conversation progress restoration/saving, playback targeting, sticky header composition, and Preferences scroll restoration.
  - Delete: The always-open mobile route Modal and mobile nested `overflow-y-auto` ownership.
  - Touch points: Conversation reader header, progress, playback, Preferences, category return path, and desktop containment.
  - Validation: Targeted tests plus live 390 px category/subcategory/list/reader geometry and 1280 px reader geometry.
  - Notes: The operator's iPhone screenshot exposed this route as the remaining nested-scroll surface.

- [x] Step 8 — Make short intermediate conversation lists Safari-collapse capable
  - Achieve: Let category and conversation-list routes provide enough root-document travel for Safari to collapse its chrome even when only a few rows are present.
  - Create: Regression contracts for a deterministic mobile root-scroll runway.
  - Modify: The shared Conversation Library wrapper minimum height while preserving its previously working transition wrapper and bottom safe-area spacer.
  - Delete: None; the speculative wrapper change was reverted after the operator reported a regression on the root page.
  - Touch points: Root category, subcategory, starred, and conversation-list routes through one shared shell.
  - Validation: Exact reported route at 390 px and 1280 px, focused tests, lint, and production build.
  - Notes: Fixed-size spacing was insufficient: the reported three-row list had 44 px of scroll, while short category and Starred pages had only 1 px. The shared wrapper now guarantees at least 6rem of mobile root-document travel.
