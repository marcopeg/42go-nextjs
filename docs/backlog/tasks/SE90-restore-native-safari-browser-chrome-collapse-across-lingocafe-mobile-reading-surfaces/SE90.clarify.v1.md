# Clarify Round v1 — Restore Native Safari Browser-Chrome Collapse Across LingoCafe Mobile Reading Surfaces

## Questions

### 1. What is the minimum supported iOS/Safari version for this work?

### 2. Should `containedMobileScroll` remain available for dense backoffice pages, with this task only removing it from the three LingoCafe reading surfaces?

### 3. Should desktop Reader retain its current element-level scroller while mobile switches to document scrolling?

## Answers

### 1.

Support the current and previous major iOS/Safari generations. Older versions receive a usable document-scroll experience where practical, but browser-chrome animation details outside that window are not release blockers.

### 2.

Yes. Keep `containedMobileScroll` available for dense backoffice pages. This task removes or bypasses it only on the three named LingoCafe mobile reading surfaces and performs a regression audit of existing consumers without redesigning them.

### 3.

Yes. Preserve the desktop Reader's current element-level scroller. Introduce a shared scroll-target abstraction so mobile can use the document scroller without changing verified desktop behavior.

## Resolution Summary

- Target the current and previous major iOS/Safari generations, with graceful usability on older versions.
- Limit document-scroller migration to Conversations, Book Details, and Book Reader on mobile.
- Preserve `containedMobileScroll` for unrelated consumers, including backoffice pages.
- Preserve the desktop Reader's element-level scroll model behind a shared scroll-target abstraction.
