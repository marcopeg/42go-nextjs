# Execution Notes — Add an AI Mode explain action to the LingoCafe reader
**Task**: ./ZA10.task.md
**Plan**: ./ZA10.plan.md

## Decisions

- Added a pure `reader-ai-mode` utility that builds the specified four-part learning prompt and opens it through Google Search AI Mode (`udm=50`) using a URL-encoded query.
- The resolved reader popover actions are now ordered `Play word`/`Play sentence`, `Start audiobook`, then `Explain`.
- The Explain action uses `window.open(..., "_blank", "noopener,noreferrer")`. In normal browsers this creates a new tab/window and preserves the reader. Installed/fullscreen platforms can route the external window through their supported browser presentation.
- Book sentence explanations include the enclosing paragraph. Conversation explanations include the active round and up to two rounds before and after, with speaker labels.

## Problems Encountered

- The browser platform does not expose a portable, standards-based API that guarantees an embedded cross-origin Google AI Mode window, particularly for iOS installed PWAs. The implementation intentionally lets the operating system/browser select its supported managed or external presentation rather than attempting an iframe.
- A concurrent Next production build held `.next/lock` during the final quality-gate rerun. Focused tests, lint, and a lock-free `npx tsc --noEmit` check passed; the previous full QA run before this context extension also passed.

## Deviations From Plan

- No separate fullscreen/PWA in-app-window abstraction was added because cross-origin embedding is not reliably supported. The same secure new-window handoff is the platform-safe fallback and preserves reader state in normal browsers.

## Additional Requests

- None.

## Known Limitations

- Google controls AI Mode availability by region, account, and product changes. The `udm=50` search handoff should be smoke-tested when Google changes its AI Mode URL behavior.
