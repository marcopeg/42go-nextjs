# Add an AI Mode explain action to the LingoCafe reader

## Elevator's Pitch

Add an Explain action to LingoCafe book and conversation translation results so readers can open Google AI Mode with a context-rich prompt for the selected sentence or word.

## Business Gain

Readers can move from a quick translation to grammar, vocabulary, and contextual explanation without manually copying text or losing their place in the book.

## Current State

The reader already supports sentence and single-word translation modes and presents translations in the reader interaction. It has no dedicated handoff to an AI explanation experience, so users must manually compose and paste a query elsewhere.

## Desired State

Once a translation has resolved, its popover presents three actions in this order: play the active selection, start the continuous audiobook from that point, then Explain as the final action. The selection-play label remains scope-specific (`Play word` or `Play sentence`) while the existing `Start audiobook from here` label is shortened to `Start audiobook`, clearly distinguishing the full continuous experience from selected-text playback. Activating Explain builds a Google AI Mode deep link whose prompt requests a full language-learning explanation in the reader's own/fluent language: an accurate translation, an explanation of the intended meaning, a dedicated explanation of any multi-word or composite expressions, and a deeper grammar and sentence-parsing analysis of how the components work together in communication. In book word mode, the prompt includes the complete enclosing sentence; in book sentence mode, it includes the full enclosing paragraph. In Conversations, it includes the translated sentence plus up to two dialogue rounds before and after the active round. In a normal browser, the handoff opens in a new tab/window. The task should prefer an in-app browser/window while the application runs in fullscreen or installed/PWA mode, if that can be done without breaking platform behavior; otherwise it must use a safe external handoff.

## Definition of Success

A reader can open a useful language-aware Google AI Mode explanation from the third and final translation-popover action without retyping selected text. The other two actions clearly distinguish selection playback from continuous voiceover. Word explanations retain sentence context, and fullscreen/PWA behavior is deliberate and tested.

## Additional Context

The supplied mobile reference shows the intended flow: a selected Swedish sentence has an inline translation, then Google AI Mode receives an explanation prompt and returns a detailed breakdown in English. Relevant reader behavior is documented in completed task QQ09 (translation scope) and active mobile-reader work SE90 (fullscreen/PWA and document-scrolling behavior).

## Assumptions

- The user's own language is the existing LingoCafe fluent-language profile value (`ownLang`).
- The reading language is available from the active book/reader state.
- Google AI Mode supports a URL/deep-link format that can receive a prefilled prompt; exact URL format and encoding must be verified during refinement or implementation.
- The Explain action is a client-side navigation/handoff and does not require sending reader text through a new LingoCafe backend endpoint.
- In-app window means the platform-appropriate embedded or managed browser presentation available to the installed/fullscreen environment; iOS and browser restrictions may require fallback to the system browser.

## Constraints

- Reuse the active reader translation selection rather than allowing arbitrary freeform input.
- Construct prompts with correctly escaped/URL-encoded reader text and language labels.
- Every prompt must request, in this order, an accurate translation, intended-meaning explanation, a distinct multi-word/composite-expression explanation when applicable, and detailed grammar plus sentence-parsing analysis in the user's own language.
- Sentence mode prompt must request the full analysis of the selected sentence in the user's own language.
- Word mode prompt must name the selected word and include the complete source sentence as context for the full analysis.
- For book sentence mode, include the full enclosing paragraph as additional context.
- For conversation translations, include up to two preceding and two following dialogue rounds, with speaker labels, as additional context.
- Do not expose tokens, credentials, or private user data in the URL.
- Keep the action usable and accessible on mobile and desktop.
- Preserve existing translation, selection, popover, reader progress, and fullscreen/PWA behavior.
- Keep the three post-translation actions in the fixed order: selection playback, continuous voiceover, Explain.
- In a normal browser, open Google AI Mode in a new tab/window so the reader stays open.
- Do not promise an embedded Google surface where browser security or platform policy prevents it; provide an explicit safe fallback.
- Run `npm run qa` after implementation.

## Acceptance Criteria

- [ ] After a translation resolves, the reader popover presents exactly three accessible actions in order: scope-specific selection playback, continuous voiceover, and Explain.
- [ ] The selection-play action uses a scope-specific visible label (`Play word` or `Play sentence`), and the continuous-audio action is labeled `Start audiobook`, clearly representing the full audiobook experience rather than selected-text playback.
- [ ] Explain is the third and final action in the translation popover for both sentence and word translation modes.
- [ ] Activating Explain opens a Google AI Mode deep link with a prefilled prompt based on the active reader selection.
- [ ] The prompt explicitly asks for the explanation in the user's own/fluent language, using a human-readable language label.
- [ ] The prompt requests an accurate translation and an explanation of the intended meaning before any deeper analysis.
- [ ] The prompt requests a dedicated explanation of relevant multi-word or composite expressions, rather than treating every term as an isolated word.
- [ ] The prompt requests detailed grammar and sentence-parsing analysis that explains each component and how they work together in communication.
- [ ] For sentence mode, the prompt includes the complete selected sentence and identifies its reading/source language.
- [ ] For word mode, the prompt requests an explanation of the selected word and includes the complete enclosing sentence as context.
- [ ] For book sentence mode, the prompt includes the complete enclosing paragraph as additional context.
- [ ] The Explain action is available in the Conversation reader translation popover as well as the Book reader popover.
- [ ] For a conversation translation, the prompt includes up to two preceding and two following rounds, with speaker labels, while respecting the beginning and end of the conversation.
- [ ] The deep-link prompt is correctly URL encoded, including punctuation, diacritics, quotes, and non-Latin characters.
- [ ] No API keys, credentials, or unnecessary profile information are placed in the URL.
- [ ] When running in a fullscreen or installed/PWA context, the implementation attempts the supported in-app browser/window experience where available.
- [ ] If an in-app window cannot be opened or is unsupported, the reader uses a clear, safe external-browser fallback.
- [ ] Outside fullscreen/installed-PWA mode, Explain opens Google AI Mode in a new tab/window and leaves the reader page open.
- [ ] Returning from the handoff leaves the reader's current page, translation selection, and reading position intact where the platform permits.
- [ ] The action remains keyboard accessible and usable at mobile and desktop breakpoints.
- [ ] Automated checks cover sentence and word prompt construction, own-language selection, special-character encoding, and navigation fallback selection.
- [ ] `npm run qa` passes after implementation.

## Dos

- Reuse the existing translation scope and reader selection models.
- Reuse the existing selection pronunciation and audiobook-start actions while making their user-facing distinction unambiguous.
- Treat prompt construction as a small, testable pure utility.
- Use canonical LingoCafe language labels and codes.
- Verify the exact Google AI Mode URL contract before shipping.
- Test normal browser, mobile browser, and installed/PWA contexts where available.

## Don'ts

- Do not send only a word without its sentence context in word mode.
- Do not make Google AI Mode access a prerequisite for normal translation.
- Do not silently discard the user's reading state during the external handoff.
- Do not embed Google in an iframe if browser security headers or platform rules prohibit it.
- Do not broaden this task into a first-party AI explanation backend or saved explanation history.

## Open Questions

- The exact Google AI Mode URL contract and prefill parameter must be verified during implementation.
