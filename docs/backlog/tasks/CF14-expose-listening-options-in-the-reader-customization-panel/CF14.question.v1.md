# Refinement Questions v1 — Expose Listening Options in the Reader Customization Panel

Answer inline under each question, then return to chat and say `next round`.

## Questions

### 1. What should make the Listening tab available?

Should it use the current full `playback.canPlay` result—which requires browser speech support, a matching voice, and readable sentences on the current page—or a broader device/language capability that can remain available on a page with no readable sentences?

Answer:

Use the current full `playback.canPlay` result. It is the canonical feature flag for whether Listening is available.

### 2. How should asynchronous voice discovery affect the open panel?

While voices are still loading, should the panel initially show the existing reading-only layout and add the tabs if listening becomes available, or should it hold a loading state until capability is known?

Answer:

Start device voice discovery when the client app boots rather than waiting for the settings panel to open. If discovery is still pending when the user opens the panel, show a small loader in the settings panel until capability is known.

### 3. What should happen if listening becomes unavailable while the Listening tab is selected?

Should the panel switch immediately to Reading and remove the tabs, or preserve the Listening view until the panel closes?

Answer:

Do not remove or switch the Listening settings while the panel is already open. The user may continue changing preferences. The playback layer should still reflect and enforce the real capability. Re-evaluate whether Listening is offered the next time the panel opens.

### 4. Should the panel remember the selected tab?

Should every opening begin on Reading, remember the selection only while the reader page remains mounted, or persist the last selection across sessions on the device?

Answer:

Do not remember the selected tab. Every time the settings panel opens, start on Reading.

### 5. Should opening the Listening tab participate in `Auto-pause on settings`?

If playback is active and that preference is enabled, should switching to Listening pause playback and resume it when leaving Listening or closing the panel, or should auto-pause remain exclusive to the playback-bar settings popover?

Answer:

Switching to the Listening tab does not independently pause playback. Opening the reader settings panel itself should participate in `Auto-pause on settings`, regardless of whether the user stays on Reading or switches to Listening. The same setting should pause playback when other reader-level configuration or navigation panels open, including the chapter/book navigation panel.

### 6. How closely should the Listening tab mirror the playback popover layout?

Should both surfaces reuse the exact same compact layout, or should they share the same controls and logic while the customization panel presents a roomier arrangement suited to its available space?

Answer:

Use the page settings panel's established visual style and available space. Reuse the generic tabs, switches, and shared playback-setting components and logic where practical; do not force the playback popover's compact composition onto the larger panel.

### 7. Should the Listening tab include any preview?

Should the existing reading preview remain exclusive to Reading, or should Listening include a small live preview of progressive reveal, played-text dimming, and highlight preferences?

Answer:

No. Keep the existing preview only in the Reading tab. The Listening tab has no preview.
