# Execution Notes — Show the Standard Mobile More Item to LingoCafe Backoffice Users
**Task**: ./LW16.task.md
**Plan**: ./LW16.plan.md

## Decisions

- Reuse the existing `AppLayout` mobile drawer and `SidebarMenu`; the profile component will contain no menu entries.
- Expose only an `openMobileMenu` action through a focused client context.
- Keep the trigger presentation in shared 42Go infrastructure and let LingoCafe declare its app-scoped `backoffice` policy in AppConfig.
- The shared hook throws a clear developer error outside `AppLayout`; inside the layout it reuses the same callback supplied to `MobileBottomNav`.
- The standard bottom-bar More item remains the only trigger; LingoCafe controls its visibility through `app.menu.mobile.more.policy`.
- Mobile navigation items use flex distribution so a policy-hidden More item leaves no empty slot.
