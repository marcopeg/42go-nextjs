# Refinement Questions v1 — Add a Backoffice-Only Full-Menu Trigger to the LingoCafe Mobile Profile

Answer inline under each question, then return to chat and say `next round`.

## Questions

### 1. Where should the Admin menu appear in the mobile profile content order?

Recommendation: place it after the optional Notification Center and before the configurable profile blocks. This keeps urgent user notifications first, then exposes operator navigation before account settings.

Answer:

Do not render an Admin menu. Add one **Open full menu** button as the final
LingoCafe-configured profile block. It may remain above the shared app-version
label.

### 2. What visual treatment should the Admin menu use?

Recommendation: one profile-style panel titled **Admin**, containing compact full-width navigation rows with the configured icon, label, and a trailing chevron. This fits the existing stacked profile-panel layout and keeps every row comfortably tappable.

Answer:

Use a simple full-width button with a menu icon. Activating it opens the
existing mobile drawer; do not reproduce its navigation rows in the profile.

### 3. Should this behavior be shared by every app using the standard profile page, or limited to LingoCafe?

Recommendation: implement it in the shared standard profile page and derive entries entirely from each app's `app.menu.bottom.items`. Apps without an authorized bottom item render nothing.

Answer:

Limit the trigger component to LingoCafe. The existing shared drawer and menu
rendering remain authoritative.
