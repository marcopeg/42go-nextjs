# Show the Standard Mobile More Item to LingoCafe Backoffice Users

## Elevator's Pitch

Show the standard 42Go **More** item in LingoCafe's bottom mobile app bar only for app-scoped `backoffice` users. It opens the existing `AppLayout` mobile drawer, allowing `SidebarMenu` to remain the single source of navigation, visibility, and policy behavior.

## Business Gain

- Make LingoCafe backoffice tools discoverable through the established mobile navigation pattern.
- Reuse the complete existing menu instead of duplicating navigation entries or authorization rules in the profile.
- Keep the workaround small, isolated, and easy to remove if LingoCafe's mobile navigation changes later.

## Current State

- `AppLayout` already owns a mobile-menu open state and renders the existing `SidebarMenu` in an 80%-width right drawer over a scrim.
- `SidebarMenu` already renders the configured top menu, policy-filtered bottom menu, and signed-in user row, and closes itself after navigation.
- LingoCafe sets `app.menu.mobile.disableMore: true`, which hides the standard More item even for backoffice users.
- `MobileBottomNav` already receives the drawer-opening callback from `AppLayout` and already applies declarative policies to configured navigation items.

## Desired State

- Extend `app.menu.mobile.more` with the standard 42Go `policy` contract.
- Configure LingoCafe's standard bottom-bar More item with `require: { role: 'backoffice' }`.
- `MobileBottomNav` silently omits the More item while its policy loads or fails and redistributes the remaining items without a dead gap.
- Activating More opens the existing mobile `SidebarMenu` drawer. The drawer continues to derive items from AppConfig and apply existing user-feature and policy filtering.
- Do not add anything to the Profile page body or title bar.

## Definition of Success

- A LingoCafe backoffice user can reach the established full mobile drawer from the standard bottom mobile app bar and use every menu destination already authorized for that session.
- Ordinary LingoCafe users do not see the trigger.
- No custom trigger component, page-specific drawer context, or duplicated navigation rules are introduced.
- Other apps and desktop behavior remain unchanged.

## Additional Context

- Relevant shared surfaces are `src/42go/layouts/app/MobileBottomNav.tsx`, `src/42go/layouts/app/SidebarMenu.tsx`, and the mobile menu section of AppConfig.
- LingoCafe owns only the declarative `app.menu.mobile.more.policy` value.
- For current LingoCafe backoffice sessions, the drawer can expose Users and Notifications through their existing menu policies.
- The app shell switches between mobile and desktop at `md`/768 px.

## Assumptions

- The existing `SidebarMenu` drawer is the complete menu requested by the operator; no separate Admin menu is needed.
- The existing standard More item is the correct trigger; no nested page-content API is needed.
- The role rule is LingoCafe-specific while policy evaluation and drawer behavior are shared infrastructure.

## Constraints

- Gate the LingoCafe trigger with the current app-scoped session and exact `backoffice` role. Client visibility is not a substitute for existing page or API enforcement.
- Keep drawer state and the opening callback inside `AppLayout`.
- Do not duplicate AppConfig menu data, item policies, user-feature filtering, `SidebarMenu`, drawer markup, or scrim behavior.
- Preserve the standard mobile app-bar appearance, accessible **More** label, and `md` breakpoint.
- Preserve the existing drawer close behavior after navigation, on scrim click, and when crossing to desktop width.
- Run focused tests and `npm run qa` after implementation.

## Acceptance Criteria

- [ ] AppConfig exposes an optional policy for the standard mobile More item.
- [ ] LingoCafe's bottom mobile app bar renders **More** below 768 px for a current-app session carrying the `backoffice` role.
- [ ] More does not render for ordinary LingoCafe users or at widths of 768 px and above.
- [ ] Activating the trigger opens the same drawer used by the standard mobile More button.
- [ ] The opened drawer preserves existing top/bottom item order, user-feature filtering, per-item policy filtering, user row, scrim dismissal, responsive dismissal, and close-after-navigation behavior.
- [ ] The More policy is configured only for LingoCafe; no other app's mobile navigation changes.
- [ ] Existing desktop sidebar and drawer contents remain unchanged.
- [ ] Policy-hidden items leave no empty space in the mobile bar.
- [ ] Automated coverage verifies the app-layout drawer controller, LingoCafe role gate, mobile-only visibility contract, and reuse of the existing drawer.
- [ ] Mobile visual verification at approximately 390 px covers an authorized backoffice session opening and navigating the drawer plus an ordinary-user session without the trigger; a desktop regression check confirms the trigger is absent.
- [ ] `npm run qa` passes.

## Dos

- Reuse the existing drawer and `SidebarMenu` unchanged where possible.
- Configure the existing More item with the standard declarative policy shape.
- Use the shared Button primitive and Lucide Menu icon.
- Verify that current authorized Users and Notifications entries remain reachable through the opened drawer.

## Don'ts

- Do not render a second Admin menu or any individual backoffice links in the profile.
- Do not add any trigger to the Profile page.
- Do not create another drawer opener, global event, or custom menu component.
- Do not expose More to other apps or roles unless their configuration requests it.
- Do not weaken feature, session, role, grant, or server-side route checks.
