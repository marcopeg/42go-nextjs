# Clarify Round v4 — QuickList Personal API Access and Agent Skill

## Questions

### 1. For shared lists, should the API exposure switch follow ordinary collaboratively editable settings, or be owner-only?

## Answers

### 1.

Only the list owner may see or change the list's API-enabled status.

If the owner enables API access for a shared list, each collaborator with an active personal token may operate on that list through the API with exactly the same capabilities they have in the UI. This includes adding, editing, sorting, checking/unchecking, and deleting items, plus other ordinary collaborator actions. The token does not gain owner-only powers.

## Resolution Summary

- Per-list API exposure is a list-wide owner-controlled setting.
- Non-owners do not see or change the exposure setting in the UI.
- An enabled shared list is available to each collaborator's own token when their account API gate is active.
- Token-authenticated authorization mirrors the represented user's existing UI permissions.
- Collaborators retain broad content operations but cannot invite/remove people, delete the list, or perform other owner-only actions.
