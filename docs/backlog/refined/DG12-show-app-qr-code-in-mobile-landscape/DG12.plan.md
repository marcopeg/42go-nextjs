# Plan - Show App QR Code in Mobile Landscape

## Goal

Implement a top-level AppConfig-driven QR overlay that replaces any enabled app page with a centered QR code on phone-sized touch devices in landscape orientation, with configurable destination rules and first opt-ins for LingoCafe and Quicklist.

## Milestones

### Milestone 1 - Config Contract and Dependency Choice

- [ ] Step 1 - Add QR config typing
  - Achieve: Extend the app configuration contract with a top-level optional `qr` section.
  - Create: A small exported QR config type if it keeps `src/AppConfig.ts` readable.
  - Modify: `src/AppConfig.ts`.
  - Delete: n/a.
  - Touch points: `TAppConfigItem`, `apps` type satisfaction.
  - Validation: TypeScript accepts `qr.active`, `qr.url`, and `qr.pageURL` on app configs while apps without `qr` still compile.
  - Notes: Shape should support future fields without forcing all apps to opt in.

- [ ] Step 2 - Select QR rendering package
  - Achieve: Use a proven React-compatible QR renderer instead of hand-building QR output.
  - Create: n/a.
  - Modify: `package.json`, `package-lock.json`.
  - Delete: n/a.
  - Touch points: Candidate dependency such as `qrcode.react`, unless implementation finds a better maintained fit.
  - Validation: Install succeeds and package is usable from client components.
  - Notes: Keep dependency narrow. Chuck Norris does not import a freight train to print a square.

### Milestone 3 - QR Destination Resolution

- [ ] Step 1 - Implement destination precedence
  - Achieve: Resolve QR destination in the requested order: `qr.url`, matching `qr.pageURL`, then app root URL.
  - Create: A small resolver helper if it improves testability.
  - Modify: QR overlay component and/or helper under `src/42go`.
  - Delete: n/a.
  - Touch points: browser `window.location`, config `qr.url`, config `qr.pageURL`.
  - Validation: Custom URL wins; pageURL match uses the full current URL; no match falls back to app root.
  - Notes: App root means current origin with `/`, not the current path.

- [ ] Step 2 - Safely handle `qr.pageURL` patterns
  - Achieve: Treat `qr.pageURL` as a config-owned regex allowlist and fail closed on invalid patterns.
  - Create: n/a.

  - Delete: n/a.
  - Touch points: regular expression compilation and match checks.
  - Validation: Invalid regex entries do not crash the page; non-matching pages fall back to app root.
  - Notes: Patterns come from source config, not user input, but runtime should still be sturdy.
