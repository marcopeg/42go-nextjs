# Plan - Add Backoffice Account Erasure

## Goal

Implement a backoffice-only account erasure flow that requires `users:delete`, blocks self-delete, runs app-specific cleanup hooks, deletes the app-scoped auth user, leaves historical events untouched, and writes a minimal audit event.

- [ ] Step 1 - Add destructive grant

  - Create: If needed, seed or migration coverage for `auth.grants`.
  - Modify: `knex/seeds/20240522_init_auth_data.js`, `knex/seeds/20260427150500_lingocafe_test_users.js`, and any relevant RBAC seed/config that grants backoffice deletion.
  - Delete: Nothing.
  - Touch points: RBAC seed data, role-grant assignments, `/users` page policy checks.
  - Validation: Seed/migration path creates `users:delete`; users without the grant cannot call delete.
  - Notes: Keep `users:list` for list/edit visibility. Do not let it authorize deletion.
